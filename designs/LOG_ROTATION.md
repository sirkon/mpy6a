# Осуществление ротации логов.

Запись в логи осуществляется посредством Sink-ов или Writer-ов определенных в модуле blog, где каждый
поток имеет свой собственный логгер со своим собственным [IouringSink](../src/logging_iouring.zig), который пишет
в общий для всех потоков FD.

Остановился на схеме с открытием файла в слоне, который при "а сейчас нужно подменить файл для логирования":

1. Смотрит, не идет ли уже задача подмены файла. Если уже идет, продолжает дальше.
2. Переименовывает `mpy6a.log` -> `mpy6a.log.20260918080101`. Внимание: этот файл пока продолжает писаться.
3. Создает файл `mpy6a.log` (новый FD) и создает задачу "заменить FD в синке на данный"
4. Рассылает индекс этой задачи на ВСЕ N колец.
5. Ожидает N подтверждений от всех потоков.
6. Закрывает старый FD.

Потоки реагируют на это так:

1. Получили CQE с задачей "подмени файл логирования".
2. Подменяют FD в своих Sink-ах.
3. Посылают подтверждение постановщику задачи через тот же механизм сообщений.

Следовательно, задача сама задача должна ставиться так:

```zig
const FdType = @import("std").posix.fd_t;

const TaskLogRotate = struct {
    new_fd: FdType,  // Дескриптор нового файла для записи.
    who_am_i: *Ring, // Кольцо слона, который поставил задачу смены дескриптора.
};
```
