# Протокол консенсуса.

Необходимо ознакомление с [архитектурой](./shard_architecture.md). 

## Лидерство.

Лидерство привязано к сессии. Индекс хоста, начавший вести сессию, становится ее лидером, что выражается
в индексе сессии.

В случае, если потеряна связь с хостом лидирующего индекса лидерство неким образом перехватывается одним
из этих зеркальных индексов. Для попытки перехвата лидерства по индексу необходимо, чтобы сессия
считалась находящейся в актуальном состоянии и чтобы подключение к зеркальному индексу на хосте
с лидирующим индексом продолжительное время не проводило никаких операций в течении оговоренного времени (в секундах).

## Подтверждение операций.

Для подтверждения успешности операции клиенту лидер должен получить одобрение кворумного числа
зеркальных индексов с других хостов шарда.

В случае, если отвалился лидирующий индекс, все имеющиеся записи считаются подтвержденными - это требование
домена, так как работа с WAL имеет следующий вид:

1. Декларация намерения "выполнить `X(args)`".
2. Выполнение `X(args)`.

Само такое взаимодействие уже подтверждает факт, что все необходимое для выполнения `X` готово. Нам очень желательно
сохранить информацию об этом, чтобы уменьшить сложность выполнения компенсации.

**Ответ на запрос подтверждения**

```
data CommitResponse 
   = Commited
   | Outdated SequenceID   -- Диагностирует попытку продавить решение по сессии, которая отстала от "мейнстрима" 
```

## Фоновая синхронизация.

Каждый индекс регулярно обменивается с зеркальными векторными часами состояний всех имеющихся у него индексов.
В случае, если зеркальные индексы присылают данному состояние некоего третьего большее чем имеется локально, данный
индекс запрашивает недостающие данные третьего индекса у индекса с самым последним состоянием. Так же эта информация
должна служить критерием для принятия решения о захвате лидерства по сессии - если данный индекс отстает в образе
индекса-лидера, он не пытается выполнять захват.
