# Механизм снапшотов.

Механизм снапшотов отвязан от консенсуса и выполняется оппуртунистически для `(host_idx, index_idx)`. Задача ставится в
рамках конкретного индекса, который раз в T секунд смотрит на длины своих WAL-файлов, т.е. длины WAL-файлов индексов с
себя и с зеркальных индексов с других хостов и решает "а вот для данных с моим номером индекса этого хоста нужно сделать
снапшот и завести новый WAL-файл".

## Механизм периодического контроля размеров.

Имеется тикер над кольцом данного индекс-потока, который раз в T секунд присылает особое сообщение.

При получении сообщения индекс-тред (с данным `index_idx_0`):

1. Смотрит на все пары `(host_idx, index_idx_0)` и смотрит, какого размера у них `WAL`-файл. Если размер больше чем
   некий `S`, он добавляет его в кандидаты на снапшот.
2. Среди таких кандидатов выбирается пара с наибольшим размером `P`.
3. Ставится задача: создать снапшот состояния для данной пары `P = (host_idx_0, index_idx_0)`.

## Постановка задачи создания снапшота.

Создание снапшотов выполняется в рамках тредов-слонов (`elephant`). Описание задачи прокидывается через механизм
`CrossTaskSlots` и кольцо сообщений. Когда индекс-тред:

1. По какому-то критерию выбирает слона из существующих (раунд-робин, сбалансированный раунд-робин и т.п.)
2. Занимает слот в `CrossTaskSlots` с описанием задачи - этот слот будет занят до завершения операции, вне зависимости
   от исхода.
3. Кидает идентификатор слота в кольцо слона через собственное кольцо.

## Исполнение задачи создания снапшота, прелюдия.

1. Слон создает новый WAL-файл и кидает в индекс-тред сообщение (через тот же механизм) - вот тебе новый WAL-файл под
   эту задачу (проще всего сделать в рамках того же слота). Че дальше?
2. Индекс-тред получает это сообщение и:
   1. Делает слепок своего состояния.
   2. Заменяет интерфейс своего WAL-файла на композитный: сейчас при записи события мы пишем сначала в НОВЫЙ, а затем в
      старый файл. Неудача записи в старый означает завершение обслуживания клиентов. Мы перестаем обрабатывать новые
      запросы от клиентов, начинаем слушать ТОЛЬКО команды управления временем жизни.
   3. Еще раз выбирает слона, уже для настоящего создания снапшота.

## Создание снапшота.

Итак, слепок данных у нас на руках - он был добавлен в данные слота. Напоминаем, что слон может быть не тем, который
создавал новый WAL-файл.

1. Слон делает дамп состояния конкретной пары `(host_idx_0, index_idx_0)` и пишет ее в файл. Логика - синхронная. Слон
   как раз предназначен для такой.
2. После успешного создания он пишет в ФИКСИРОВАННЫЙ файлик (для каждого индекс-треда используется отдельный файлик)
   данные вида
   ```json
   {"host_idx":host_idx_0,"snapshot_path":"/path/to/shapshot/file","wal_path":"/path/to/wal/file"}
   ```
   с обязательным `\n` после такой строки. После чего, может провести компакцию этого файлика: оставить только последние
   `N` записей для каждого данного `host_idx`. Естественно, это делается транзакционно - создаем новый файлик, наполняем
   содержимым, переименовываем файлик в то фиксированное название.
3. После чего кидаем сообщение индекс-треду "компакция завершена". При неудаче доставки повторяем (после небольшого
   спинлока).

### Обработка завершения на стороне индекс-треда.

После получения сообщения индекс-тред заменяет композитный WAL-интерфейс на одинарный, где он должен писать уже ТОЛЬКО в
новый файл. Если он был заморожен из-за неудачи записи в старый WAL-файл, он делает попытку реанимации.

## Инварианты и ограничения.

- В рамках индекса может идти только ОДНА операция создания слепка состояния (т.е. снапшота). Новые события тикера на
  снапшоты игнорируются.
- Слепок состояния для данного `host_idx_0` описывается последней строкой (в том фиксированном файлике) с данным
  `"host_id":host_idx_0`.
- Если в фиксированном файлике лежит невалидная строка, то это фатальная ошибка старта и функционирования (если на нее
  напоролся слон делающий компакцию такого файлика - он делает запрос на останов процесса).
- Имена WAL и snapshot-файлов содержат state_idx для данного зеркала, которые были на момент выбора слона для начала
  создания снапшота (фиксируется в данных в слоте).
