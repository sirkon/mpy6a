# Список отложенных вещей.

## Команда тулчейна `pmem-migrate`.

Содержит подкоманды, каждая из которых работает на обновленном конфиге и требует указания старых значений для
перестройки фиксированной области pmem.

### `lba` для смены размера хардверного LBA при смене накопителя.

Режим работы `pmem` для WAL-а требует перестройки буферов в NVDIMM при переходе на накопитель с другим LBA.

Выглядит как

```shell
mpy6a pmem-migrate lba --old-lba 4Kib
```

## `cpu` при перенастройке количества индексов (смена CPU, осознанное решение о расширении).

Работает ТОЛЬКО в сторону увеличения. Уменьшение потребует кластерной миграции данных.

```shell
mpy6a pmem-migrate cpu --old-index-count M
```

## `replication` при изменении фактора репликации.

```shell
mpy6a pmem-migrate replication --old-factor F
```

## Опции команды WRITE при постановке задачи записи в WAL.

При сбросе накопленных данных в физический WAL надо бы сохранять с

```zig
sqe.rw_flags = std.os.linux.RWF.DSYNC;
```

чтобы контроллер SSD сбросил свой внутренний кеш тоже. Вот такое НМВ лучше делать ТОЛЬКО в случае PMEM-режима.

## Процедура пересборки JSONL-файла для восстановления списка (snapshot file, wal file).

Утилита ищет существующие snapshot и wal-файлы в директории индекса, группирует их по парам `(host_idx, index_idx)`,
упорядочивает внутри этой пары по state_idx, выбирает N последних (параметр) и выдает все в виде JSONL-выхлопа.
