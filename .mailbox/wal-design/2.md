## 1. The pad, restated as facts

**U1 — durability contract.** WAL files are opened `O_DIRECT`; there is no page cache anywhere in
the WAL path and deliberately no fsync/fdatasync/FUA in either mode — we already buffer, a second
buffer would only add latency. Non-PMEM durability therefore covers the process crash exactly: a
record is durable once its buffer's `O_DIRECT` flush completed, and a power cut may lose even
completed flushes that still sit in the device's volatile write cache — accepted; power-loss
durability is what PMEM mode exists for. The un-flushed tail lost to a process crash is recovered
from the quorum through the background sync (`docs/consensus.md`, the `RequestLog` service of stage
7). If a stronger non-PMEM contract is ever wanted, that is a new subject, not an amendment here.

**U2 — flush I/O mode.** `O_DIRECT` in both modes, mode-independent open flags, and buffers laid out
so the alignment requirement holds by construction (the layout itself is **U8** below).

**U3 — geometry.** The `u512` header is never written to disk; it is battery metadata only, one
64-byte cache line so that a barrier write covers it with one CLWB. The data area is one device LBA
(4 KiB, 16 KiB, whatever the drive has). A flush is always one whole data area at an LBA-multiple
file offset, so file-side `O_DIRECT` alignment is automatic and the file length is always a multiple
of the LBA. Each file's buffers form a ring addressed by head and tail — plain fields, no atomics —
because every write and read task is set up in the index thread that owns the file. The NVDIMM pool
is partitioned, not searched: with the number of indexes and the replication factor both known at
startup, the required pool length is known, and the battery of a given index of a given host sits at
a computed offset (§3).

**U4 — the terminator rule.** An exactly filled buffer is never exposed (header persisted, flush
queued) before its successor's header is initialized to `data_len = 0`, filled flag cleared, and
persisted — otherwise a restart would see a filled tail whose successor still carries a stale header
from a previous ring lap and would replay garbage. Generalized, this is the battery's core
invariant: **a data area only ever receives bytes after its own header has been persisted as a
zero-terminator.** Every path that makes a slot current (open-reset, exact-fill transition)
satisfies it.

**U5 — exact-fill gate.** Kept, but only in PMEM mode, through the comptime branch suggested in the
pad (`if (mode == .pmem)` around the gate). Non-PMEM accepts the fill: no walk ever consults a RAM
battery.

**U6 — the open block.** Incomplete blocks have no CRC, at a crash and at a clean close alike. The
loosening is a probability tradeoff, accepted: block CRCs reduce the chance of undetected bit rot,
they never make it zero, and the tail block additionally rides on the per-record checksums and the
self-delimiting framing, with replay stopping at the first torn record. No running CRC is stored in
any header; the running CRC lives in `WALFile` RAM registers and is restored at open (**U9**).

**U7 — one type, two initializations.** A single `WALFile` comptime-parametrized by the mode.
PMEM-only barrier writes; different initialization only: the battery is a computed slice of the
process-wide DAX-mapped NVDIMM pool in PMEM mode, and one ordinary aligned allocation of the whole
buffer space otherwise. The header fields are battery parameters, pinned in §3 minus the `block_crc`
U6 rejected.

## 2. File identity, threading, and naming

One file per (index thread, host): the replica logs are already named `<wal_path>.<index_id>.<host>`
(`src/index.zig`), and `docs/shard-arch-hld.md` calls the separate file per index the principled
difference from Raft. The log of a host is the union of the per-index files; ordering inside one
file is total, and each session lives in exactly one file (sessions are partitioned across index
threads by id).

`state: u128` carries the host identity and a monotone counter (CONSENSUS-PLAN 2.5), so
`WALController.open(index_idx, state)` is read as: the file of (calling index thread, `state`'s host
slice), positioned at `state`'s counter; `read_seek(state)` is the same resolution on the read side.
The controller is a process-wide table over (index, host) → file + battery, but each entry is
touched only by its index thread; nothing WAL-related crosses threads (records produced elsewhere
already arrive through the inbox as this thread's work), so the battery head/tail, the flush queue,
and the waiter list of §6 are plain fields.

One naming hole remains: the own log. Today every index thread opens the bare `wal_path`
(`src/index.zig`), which the stub tolerates only because 43-byte `O_APPEND` writes interleave whole;
the battery scheme needs one writer per file. **U10.** Proposed: the own log of index thread `i` is
simply the file for `(i, own_host)` under the same scheme and the same naming,
`<wal_path>.<i>.<own_host>`, one battery per file like every other file.

## 3. Pinned constants, layouts, and formats

- **LBA.** The data-area size. Comptime constant, default 4096; any power of two from 512 to 1 MiB
  is legal (it must divide the block). Checked against the device at open; a mismatch surfaces as
  `EINVAL` on the first flush anyway. **U8** pins the sourcing and the memory layout.
- **Battery.** N buffers per file, the same N for every battery (a config knob). Sizing criterion,
  per the pad: enough buffers to damp sequential writes — `N × LBA` comfortably above the burst one
  flush round-trip must absorb; N ≥ 2. The slot of logical area position p is `p mod N`.
- **Buffer.** `header: u512` (battery-only) plus one LBA data area. The memory layout is **U8
  (blocking)**: an adjacent `[header | data]` buffer with stride 64 + LBA can never present an
  LBA-aligned data pointer, and `O_DIRECT` requires that of the user buffer too, so every flush
  would fail with `EINVAL`. Proposed: two parallel arrays per battery — data first (`N × LBA` at the
  battery-area start, aligned by construction), headers after (`N × u512` at offset `N × LBA`, a
  multiple of 64) — zero slack, the recovery walk reads one linear line per slot, `persist()` just
  takes two ranges. The adjacency-keeping alternative is a stride of `2 × LBA` as
  `[data LBA | header 64 | pad]`, at the price of doubling the pool.
- **Pool partition (PMEM).** The whole NVDIMM area is DAX-mapped once at startup, before threads
  spawn. `battery_area(i, h) = pool_base + (i × R + h) × area_stride`, with `area_stride =`
  `N × (LBA + 64)` rounded up to a page, R the replication factor and i the index-thread ordinal —
  both known at init, so the required pool length is known; a restart recomputes the same addresses.
  Non-PMEM: one aligned heap allocation of the battery per open file. An empty `wal_path` keeps no
  logs at all (existing semantics); the pool is simply not mapped.
- **Header (final).** One cache line: `data_len: u32` (valid bytes in the area; LBA when filled),
  `flags: u32` (bit 0 = filled), `buffer_seq: u64` (the area's file position ÷ LBA — the flush
  offset, and a stale-lap sanity check for the walk), `reserved: u64`. No `block_crc` (U6); no
  closed flag (open resets the ring, §8).
- **Block.** 1 MiB over the logical stream. Bytes `[0, 1 MiB − 4)` are content; the last 4 bytes
  hold CRC32C (Castagnoli) over the content, zero padding counted. A block boundary always coincides
  with a data-area boundary (1 MiB is a multiple of every legal LBA), so the CRC slot always lands
  inside the last data area of its block, and every block rollover is also a buffer fill.
- **Record.** Unchanged from `src/wal.zig`:
  `magic u16 | len u32 | crc32 u32 | session u128 | op u8 | upgrade u128`, 43 bytes,
  self-delimiting, per-record checksum. One `write()` call is one record. A record that does not fit
  the open block's content remainder zero-pads it — the WAL stores the completed block's CRC right
  then, inside the battery — and starts in the next block; a record larger than a block starts at a
  block boundary and spans blocks. The capacity gate accounts for the pad.

## 4. Write path

`write(record)`, in order, on the owning index thread:

1. **Gate.** `capacity = free_buffers × LBA + (LBA − current.data_len)`, where free counts only
   buffers neither queued nor in flight (a buffer is reusable only after its flush completed).
   `need = record.len + rollover_pad`, where `rollover_pad` is the open block's content remainder if
   the record does not fit it, else 0. `need > capacity` → immediate error, nothing queued, battery
   untouched. PMEM-only (comptime), the exact-fill rule: reject also a write whose absorption would
   end with the last available buffer filled exactly and no free successor.
2. **Rollover.** If the record does not fit the open block's remainder: zero-fill the remainder into
   the battery (zeros into the running CRC), store the block's CRC32C in its last 4 bytes, reset the
   running CRC for the next block. The pad may itself fill areas — run step 4's transition for each.
3. **Copy.** Copy the record into the current data area, updating the running CRC incrementally; the
   copy may spill over several areas. `persist()` the freshly written ranges — data first.
4. **Exact-fill transition**, while an area was filled exactly: (a) initialize the successor's
   header — `data_len = 0`, filled cleared, `buffer_seq = current + 1` — and persist it: the
   terminator first (U4); (b) mark the filled buffer's header — `data_len = LBA`, filled set — and
   persist; (c) push the filled buffer onto the per-file flush queue; (d) the successor becomes
   current, copying continues.
5. **Tail metadata.** Update the current header's `data_len`; persist.
6. **Exit kick.** If the writing flag is clear and the queue is non-empty: register a `wal_flush`
   context in `RingSlots` (the `*WALFile` travels in the `TaskCtx` alongside the existing variants,
   replacing the per-record `flush_op`/`log_command` write path), arm one SQE —
   `write(fd, data_area(queue head), LBA)` at offset `buffer_seq × LBA`, `O_DIRECT` — set the flag,
   return.

`persist(range)` is the single point of divergence: CLWB per line, then one SFENCE, in PMEM mode; a
comptime no-op otherwise. Data is always persisted before any header that exposes it.

## 5. Flush path

One flush SQE in flight per file, strictly sequential: a failed write N can never be preceded in the
file by N+1's bytes at a known length, so the file length stays a meaningful recovery cursor.
Nothing prevents different files from flushing in parallel — the contexts are per file.

The CQ handler, on a `wal_flush` completion:

1. Return the flushed buffer to the front of the free order (cache warmth).
2. Queue empty → clear the writing flag; otherwise arm the next SQE from the queue head, the flag
   stays.
3. Either way, release the durability waiters the new frontier covers (§6), then continue the
   handler's own work; the WAL never blocks the ring loop.

A completion with `res != LBA` is a failure. **U11.** Proposed: stall — keep the queue and the
buffer, report the error once, do not rearm; the file is failed until the controller decides (the
queue order is intact, so a controller-level retry of the same head is always safe). The alternative
is an automatic in-order retry loop inside the handler. Pin one.

## 6. Durability notification

The consensus tract answers the client once the operation's record is durable, so the WAL must say
when. **U12.** Proposed:

- **PMEM:** `write()` returning is the durability point (data and the headers exposing it passed
  CLWB → SFENCE before any flush); the session advances inline, no CQE per record. This is the
  entire latency win of the mode.
- **Non-PMEM:** durability is the flush completion. Each file keeps a FIFO of
  `(session, end-position)` waiters that `write()` appends to; a `wal_flush` completion covers every
  waiter below the new flushed frontier, and the CQ handler advances exactly those sessions. Plain
  single-threaded fields, like the queue.

## 7. Close

Pad the current data area with zeros to its end (zeros counted in the running CRC; if the pad
exhausts the open block, the block's CRC is stored as at any rollover, otherwise the block stays
open — the U6 loosening), set `data_len = LBA`, mark filled, persist, enqueue as the final unit,
kick. The caller then drains its ring — the existing shutdown choreography — until the file's queue
is empty and the flag is clear; close the descriptor. A torn flush of this final unit is ignored by
replay exactly as before: the zeros are not a record.

## 8. Open, recovery, and read cursors

**Scan.** The logical stream is the file bytes `[0, L)` plus, in PMEM mode, the ring tail: slot
`(L / LBA) mod N` holds the first unflushed area; filled headers continue the file (LBA each,
`buffer_seq` checked against the walk position), the first non-filled header ends the walk, its
`data_len` bounding the partial. Termination is guaranteed by the three invariants now pinned: the
U4 terminator (every current slot was a persisted zero-terminator before receiving data), slot reuse
only after flush completion, and the PMEM exact-fill error. If L is not an LBA multiple, crop the
tail (a torn final flush). Complete blocks verify by CRC32C; replay decodes self-delimiting records
and stops at the first torn record or bad block; the restart epoch (`docs/consensus.md`) is computed
by this scan exactly as `src/wal.zig` does today. Non-PMEM: the battery was RAM, the stream is the
file alone.

**Positioning (U9, blocking).** Three cases:

- _Normal restart_ — the recovered state is the end of the valid stream: the writer continues in
  place. Current buffer = the walk's terminator slot with its `data_len`; no reset; the
  committed-but-unflushed tail stays live, the walk rebuilds the flush queue from the filled tail
  buffers in `buffer_seq` order, and the first kick (at open or on the next write, whichever comes
  first) resumes flushing them. The running CRC of the open block must be restored from the prefix —
  the choice is U9(a).
- _State below the stream's end_ — a suffix must be dropped. Trim the ring first (re-zero every
  trimmed header as a terminator, deepest first, then persist), then truncate the file to the
  state's byte offset. A crash in between replays at worst the not-yet-dropped suffix (the caller
  retries the open at the same state; it converges), never garbage. Whether this case is reachable
  at all is U9(b).
- _Fresh file, or after `delete`_ — reset all N headers to terminators (one persist sweep; a memset
  otherwise), current = slot 0, running CRC fresh, L = 0.

**U9c.** The offset index `src/wal.zig` left to this design: proposed sparse, one entry per 1 MiB
block naming its file offset and its first record's state, rebuilt by the scan and appended on
rollover; `read_seek(state)` lands on the block and scans at most 1 MiB. RAM cost is one entry per
megabyte of log.

**Read cursors.** `read_begin()` positions at stream offset 0; `read_seek(state)` resolves through
the offset index. In PMEM mode the stream includes the live ring tail, so a cursor may serve
`RequestLog` reads of records that have not flushed yet — same thread, plain reads.

`delete(index_idx, state)` removes the file of that (thread, host); the battery is not freed — the
next `open` resets it (third case above).

## 9. The complete mode delta

1. Battery backing: a computed slice of the DAX-mapped pool vs one aligned heap allocation.
2. `persist()`: CLWB → SFENCE vs a comptime no-op.
3. The exact-fill gate: present vs absent (comptime branch).
4. Recovery authority: the ring is a persistent tail and the walk consults it, vs scratch memory
   that died with the process.

Everything else — API, gate math, copy/transition ordering, flush queue mechanics, sequentiality,
close, block and record formats, the durability waiters — is one shared implementation. Snapshots
and front-truncation (compaction) stay a separate subject; this design covers the buffered battery
writer, reader, and crash recovery only.

## Open questions

- **U8 (blocking).** Battery memory layout under the `O_DIRECT` memory-alignment requirement.
  `O_DIRECT` requires the user buffer itself to be aligned to the device's logical block size, but
  an adjacent `[header u512 | data LBA]` buffer with stride 64 + LBA puts every data pointer at
  offset 64 mod LBA — never aligned, so every flush would fail with `EINVAL`. Two candidates that
  keep the header a single CLWB-friendly line: (a) two parallel arrays per battery — the data array
  (`N × LBA`) at the battery-area start so every area is aligned by construction, the header array
  (`N × u512`) after it — zero slack, a linear recovery walk, `persist()` taking two ranges; (b)
  per-buffer adjacency kept at stride `2 × LBA` as `[data LBA | header 64 | pad]`, doubling the
  pool. Proposed: (a). Also pin here the LBA sourcing: a comptime constant (default 4096, any power
  of two 512 .. 1 MiB that divides the block), checked against the device at open.

- **U9 (blocking).** Open-time positioning and the running CRC. After a restart the writer may
  resume mid-block — the recovered state can end anywhere inside a 1 MiB block — and the running
  CRC32C of that block lives only in RAM, which died. (a) Proposed: restore it by reading the open
  block's durable prefix back at open — at most 1 MiB, one read, uniform for both modes (the prefix
  is in the file even in PMEM mode) — and continue the block in place. Alternative: at open,
  finalize the open block with zero padding and its CRC and always resume at the next block boundary
  — no CRC is ever restored, at the price of up to 1 MiB of padding per reopen. (b) Is `open` ever
  called with a state below the end of the valid stream (the trim case of §8), or is positioning
  always end-of-stream — in which case the trim choreography is dead code for now and the question
  can be closed as "unreachable, revisit with compaction"? (c) The offset index: confirm the sparse
  per-block shape of §8 (one entry per 1 MiB block) or name a different granularity.

- **U10.** Own-log identity and the exact parameters of `open`/`delete`. Every index thread
  currently opens the bare `wal_path` — the stub survives only because 43-byte `O_APPEND` writes
  interleave whole, and one writer per file cannot be shared with a battery. Proposed: the own log
  of index thread `i` is the file for `(i, own_host)` under the same naming as the replica logs,
  `<wal_path>.<i>.<own_host>`, one battery per file like all the others; `wal_path` remains the
  config prefix. Same question, other side: confirm the reading of `open(index_idx, state)` as
  (calling index thread, host taken from `state`, positioned at `state`'s counter), with `index_idx`
  asserted to equal the caller's thread ordinal. Confirm or override.

- **U11.** Flush-failure policy. Strict per-file sequentiality means a failed write leaves the queue
  order intact — a hole is impossible as long as nothing past the failure is written. Proposed: on a
  failed flush completion, stall the file: keep queue and buffer, report the error once, do not
  rearm; the file stays failed until the controller decides (an in-order retry of the same head is
  always safe for it to attempt). Alternative: an automatic bounded in-order retry inside the CQ
  handler. Pin one.

- **U12.** The durability notification bridge. The consensus tract answers the client once the
  record is durable, so the WAL must expose that moment. Proposed: in PMEM mode, `write()` returning
  is the durability point (the barriers ran before any flush), so the session advances inline with
  no per-record CQE — the mode's entire latency win; in non-PMEM mode, each file keeps a FIFO of
  `(session, end-position)` waiters that `write()` appends to and the `wal_flush` CQ handler drains
  as the flushed frontier passes them. Confirm, or say if PMEM should also defer to flush completion
  for uniformity.
