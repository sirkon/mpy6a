## 1. U15 restated: a RAM battery, durable at the end

**Fact.** The tmp WALFile instantiates the **non-PMEM shape even under a PMEM deployment**: one
ordinary aligned heap battery, `persist()` a comptime no-op, the exact-fill gate absent. The PMEM
pool partition stays sized for the fixed `(index, host)` slots only — the tmp battery is never
carved from it.

**Fact — the durability clause.** Nothing durable is spent on the tmp file mid-procedure: a crash or
a failed procedure turns it into junk by design, and the old side carries the log meanwhile. The
durability moment is **the end**: at the OK-path swap, the tmp WALFile's whole state — battery
arrays, current slot, running CRC, flush queue, flags — lands in the fixed battery place and is made
durable there, with the fixed battery's own mode barriers: one sweep of CLWB → SFENCE over the
memcpy'd control lines and data under PMEM; a comptime no-op under non-PMEM, whose contract never
had power-cut durability and needs nothing beyond the ordinary flush frontier. From the swap on, the
direct interface carries the ordinary mode semantics, flushes included. Which flush machinery runs
in between — the parenthetical "(no `O_DIRECT` obligation either)" of the iteration-6 proposal said
less than it seemed to — is **U19** below.

**Fact — the stall inversion.** An old-file flush failure still stalls the old file exactly as
before (§6): the log is never failed by the procedure. A tmp-side failure — an error on a
temporary-side write, or a stalled temporary-side flush — fails the **procedure**, never the log.

## 2. U16 restated: (host, index) groups

**Fact.** WAL files and snapshot files are managed as separate families, **both grouped by
`(host, index)`** — the correction of the iteration-6 proposal, which grouped WALs by host alone and
would have dropped another index's only WAL file while a first index kept N. The grouping keys on
the explicit name components; the ordering compares whole states (the total order of the tag — 32
hex digits compare lexicographically as numerically, U18), never decoding anything; only the N
latest are kept per group, everything else removed. One constraint recovery adds on top — the
greatest snapshot's pair file is never removed — is part of **U20**.

## 3. U17 restated: greatest tag, greatest state, advisory symlink

**Fact.** On restart, per `(host, index)`, the recovery selects from the valid-named files by
whole-state comparison, never by parsing names. The `snapshot` symlink is advisory only — a gimmick
for tooling and humans; recovery never reads it. The snapshot's own name pairs it with its WAL file
(the same state value in both names).

**Fact — the window.** Between the elephant's renames and the flag-clearing close CQE, a crash
leaves two valid-named files; whichever file the selection opens, the frontier gap between the two
flush frontiers is quorum-recovered per §1 — a procedure-bounded relaxation, accepted even in PMEM
mode, where the older battery still holds the bytes but the selection ignores it. Which file the
selection actually opens — the plain greatest-tag rule of U17's proposal text breaks on pairless
fragments — is **U20**.

## 4. U18 restated: 32 lowercase hex digits

**Fact.** `<state>` renders as **32 lowercase hex digits** everywhere it names a file — WAL tags and
snapshot names alike. Fixed width: lexicographic order equals numeric order; no separator hazards.
Decimal is rejected: variable-length renders break lexicographic tooling.

## 5. The snapshot choreography, worked through (the promotion's §12)

### Prerequisites (restated as fact)

- An **index** is an execution entity holding an **own index state** (with timing-wheel machinery)
  and **mirror states** of other indexes, commanded through cluster connections, with **no**
  timing-wheel machinery over them. The index state
  (`active sessions, sessions ordered by replay/compensation order, ...`) is dumpable through its
  public interface:

```zig
const IndexState = struct {
    // ...
    pub fn clone(self: *Self, dst_allocator: *std.heap.Arena) !*Self {}
    pub fn dumper(self: *Self) !IndexState.Dumper {}  // on a cloned entity
    const Dumper = struct {
        // Synchronous on purpose: a large placeholder buffer (512 KiB or more) makes io_uring
        // meaningless for the task.
        pub fn dump(self: *Self, placeholder: []u8, dst: std.Io.Writer) !void {}
    };
};
```

- **Elephants** are execution entities on their own threads, receiving orders through cross-task
  slots / io_uring messages carrying slot references, executing **heavy blocking logic
  synchronously**. Round-robin task distribution.
- `WALController` marks a fixed battery area per `(host_idx, index_idx)` file and gains the
  temporary-file surface:

```zig
pub const WALController = struct {
    pub fn open(self: *Self, host_idx: u8, index_idx: u16, state: u128) !*WALFile {}
    // A wrapper over the given RW descriptor plus a buffer for temporary WAL files.
    pub fn tmp(self: *Self, tmp_fd: std.posix.fd_t) *WALFile {}
};
```

### The invariant

**At most one snapshot procedure at a time, process-wide.** A single atomically accessible flag
(boolean or integer — whichever is cheaper) serializes all of it; there is no parallel snapshot
creation, own or mirrored, ever.

### Index thread

1. A **multishot timer** in each index thread (tick on the order of 1–10 minutes) wakes the review;
   the thread reviews its states' WAL sizes.
2. A state's WAL grew past the configured bound → it deserves a snapshot (`host_idx` may name a
   mirror).
3. **CAS the flag** false → true; failure means another procedure is in flight — drop the idea this
   tick.
4. On success, set the meta-state and arm io_uring to create an **empty** temporary WAL file in the
   **in-progress directory** under a **fixed name** (safe under the invariant; the path and names
   are **U21**):

```zig
snapshot_in_progress: ?struct {
    host_idx: u8,
    state: *IndexState,
    current_wal_len: usize,
},
```

5. On the CQ reply carrying the FD (`snapshot_in_progress` must be non-null then — otherwise the
   procedure is already failed):
   1. **Clone** the given state (arena).
   2. Switch the file's write interface to a **composite WAL file**: every `write()` fans out into
      the **old** WAL file and the **temporary** one (§1 for the sides' disciplines).
   3. Send the "create snapshot" task to a round-robin-chosen elephant.
   4. Keep working — the composite writes keep flowing; nothing blocks the ring loop.

**Rotation defers while the procedure is in flight.** The composite owns the old file's descriptor,
and the §8 close cannot run under it; the epoch-bump threshold check resumes when the flag clears.
This is a constraint, not a choice — a mid-composite rotation would tear the composite apart.

### Elephant thread — all synchronous, all blocking

1. Create the snapshot file in the in-progress directory (fixed name). Dump is the cloned state's
   `Dumper.dump` with a ≥ 512 KiB placeholder into a plain buffered writer — no io_uring. **Its
   durability is U19(c).**
2. Rename the temporary WAL file into its **valid name** — the new full-state tag minted from the
   state at snapshot start.
3. Rename the snapshot into `snapshot.<host_idx>.<index_idx>.<state>`.
4. Replace the `snapshot` symlink → the new snapshot name.
5. Reply OK (or failure) to the index through the slot, **carrying how far the procedure got**
   (**U20** — the failure path needs the watermark).

### Index thread, on the reply — either way the last io_uring close CQE finishes the procedure and

clears the flag

- **OK:** the new WAL file (already renamed into its valid name by the elephant) becomes
  authoritative.
  1. **Wait out both sides' in-flight flush SQEs** — a live SQE reading the battery must not race
     the memcpy's overwrite, and the WALFile state must outlive its CQE. This is a constraint, not a
     choice.
  2. **Drop the old side's flush queue.** The old file needs no §8 close at all: it is abandoned
     mid-stream, its flushed prefix a clean byte-identical prefix of the same stream — a complete
     replayable unit in exactly the sense the recovery rule leans on (either file is a sane replay
     source; §5 of iteration 6 said the same) — and junk for retention (U16). Nothing logical is
     lost: the composite wrote every record into both sides, so the suffix beyond the frontier lives
     on in the new file's stream.
  3. **Memcpy the tmp WALFile's whole state** into the fixed battery place — arrays, current slot,
     running CRC, flush queue, flags. The tmp-side queue entries ride along: their `buffer_seq` are
     the new file's own stream positions, so the flushes continue from the fixed battery against the
     new descriptor without a seam.
  4. **Persist it** (§1 above — the mode barriers over the memcpy'd battery).
  5. **Swap in the direct interface on the tmp descriptor** — the same inode, now the new file.
  6. Arm io_uring to **close the old descriptor**; its CQ completion ends the procedure.

  A crash mid-memcpy is an accepted window: the new file plus a battery that is some prefix of the
  tmp state — the walk terminates, the replay stops at the first torn record, and the rest is the §1
  tail contract.

- **Failure:** swap back to the direct interface over the **old** file — its stream is complete: the
  `current_wal_len` prefix plus the composite suffix under its own ordinary discipline — and
  **remove whatever the elephant already renamed** (**U20**); arm io_uring to close the tmp
  descriptor; its CQ completion ends the procedure.

### Junk management

- The **in-progress directory is never cleaned**: it only ever holds fixed-name files, so its junk
  is a constant overhead, accepted (path and names: **U21**).
- Valid-named WAL and snapshot files are managed per **U16** — separate families, `(host, index)`
  groups, state order, N latest — with the pair-pinning constraint of **U20**.

### The wire note

`src/wire.zig`'s `RequestSnapshot` and `src/index.zig`'s `answerSnapshotRequest` stub ("the snapshot
store does not exist yet") predate this design; the snapshot store built here is the natural future
backend of that service. The integration is the consensus tract's business and stays out of scope.

## 6. The restart under the chain model (the U20 core, previewed)

The log of a `(host, index)` is the **union of its valid-named files in state order**: a rotated-out
file is a complete replayable unit (§8's own requirement), the next file's stream abuts it, and a
record carries its state (the `upgrade`, CONSENSUS-PLAN 2.5) — monotone and unique per
`(host, index)` — so the composite overlap (both sides receive every record byte-identically)
replays harmlessly: chain the files in state order, skip states already applied.

Under that model the plain rules of U17's proposal text break twice, both times on the same artifact
— a **pairless fragment**: a valid-named WAL file whose snapshot pair does not exist (the failure
path after the elephant's WAL rename, or a crash between the two renames).

1. A pairless fragment **cannot be replayed from the snapshot's state at all**: its stream starts at
   the snapshot-start state, above the greatest snapshot's state — `read_seek` finds nothing, and
   U17's plain "open the greatest tag" rule opens exactly this file.
2. As a **write target** it grows an internal state gap — its flushed frontier sits below the
   recovered state, and the records in between live only in the junk file — so a live `read_seek` /
   `readAfter` for a gap state fails on the file that the `RequestLog` answer is supposed to come
   from.

**Proposed resolution (folded into U20):** the snapshot = the greatest state whose pair file exists
(fallback to an older pair); the replay = the chain from that pair; the write target = the chain's
tail file at the recovered state — a pairless fragment is never a target, it is junk. The windows
then close: the OK-path crash window (both renames landed) recovers the pair completely (the
ordinary §1 tail loss aside); the failure/fragment cases recover from the fallback pair — the old
file covers everything, the composite wrote it byte-identically; a crash mid-cleanup leaves a
fragment that the same tail-file rule junks.

## Open questions

- **U19 (blocking).** The durability points of the snapshot choreography, three sub-questions. (a)
  The tmp side's flush machinery during the composite phase: the confirmed shape says which battery
  (RAM, never PMEM) and when durability (the end), but not which flushes run in between. The
  iteration-6 proposal's parenthetical "(no `O_DIRECT` obligation either)" reads as if the tmp file
  escapes the O_DIRECT discipline — but §2 pins `O_DIRECT` for both modes, and the non-PMEM shape's
  LBA-aligned battery exists for exactly those flushes. Proposed: the ordinary `wal_flush` machinery
  — whole-area `O_DIRECT` writes, sequential per file — reused by the composite with the stall
  inverted onto the procedure (§1); the parenthetical is dropped as loose talk of iteration 6: what
  the confirmation bought is the shape and the end-durability, not a second flush discipline.
  Alternative: plain page-cache writes plus one fdatasync at the end — a second write path, and a
  page cache §1 explicitly rejected for the WAL. (b) The end-durability mechanics: proposed as §1
  above — the memcpy'd battery persisted into the fixed place (the barrier sweep under PMEM; a
  comptime no-op under non-PMEM, the flush frontier carrying the ordinary contract); no fdatasync
  anywhere on the WAL path. (c) The snapshot file's own durability: the elephant dumps into a plain
  buffered writer (page cache) and renames the file into authority; a power cut before writeback
  leaves a torn authoritative snapshot, which the U20 fallback would mask at the price of the
  window's work. Proposed: the elephant fdatasyncs the snapshot once, after the dump, before its
  rename — "we make it durable after it is done" applied verbatim to the one file that is written in
  a single synchronous go. Confirm or override (or mix).

- **U20 (blocking).** The restart's file selection and the broken-pair artifacts. U17's confirmed
  text says "the recovery opens the file with the greatest tag" — but a **pairless fragment** (a
  valid-named WAL file whose snapshot pair does not exist: the failure path after the elephant's WAL
  rename, or a crash between the two renames) can _be_ the greatest-tag file. It cannot be replayed
  from the snapshot's state at all (its stream starts at the snapshot-start state, above the
  greatest snapshot's state — `read_seek` finds nothing), and as a write target it grows an internal
  state gap (its flushed frontier below the recovered state, the gap's records only in the junk
  file) that live `read_seek` / `readAfter` answers then fail on — §6 above works it through.
  Proposed: chain replay with state-dedup (rotation-closed files are complete units, streams
  abutting; the composite overlap is byte-identical; records carry monotone unique states); the
  snapshot = the greatest state whose pair file exists (fallback to an older pair); the write target
  = the chain's tail file at the recovered state — a fragment is never a target, it is junk; the
  elephant's reply carries the completed-step watermark, and the failure path unlinks whatever was
  renamed (restoring the old file as the greatest); a crash mid-cleanup leaves a fragment the same
  tail-file rule junks; retention never removes the greatest snapshot's pair file, the N-latest
  applying beyond it. This amends U17's plain greatest-tag rule. Confirm or override.

- **U21 (non-blocking).** The in-progress directory's path and the two fixed names (the tmp WAL and
  the snapshot file created there). Nothing pins them; the choreography only says "the in-progress
  directory" and "fixed name". Proposed: `<wal_path>.inprogress/` — a sibling of the WAL family
  under the same prefix — holding `wal.tmp` and `snapshot.tmp`, safe under the one-procedure
  invariant. Confirm or override.

# Critical.

Let's do transactional logic instead.

Let we have a fixed file, a log:

```
host_idx_1:index_idx_1:snapshot-path-1:wal-path-1\n
host_idx_2:index_idx_2:snapshot-path-2:wal-path-2\n
...
host_idx_n:index_idx_n:snapshot-path-n:wal-path-n\n
```

We take last line for given (host_idx, index_idx) as a source of snapshot and WAL for this index
state.

Instead of using temporary names, we start right from final names. Once a snapshot is ready - WAL
file exists because of the process - we put a new line into this file. This finalizes a transaction.

Lines that does not match this format are HARD STOP - an invalid line and ANY line after it are
ignored.

## Junk management.

Files that match snapshot and WAL format (so, we can compute their host_idx and index_idx) and
precede the oldest reference of this pair in this log file are to be removed.

An idea with "we remove any file that is not listed in the log" ain't working: candidate snapshot
and WAL files are not listed and should be removed by this logic.

## Periodical log compaction

Compaction leaves no more than N newest records for each host. It is performed at the end of the
snapshoting routine: it checks before the write if that log file grew too large. And apply
compaction if it did.
