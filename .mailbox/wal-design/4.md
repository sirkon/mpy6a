## 1. Critical restated: LBA is a runtime parameter

**Decision.** LBA is read from configuration at startup, not a comptime constant. Replacing the SSD
(say 4 KiB → 16 KiB LBA) must not require a recompile. The comptime surface of `WALFile` shrinks to
the mode (`pmem` / non-PMEM) and whatever the language forces; everything LBA-dependent becomes a
runtime field or a value computed at open.

Ripple effects, worked through iteration 3:

- **§3 Battery layout.** The control array's offset `N × LBA` is computed at open. It stays a
  multiple of 64 (every legal LBA is a power of two ≥ 512), so one cache line per control line and
  one CLWB unit per line survive unchanged.
- **§3 Pool partition (PMEM).** `area_stride` and the required pool length are computed at init from
  the runtime LBA. One correction to the stride formula falls out of runtime-ness: the stride must
  be rounded up to a multiple of **LBA** (in addition to page granularity), because the flush
  presents `data_area(p)` at `battery_base + p × LBA` as the `O_DIRECT` user buffer, and a stride
  that is not an LBA multiple would misalign every area after the first battery. This is not a
  choice, it is the alignment requirement of §3; with the comptime default it happened to hold by
  luck of the numbers.
- **§3 Block.** "A block boundary always coincides with a data-area boundary" relied on 1 MiB being
  a multiple of every _legal_ LBA; with runtime values the config check becomes: 1 MiB must be a
  multiple of the configured LBA, else the config is rejected at startup. The check against the
  device moves with it: at open, the file's `O_DIRECT` geometry is probed once, and a mismatch with
  the configured LBA is an error **at open**, not deferred to the first flush ("`EINVAL` on the
  first flush anyway" dies — the config knob now means something, so it is validated).
- **Non-PMEM battery allocation.** One `allocAligned` of the whole battery, alignment = max(LBA, 64)
  — a runtime alignment argument, no comptime dependence.
- **§4/§5 gate and flush math.** All already runtime arithmetic; nothing comptime there except the
  exact-fill branch, which keys on the **mode**, not the LBA, and stays comptime.

## 2. Critical restated: `WALController` semantics

**Decision.** The controller surface is:

```zig
pub const WALController = struct {
    pub fn open(self: *Self, host_idx: u8, index_idx: u16, state: u128) !*WALFile {}
    pub fn delete(self: *Self, host_idx: u8, index_idx: u16, state: u128) !void {}
};
```

Rationale, restated: within an index thread, the thread writes its **own** log and replicates the
logs of its mirror indexes living on other hosts — so both `host_idx` and `index_idx` are required
to name a file, and neither is derivable from the other. Logs are **rotated**: old log files stay
around for a while, and the moment of switching to a new file is reflected into the new file's
**name**, as a function of `state`.

Ripple effects:

- **§2 File identity.** The file of `(host_idx, index_idx)` under a given `state` is
  `<wal_path>.<index_idx>.<host_idx>.<epoch(state)>`, where `epoch(state)` is the naming slice of
  the state (the epoch id of CONSENSUS-PLAN 2.5; the exact slice is U13). The own log of index
  thread `i` is `open(own_host, i, state)`; a replica log is `open(h, i, state)` with
  `h ≠ own_host`. The earlier reading — "`WALController.open(index_idx, state)` is read as: the file
  of (calling index thread, state's host slice)" — is superseded: the host is now an explicit
  parameter, not a slice of `state`, and the caller's-thread assertion on `index_idx` stands.
- **§3 Control line / pool partition.** `battery_area(i, h)` keeps its formula; both i and h are
  controller parameters now, R and the pool length still known at init.
- **§8 Open.** Positioning at `state`'s counter is unchanged in substance; what changes is that
  `open` may name a file that **does not yet exist** (first file of a new epoch) — the "fresh file"
  case — or a file that exists with a **shorter** valid stream (see U14 for the LBA-change corner).
- **Rotation itself is out of scope here.** Which event triggers the switch, and when old files are
  reclaimed, is the compaction/snapshot subject; this design pins only the naming, the
  open/positioning choreography, and the requirement that a rotated file is a complete, replayable
  unit (the §7 close runs at rotation exactly as at shutdown).

## 3. What does not move

Mode comptime branches, the terminator rule (U4), the exact-fill gate as a mode branch (U5),
`crc_running` in the control line (U6 amendment), the columnar battery (U8), the offset index and
scan (U9), the no-durability surface (U12), flush sequentiality and the stall policy (U11), close
(§7) — all restated unchanged from iteration 3, now with LBA read as "the configured runtime LBA"
wherever it appears.

## Open questions

- **U13 (blocking).** The naming slice of `state` and the read scope across rotation. Proposal: the
  file name carries the **epoch id** slice of `state` only
  (`<wal_path>.<index_idx>.<host_idx>.<epoch>`), because the counter/index slices position _within_
  a file and would explode the file count; and `read_begin` / `read_seek(state)` are scoped to the
  epoch of the opened file — a cursor never crosses a rotation boundary, because `RequestLog` replay
  of a quorum sync asks for a state that lives in the current epoch, and any cross-epoch need
  arrives with the compaction subject. Confirm or override.
- **U14 (non-blocking).** LBA change across restarts. An existing file's length is a multiple of the
  **old** LBA; opened under a new LBA the scan may find `L` not a multiple and crop up to `LBA − 1`
  bytes of the tail, and old block-CRC positions (1 MiB grid) are unaffected, but
  area-boundary/rollover alignment of mid-file content is unaffected too (block boundaries are
  content-relative, not LBA-relative). Proposal: the crop rule stands (the trimmed tail is by
  definition below the recovered `state`, so nothing positionable is lost), and the config documents
  LBA as deployment-tied. Confirm or override.

## U13.

Aggree on `epoch_id` slice of the state in the name. This especially makes a sense since we can bind
epoch bump to an state index being large enough without a risk to hit u64 ceiling within a state. It
is rather a theoretical possibility mostly, but still a gap in a logic. Nice to have it to be taken
care of.

mpy6a lba-migrate -f 4096 -t 16384
