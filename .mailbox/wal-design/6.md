## 1. Critical restated: the name is a full-state tag, not an epoch

**Decision.** The WAL file of `(index_idx, host_idx)` is
`<wal_path>.<index_idx>.<host_idx>.<state>`, where `<state>` is the **full `state: u128`** — the
whole `(host_id: u8, index_id: u16, epoch_id: u40, index: u64)` concat of CONSENSUS-PLAN 2.5 — and
its **only semantics is "just some unique tag"**: the name is never parsed, no slice of it is
extracted, and nothing (least of all an epoch) is ever derived back from it. This **supersedes** the
promoted §2's `<epoch>` naming and its rationale ("the counter and index slices would explode the
file count"): tags are minted only at **file creation** — at rotation and at snapshot finalization
(§2 below), using the then-current full `state` — never per write, per open, or per state advance,
so the file count is unchanged; the tag is a creation-time uniqueness witness, not a locator.

Ripple effects:

- **Uniqueness by construction.** `state` is monotone per (host, index) within and across epochs
  (the `index: u64` counter advances, the `epoch_id` bumps at rotation), so a minted tag never
  collides with an existing name. The `host_id`/`index_id` slices inside `state` are redundant with
  the explicit `<host_idx>.<index_idx>` components — kept as explicit components anyway, for
  ordering and greppability; the tag itself is opaque.
- **Order survives opacity.** "Just some unique tag" is a semantics freeze on the _name_, not on the
  _u128_: the big-endian concat makes `state` comparison a total order consistent with recency,
  which is exactly what the junk management below ("order them by state and leave only N latest")
  needs. Retention compares states; it never decodes them. The rendering of the tag in the name is
  U18.
- **Rotation trigger unchanged.** The U13 fold — the epoch bump bound to a state index threshold,
  closing the u64 wrap-around gap by construction — survives untouched: it was never about the name.
  Rotation still mints a fresh file when the epoch's `index` slice reaches the configured bound; the
  fresh file just carries a full-state tag now instead of an epoch slice. The §8 close still runs at
  rotation.
- **Read cursors lose their epoch scoping — and don't need it.** The promoted §9 scoped `read_begin`
  / `read_seek(state)` to the epoch of the opened file, a rationale that leaned on the name carrying
  the epoch. With an opaque tag the scoping restates simpler: a cursor is scoped to **the opened
  file**; `read_seek(state)` resolves a state to an offset through the offset index of that file.
  This holds because `RequestLog` replay of a quorum sync asks for a state at or above the file's
  creation tag — the quorum never asks a live file for a state of a previous epoch — and the
  snapshot subject (§2 below) is what pins recovery to snapshot + WAL pairs. Cross-file reads arrive
  only through recovery, which opens files explicitly, not through a live cursor.
- **`WALController` surface unchanged.** `open(host_idx, index_idx, state)` / `delete(...)` keep
  their signatures; what changes is internal: `open` names the file by the **current** tag of the
  `(index, host)` slot — the tag minted at the last rotation or snapshot finalization — not by a
  slice of the caller's `state`. The caller's `state` positions _within_ the file (§9 scan, offset
  index); it does not pick the name. The controller holds the current-tag mapping per
  `(index, host)`; a restart rebuilds it by the recovery rule of U17, never by parsing names.

## 2. Critical restated: snapshotting moves out of the consensus chain, into this design

**Decision.** Snapshotting is a **WAL/index lifecycle procedure**, driven by a timer inside each
index thread and executed by an elephant thread (`src/elephant.zig`) — the consensus tract is never
a party to it. This **supersedes** the promoted §11's closing disclaimer ("snapshots and
front-truncation stay a separate subject"): the snapshot choreography is now this design's §12, and
only front-truncation beyond what retention does remains out of scope.

### Prerequisites (restated as fact)

- An **index** is an execution entity holding an **own index state** (with timing-wheel machinery)
  and **mirror states** of other indexes, commanded through cluster connections, with **no**
  timing-wheel machinery over them. The index state
  (`active sessions, sessions ordered by replay/compensation order, ...`) is dumpable through its
  public interface:

```zig
const IndexState = struct {
    // ...
    pub fn clone(self: *Self, dst_allocator: *std.heap.Arena) !*Self {}
    pub fn dumper(self: *Self) !IndexState.Dumper {}  // on a cloned entity
    const Dumper = struct {
        // Synchronous on purpose: a large placeholder buffer (512 KiB or more) makes io_uring
        // meaningless for the task.
        pub fn dump(self: *Self, placeholder: []u8, dst: std.Io.Writer) !void {}
    };
};
```

- **Elephants** are execution entities on their own threads, receiving orders through cross-task
  slots / io_uring messages carrying slot references, executing **heavy blocking logic
  synchronously**. Round-robin task distribution.
- `WALController` marks a fixed battery area per `(host_idx, index_idx)` file and gains a
  temporary-file surface:

```zig
pub const WALController = struct {
    pub fn open(self: *Self, host_idx: u8, index_idx: u16, state: u128) !*WALFile {}
    // A wrapper over the given RW descriptor plus a buffer for temporary WAL files.
    pub fn tmp(self: *Self, tmp_fd: std.posix.fd_t) *WALFile {}
};
```

### Choreography (restated, one invariant pinned)

**Invariant: at most one snapshot procedure at a time, process-wide.** A single atomically
accessible flag ("snapshot in process", boolean or integer — whichever is cheaper) serializes all of
it; there is no parallel snapshot creation, own or mirrored, ever.

Index thread, per snapshot decision (own or mirrored state — `host_idx` may name a mirror):

1. A **multishot timer** in each index thread (tick on the order of 1–10 minutes) wakes the review;
   the thread reviews its states' WAL sizes.
2. A state's WAL grew past the configured bound → it deserves a snapshot.
3. **CAS the flag** false → true; failure means another procedure is in flight — drop the idea this
   tick.
4. On success, set the meta-state and arm io_uring to create an **empty** temporary WAL file in the
   **in-progress directory** under a **fixed name** (safe under the invariant):

```zig
snapshot_in_progress: ?struct {
    host_idx: u8,
    state: *IndexState,
    current_wal_len: usize,
},
```

5. On the CQ reply carrying the FD (and `snapshot_in_progress` must be non-null then — otherwise the
   procedure is already failed):
   1. **Clone** the given state (arena).
   2. Switch the file's write interface to a **composite WAL file**: every `write()` fans out into
      the **old** WAL file and the **temporary** one. An error on the temporary-side write, or a
      stalled temporary-side flush, fails the snapshot — never the old file's stall policy (§6: an
      old-file flush failure still stalls the old file as before; a temporary-side failure is
      reported on the procedure, not on the log).
   3. Send the "create snapshot" task to a round-robin-chosen elephant.
   4. Keep working — the composite writes keep flowing; nothing blocks the ring loop.

Elephant thread, on the task — all synchronous, all blocking, exactly what elephants are for:

1. Create the snapshot file in the in-progress directory (fixed name). Dump is the **cloned**
   state's `Dumper.dump` with a ≥ 512 KiB placeholder into a plain buffered writer — no io_uring.
2. Rename the temporary WAL file into its **valid name** — the new full-state tag (§1) minted from
   the state at snapshot start.
3. Rename the snapshot into `snapshot.<host>.<index>.<state>`.
4. Replace the `snapshot` symlink → the new snapshot name.
5. Reply OK (or failure) to the index through the slot.

Index thread, on the elephant's reply — either way the last io_uring close CQE finishes the
procedure and clears the flag:

- **OK:** the new WAL file (already renamed into its valid name by the elephant) becomes
  authoritative — **memcpy the temporary battery buffer into the fixed battery place** of the
  `(host_idx, index_idx)` slot, swap the composite interface for the **direct** WAL file interface
  pointing at the new file, arm io_uring to **close the old file**. The old file's content beyond
  `current_wal_len` is abandoned (the composite kept it complete and replayable, but the new file
  supersedes it); its CQ completion ends the procedure.
- **Failure:** swap back to the direct interface over the **old** file (the composite's old-side
  writes already landed there; the `current_wal_len` prefix plus the composite suffix make it
  complete), arm io_uring to **close the temporary file**; its CQ completion ends the procedure.

### Junk management (restated)

- The **in-progress directory is never cleaned**: it only ever holds fixed-name files, so its junk
  is a constant overhead, accepted.
- Valid-named WAL and snapshot files are managed **separately**, grouped by host, **ordered by
  state** (the total order of §1), **only the N latest kept**, everything else removed. The grouping
  granularity is U16.

## 3. Ripples on the promoted sections

- **§7 (no durability notification) stands — clarified.** The elephant's OK/failure reply gates a
  _file lifecycle transition_, not a client answer and not a record's durability: no consensus step
  waits for it, and `write()` returning still means "buffered, nothing more". The notification
  surface of §7 (no waiters, no FIFOs, no per-record events) is unchanged; the snapshot procedure is
  a controller-internal state machine, not a WAL durability surface.
- **§8 (close) gains one call site.** The close runs at rotation, at shutdown — and the old file of
  a **successful** snapshot needs no close at all: it is abandoned mid-stream with its composite
  suffix intact, a complete replayable unit by construction of the composite (both sides receive
  every record byte-identically), which is what the recovery rule of U17 leans on. The abandoned
  suffix's final area is not padded to `data_len = LBA` — accepted: the §9 scan's tail crop treats a
  non-LBA-multiple length as a torn final flush, which is exactly what an abandoned tail is.
- **§9 (open/scan) needs no change for the live path.** The tmp battery is never recovered: on
  failure or crash the in-progress file is junk; on success its content is already memcpy'd into the
  fixed battery, which the ordinary scan of the renamed file walks. Which file a restart opens —
  when a crash left both the old and the new valid-named file — is U17.
- **§11 (LBA migration) stands.** The `lba-migrate` contract is untouched by naming and snapshots:
  it is a re-chunk of the same byte stream under a new LBA; the full-state tag in the name is opaque
  and migrates verbatim. The tool's re-lay must additionally **not** interpret the tag or the
  `snapshot` symlink — it operates per file, and junk/retention is the runtime's business.
- **§2/§9 promotion text is stale.** Every "epoch" mention in `designs/wal-design.md` §2/§9 (name
  slice, epoch scoping of cursors, "the first file of a new epoch") is superseded by §1 of this
  letter; the rewrite happens at the next promotion.

## Open questions

- **U15 (blocking).** The shape of the `tmp(tmp_fd)` WALFile. The temporary file's battery is not in
  the PMEM pool partition (the partition is sized for the fixed `(index, host)` slots only) and
  nothing persistent rides on it — a crash turns it into junk by design. Proposed: the tmp WALFile
  instantiates the **non-PMEM shape even under a PMEM deployment** — one ordinary aligned heap
  battery, `persist()` a comptime no-op, the exact-fill gate absent — so the tmp file is written
  buffered (no `O_DIRECT` obligation either) and the composite's old side keeps its own unchanged
  mode semantics. Confirm or override.
- **U16 (non-blocking).** Retention granularity. "Group by host, order by state, keep N latest" —
  but WAL files are per `(index, host)`, and ordering by full `state` mixes `index_id`s: a host
  group's N-latest may drop another index's only WAL file while a first index keeps N. Proposed:
  group **WAL files by `(host, index)`** and snapshots by host (a snapshot is per
  `(host, index, state)` too — same fix applies), keep the N latest per group. Confirm or override.
- **U17 (blocking).** The crash-window recovery rule. Between the elephant's WAL rename and the
  index's flag-clearing close CQE, a crash leaves **two** valid-named, complete, replayable WAL
  files for one `(host, index)` — plus possibly a dangling `snapshot` symlink swap done in between.
  Proposed: on startup, per `(host, index)`, the recovery opens the file with the **greatest tag**
  (the total order of §1); the loser is junk for retention (U16); the `snapshot` symlink is advisory
  only — recovery never reads it, it exists for tooling/humans — and the snapshot's own name pairs
  it with its WAL file for the same greatest-tag rule. Confirm or override.
- **U18 (non-blocking).** Tag rendering in the name. Proposed: `<state>` renders as **32 lowercase
  hex digits** (fixed width, sortable, no separator hazards); decimal renders variable-length and
  breaks lexicographic tooling. Confirm or override.
