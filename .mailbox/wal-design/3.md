## 1. Decisions, restated as facts

**U1 — durability contract.** WAL files are opened `O_DIRECT`; there is no page cache anywhere in
the WAL path and deliberately no fsync/fdatasync/FUA in either mode — we already buffer, a second
buffer would only add latency. Non-PMEM durability therefore covers the process crash exactly: a
record is durable once its buffer's `O_DIRECT` flush completed, and a power cut may lose even
completed flushes that still sit in the device's volatile write cache — accepted; power-loss
durability is what PMEM mode exists for. The un-flushed tail lost to a process crash is recovered
from the quorum through the background sync (`docs/consensus.md`, the `RequestLog` service of stage
7). If a stronger non-PMEM contract is ever wanted, that is a new subject, not an amendment here.

**U2 — flush I/O mode.** `O_DIRECT` in both modes, mode-independent open flags, and buffers laid out
so the alignment requirement holds by construction (§3).

**U3 — geometry.** The control line is never written to disk; it is battery metadata only, one
64-byte cache line so that a barrier write covers it with one CLWB. The data area is one device LBA
(4 KiB, 16 KiB, whatever the drive has). A flush is always one whole data area at an LBA-multiple
file offset, so file-side `O_DIRECT` alignment is automatic and the file length is always a multiple
of the LBA. Each file's buffers form a ring addressed by head and tail — plain fields, no atomics —
because every write and read task is set up in the index thread that owns the file. The NVDIMM pool
is partitioned, not searched: with the number of indexes and the replication factor both known at
startup, the required pool length is known, and the battery of a given index of a given host sits at
a computed offset (§3).

**U4 — the terminator rule.** An exactly filled buffer is never exposed (control line persisted,
flush queued) before its successor's control line is initialized to `data_len = 0`, filled flag
cleared, and persisted — otherwise a restart would see a filled tail whose successor still carries a
stale line from a previous ring lap and would replay garbage. Generalized, this is the battery's
core invariant: **a data area only ever receives bytes after its own control line has been persisted
as a zero-terminator.** Every path that makes a slot current (open-reset, exact-fill transition)
satisfies it.

**U5 — exact-fill gate.** Kept, but only in PMEM mode, through the comptime branch of the pad
(`if (mode == .pmem)` around the gate). Non-PMEM accepts the fill: no walk ever consults a RAM
battery.

**U6 — the open block.** Incomplete blocks have no block CRC, at a crash and at a clean close alike.
The loosening is a probability tradeoff, accepted: block CRCs reduce the chance of undetected bit
rot, they never make it zero, and the tail block additionally rides on the per-record checksums and
the self-delimiting framing, with replay stopping at the first torn record. The running CRC of the
open block lives in `WALFile` RAM registers and in the current slot's control line (`crc_running`),
and is restored at open (§8) — this clause is the amendment the pad of iteration 2 made to the
original U6 restatement.

**U7 — one type, two initializations.** A single `WALFile` comptime-parametrized by the mode.
PMEM-only barrier writes; different initialization only: the battery is a computed slice of the
process-wide DAX-mapped NVDIMM pool in PMEM mode, and one ordinary aligned allocation of the whole
buffer space otherwise. The control-line fields are battery parameters, pinned in §3 minus the
rejected `block_crc`.

**U8 — columnar battery.** The battery is two parallel arrays: the data array (`N × LBA`) opens the
battery area, so every data area is LBA-aligned by construction and every flush presents an aligned
user buffer; the control array (`N × u512`, the per-slot header of the source, one cache line per
slot) follows at offset `N × LBA`, a multiple of 64, so every control line is its own aligned CLWB
unit. Zero slack, the recovery walk reads one linear line per slot from the control array,
`persist()` takes one data range plus one control line. The adjacency-keeping alternative (a
`2 × LBA` stride, doubling the pool) is rejected. LBA sourcing: a comptime constant, default 4096,
any power of two from 512 to 1 MiB that divides the block; checked against the device at open — a
mismatch surfaces as `EINVAL` on the first flush anyway.

**U9 — positioning and the running CRC.** The open block continues in place; it is never finalized
with padding at open. Its running CRC32C is a control-line field (`crc_running`), written by the
same tail-metadata persist that writes `data_len`, and carried across exact-fill transitions into
the successor's terminator. At open, PMEM mode reads it straight off the walk's terminator line;
non-PMEM mode derives it from the scan, which reads every byte of the valid stream anyway to verify
complete blocks against their trailing CRC32C and to replay the records for the epoch — that read
was the only cost of restoring, and it is already paid. No writer caller positions below the end of
the valid stream today (the consensus tract's `Isolate` raises expectations; it does not truncate
local logs), so the trim choreography of §8 is dormant until the compaction/snapshot subject makes
it reachable; it is specified now so that subject inherits it. The offset index is sparse: one entry
per 1 MiB block naming its file offset and its first record's state, rebuilt by the scan, appended
on rollover; `read_seek(state)` lands on the block and scans at most 1 MiB.

**U10 — the own log.** The own log of index thread `i` is the file for `(i, own_host)` under the
replica naming, `<wal_path>.<i>.<own_host>`, one battery per file like every other file; `wal_path`
remains the config prefix, and the bare path stops naming a file — the stub's shared own-log file
dies with the stub. `WALController.open(index_idx, state)` is read as: the file of (calling index
thread, `state`'s host slice), positioned at `state`'s counter, with `index_idx` asserted equal to
the caller's thread ordinal; `read_seek(state)` is the same resolution on the read side.

**U11 — flush failure.** A completion with `res != LBA` stalls the file: keep the queue and the
buffer, report the error once, do not rearm. The file stays failed until the controller decides; the
queue order is intact — nothing past the failure was ever written — so a controller-level retry of
the same head is always safe.

**U12 — no durability notification.** The consensus tract never gates a client answer on local
durability: the leader answers on quorum approval (`docs/consensus.md`), and in non-PMEM deployments
the survival of a host's tail rides on replication and the background sync, not on its own disk. The
WAL therefore exposes no durability waiters, no FIFOs, and no per-record completion events;
`write()` returning means the record is buffered, nothing more — §6 states what the driver does with
that.

## 2. File identity, threading, and naming

One file per (index thread, host): the replica logs are already named `<wal_path>.<index_id>.<host>`
(`src/index.zig`), and the own log of index thread `i` is `<wal_path>.<i>.<own_host>` under the same
scheme — the own host's slot, skipped by today's `openReplicaLog`, becomes the own log instead of a
hole in the array. Today every index thread opens the bare `wal_path`, which the stub tolerates only
because 43-byte `O_APPEND` writes interleave whole; the battery scheme needs one writer per file,
and now every thread has exactly one. The log of a host is the union of the per-index files;
ordering inside one file is total, and each session lives in exactly one file (sessions are
partitioned across index threads by id).

`state: u128` carries `(host_id, index_id, epoch_id, index)` (CONSENSUS-PLAN 2.5), so
`WALController.open(index_idx, state)` is read as: the file of (calling index thread, `state`'s host
slice), positioned at `state`'s counter; `read_seek(state)` is the same resolution on the read side.
The controller is a process-wide table over (index, host) → file + battery, but each entry is
touched only by its index thread; nothing WAL-related crosses threads (records produced elsewhere
already arrive through the inbox as this thread's work), so the battery head/tail and the flush
queue are plain fields.

## 3. Pinned constants, layouts, and formats

- **LBA.** The data-area size. Comptime constant, default 4096; any power of two from 512 to 1 MiB
  is legal (it must divide the block). Checked against the device at open; a mismatch surfaces as
  `EINVAL` on the first flush anyway.
- **Battery.** N buffers per file, the same N for every battery (a config knob). Sizing criterion:
  enough buffers to damp sequential writes — `N × LBA` comfortably above the burst one flush
  round-trip must absorb; N ≥ 2. The slot of logical area position p is `p mod N`.
- **Battery layout.** Columnar: the data array (`N × LBA`) at the battery-area start, aligned by
  construction; the control array (`N × u512`) at offset `N × LBA`, one 64-byte line per slot.
- **Pool partition (PMEM).** The whole NVDIMM area is DAX-mapped once at startup, before threads
  spawn. `battery_area(i, h) = pool_base + (i × R + h) × area_stride`, with `area_stride =`
  `N × (LBA + 64)` rounded up to a page, R the replication factor and i the index-thread ordinal —
  both known at init, so the required pool length is known; a restart recomputes the same addresses.
  Non-PMEM: one aligned heap allocation of the battery per open file. An empty `wal_path` keeps no
  logs at all (existing semantics); the pool is simply not mapped.
- **Control line.** One cache line per slot: `data_len: u32` (valid bytes in the area; LBA when
  filled), `flags: u32` (bit 0 = filled), `buffer_seq: u64` (the area's file position ÷ LBA — the
  flush offset, and a stale-lap sanity check for the walk), `crc_running: u32` (the running CRC32C
  state of the open block as of `data_len`; meaningful on the current slot, carried to the
  successor's terminator at an exact fill), `reserved: u32`. No `block_crc` — the completed block's
  CRC lives in the block's own last 4 bytes; no closed flag — open resets the ring (§8). The control
  line is never written to disk; it is battery metadata only, one line so a barrier write covers it
  with one CLWB.
- **Block.** 1 MiB over the logical stream. Bytes `[0, 1 MiB − 4)` are content; the last 4 bytes
  hold CRC32C (Castagnoli) over the content, zero padding counted. A block boundary always coincides
  with a data-area boundary (1 MiB is a multiple of every legal LBA), so the CRC slot always lands
  inside the last data area of its block, and every block rollover is also a buffer fill.
- **Record.** Unchanged from `src/wal.zig`:
  `magic u16 | len u32 | crc32 u32 | session u128 | op u8 | upgrade u128`, 43 bytes,
  self-delimiting, per-record checksum. One `write()` call is one record. A record that does not fit
  the open block's content remainder zero-pads it — the WAL stores the completed block's CRC right
  then, inside the battery — and starts in the next block; a record larger than a block starts at a
  block boundary and spans blocks. The capacity gate accounts for the pad.

## 4. Write path

`write(record)`, in order, on the owning index thread:

1. **Gate.** `capacity = free_buffers × LBA + (LBA − current.data_len)`, where free counts only
   buffers neither queued nor in flight (a buffer is reusable only after its flush completed).
   `need = record.len + rollover_pad`, where `rollover_pad` is the open block's content remainder if
   the record does not fit it, else 0. `need > capacity` → immediate error, nothing queued, battery
   untouched. PMEM-only (comptime), the exact-fill rule: reject also a write whose absorption would
   end with the last available buffer filled exactly and no free successor.
2. **Rollover.** If the record does not fit the open block's remainder: zero-fill the remainder into
   the battery (zeros into the running CRC), store the block's CRC32C in its last 4 bytes, reset the
   running CRC for the next block. The pad may itself fill areas — run step 4's transition for each.
3. **Copy.** Copy the record into the current data area, updating the running CRC incrementally; the
   copy may spill over several areas. `persist()` the freshly written ranges — data first.
4. **Exact-fill transition**, while an area was filled exactly: (a) initialize the successor's
   control line — `data_len = 0`, filled cleared, `buffer_seq = current + 1`, `crc_running` = the
   state the successor's bytes will continue from (a fresh block's state when the fill was also a
   rollover) — and persist it: the terminator first; (b) mark the filled buffer's control line —
   `data_len = LBA`, filled set — and persist; (c) push the filled buffer onto the per-file flush
   queue; (d) the successor becomes current, copying continues.
5. **Tail metadata.** Update the current control line's `data_len` and `crc_running`; persist.
6. **Exit kick.** If the writing flag is clear and the queue is non-empty: register a `wal_flush`
   context in `RingSlots` (the `*WALFile` travels in the `TaskCtx` alongside the existing variants,
   replacing the per-record `flush_op`/`log_command` write path of `src/index.zig`), arm one SQE —
   `write(fd, data_area(queue head), LBA)` at offset `buffer_seq × LBA`, `O_DIRECT` — set the flag,
   return.

`persist(range)` is the single point of divergence: CLWB per line, then one SFENCE, in PMEM mode; a
comptime no-op otherwise. Data is always persisted before any control line that exposes it.

## 5. Flush path

One flush SQE in flight per file, strictly sequential: a failed write N can never be preceded in the
file by N+1's bytes at a known length, so the file length stays a meaningful recovery cursor.
Nothing prevents different files from flushing in parallel — the contexts are per file.

The CQ handler, on a `wal_flush` completion:

1. Return the flushed buffer to the front of the free order (cache warmth).
2. Queue empty → clear the writing flag; otherwise arm the next SQE from the queue head, the flag
   stays.
3. Continue the handler's own work; the WAL never blocks the ring loop.

A completion with `res != LBA` is a failure and stalls the file: keep the queue and the buffer,
report the error once, do not rearm. The file stays failed until the controller decides; the queue
order is intact — nothing past the failure was ever written — so a controller-level retry of the
same head is always safe.

## 6. No durability notification

The consensus tract answers the client on quorum approval and never on local durability; in non-PMEM
deployments a lost host's tail is rebuilt from the mirrors by the background sync
(`docs/consensus.md`). The WAL therefore has no durability surface at all: no waiters, no FIFOs, no
per-record completion events — `write()` returning means the record is buffered, nothing more. The
flush pipeline exists for recovery, not for notification. The own-log flush of CONSENSUS-PLAN 2.5
step 5 becomes this synchronous battery write, and the step that today rides the `flush_op`
completion (`finishFlush` of `src/index.zig`: the session advance to `ExpectReply` and the client
reply of step 6) moves inline into the driver. In PMEM mode, `write()` returning is incidentally the
durability point — data and the exposing control lines already passed CLWB → SFENCE before any
flush; the property stands, unconsumed: no consensus step waits for it.

## 7. Close

Pad the current data area with zeros to its end (zeros counted in the running CRC; if the pad
exhausts the open block, the block's CRC is stored as at any rollover, otherwise the block stays
open — the loosening above), set `data_len = LBA`, mark filled, persist, enqueue as the final unit,
kick. The caller then drains its ring — the existing shutdown choreography — until the file's queue
is empty and the flag is clear; close the descriptor. A torn flush of this final unit is ignored by
replay exactly as before: the zeros are not a record.

## 8. Open, recovery, and read cursors

**Scan.** The logical stream is the file bytes `[0, L)` plus, in PMEM mode, the ring tail: slot
`(L / LBA) mod N` holds the first unflushed area; filled control lines continue the file (LBA each,
`buffer_seq` checked against the walk position), the first non-filled line ends the walk, its
`data_len` bounding the partial and its `crc_running` the restored running CRC. Termination is
guaranteed by the three pinned invariants: the terminator rule (every current slot was a persisted
zero-terminator before receiving data), slot reuse only after flush completion, and the PMEM
exact-fill error. If L is not an LBA multiple, crop the tail (a torn final flush). Complete blocks
verify by CRC32C; replay decodes self-delimiting records and stops at the first torn record or bad
block; the restart epoch (`docs/consensus.md`) is computed by this scan exactly as `src/wal.zig`
does today. Non-PMEM: the battery was RAM, the stream is the file alone, and the open block's
running CRC is derived by the same scan — which reads every byte of the valid stream anyway.

**Positioning.** Three cases:

- _Normal restart_ — the recovered state is the end of the valid stream: the writer continues in
  place. Current buffer = the walk's terminator slot with its `data_len` and `crc_running`; no
  reset; the committed-but-unflushed tail stays live, the walk rebuilds the flush queue from the
  filled tail buffers in `buffer_seq` order, and the first kick (at open or on the next write,
  whichever comes first) resumes flushing them.
- _State below the stream's end_ — a suffix must be dropped. Trim the ring first (re-zero every
  trimmed control line as a terminator, deepest first, then persist), then truncate the file to the
  state's byte offset. A crash in between replays at worst the not-yet-dropped suffix (the caller
  retries the open at the same state; it converges), never garbage. No writer caller positions below
  the stream's end today; the choreography is dormant, specified for the compaction/snapshot
  subject.
- _Fresh file, or after `delete`_ — reset all N control lines to terminators (one persist sweep; a
  memset otherwise), current = slot 0, running CRC fresh, L = 0.

**Offset index.** Sparse, one entry per 1 MiB block naming its file offset and its first record's
state; rebuilt by the scan and appended on rollover; `read_seek(state)` lands on the block and scans
at most 1 MiB. RAM cost is one entry per megabyte of log.

**Read cursors.** `read_begin()` positions at stream offset 0; `read_seek(state)` resolves through
the offset index. In PMEM mode the stream includes the live ring tail, so a cursor may serve
`RequestLog` reads of records that have not flushed yet — same thread, plain reads.

`delete(index_idx, state)` removes the file of that (thread, host); the battery is not freed — the
next `open` resets it (third case above).

## 9. The complete mode delta

1. Battery backing: a computed slice of the DAX-mapped pool vs one aligned heap allocation.
2. `persist()`: CLWB → SFENCE vs a comptime no-op.
3. The exact-fill gate: present vs absent (comptime branch).
4. Recovery authority: the ring is a persistent tail and the walk consults it, vs scratch memory
   that died with the process.

Everything else — API, gate math, copy/transition ordering, flush queue mechanics, sequentiality,
the stall policy, close, block and record formats, control lines, the columnar layout — is one
shared implementation. Snapshots and front-truncation (compaction) stay a separate subject; this
design covers the buffered battery writer, reader, and crash recovery only.

# Critical

## LBA is a **RUNTIME** parameter.

We definitely don't want to recompile the thing just because our new SSD has 16Kb LBA instead of 4Kb
on the old one.

## WALController semantics tweaked

It is

```zig
pub const WALController = struct {
    pub fn open(self: *Self, host_idx: u8, index_idx: u16, state: u128) !*WALFile {}

    pub fn delete(self: *Self, host_idx: u8, index_idx: u16, state: u128) !void {}
};
```

Why all these matter:

- Within an index, it writes its own log and replicates logs from its mirror indexes from other
  hosts. So, `host_idx` and `index_idx` are required.
- We need to rotate logs and old logs stay for a while. The moment we decide to switch to another
  file (state of the index) is reflected into that file name.
