## 2. What the pad changes

1. **The frame is self-delimiting at the transport layer.** The two-byte length is the frame's boundary on the wire, not
   a parser heuristic. The `uvarint` prefix that `blog.append` puts in front of the payload slice stays, because the
   commit envelope sits after a variable-length payload and the parser still needs to know where the payload ends; the
   length field tells the receiver how much to read, the payload prefix tells the parser where the envelope starts.
2. **There is no cell and no zero padding.** A frame is exactly as long as its length field says; the receive buffer
   holds frames back to back, and padding never reaches the parser.
3. **Partial deliveries are the normal path, not an error.** The receive path reads the four-byte prefix, then arms
   exactly the frame's remaining length; a short completion continues into the same slot at the running offset. TCP
   guarantees that the next completion is the rest of the frame, so there is no frame-boundary scan and no second
   assembly buffer.
4. **The reorder buffer is local code.** `src/reorder_buffer.zig` is the one copied unit, because the fixed-item `push`
   API of `zigring.ReorderBuffer` cannot take a frame in pieces. `zigring` remains the dependency for everything else;
   nothing else is vendored. The pad spells the path `reodrder_buffer.zig`; the typo is taken as accidental and the
   correct spelling is used here.
5. **`invalid_host` joins the verdict map.** U25 below asks only which side emits it.
6. **The 4 KiB cap removes the "cell size" knob.** Iteration 2's proposed `cluster.frame_cell` is withdrawn; the cap is
   a constant of the codec, because it is a wire property, not an operator choice. `cluster.reorder_window` survives,
   because the lift and the flow control still need a window (§5.5).

## 3. Topology

Unchanged from iteration 2 §3, restated as the frame of reference:

- index thread `i` on host `h` dials every host `j > h` with `pushConnectIp4` on its own ring and owns the socket; no
  front is involved.
- it accepts nothing directly: a connection from `j < h` is accepted by whichever front wins the peer listener's
  multishot and is handed to index `i` by the slot path of §4.2.
- no self-link; `hosts == 1` is dark (no `cluster` block, no peer listener, no link); `hosts > 1` requires the block.
- one link per `(index thread, peer host)`, never multiplexed across index numbers; the same index number on both hosts
  is the pair, so the frame needs no index field and the receive path needs no demux.
- one socket serves both directions; the higher host answers on the same socket. The socket count stays
  `index_count * (replication_factor - 1)` per process.

The memory budget is now fixed by U18 and §5: per direction, a receive reorder buffer of `2 * window * 4096` bytes (128
KiB at the default window of 16) and a send ring of `inflight * 4096` bytes (32 KiB at 8). Both directions therefore
cost 320 KiB per link, plus the link tables. With `links = indexes * (hosts - 1)` the operator can size the process from
the socket count; nothing is allocated before a link is promoted (iteration 2 §6).

## 4. Link establishment and hand-over

The handshake, in the order the pad confirms:

1. after the connect CQE, the dialer sends exactly the 5-byte greet `(version: u16, host_idx: u8, index_idx: u16)`,
   little endian and packed, and sends nothing else;
2. the front reads exactly 5 bytes with a deadline, validates `version`, `host_idx` and `index_idx`, and either writes a
   reject reply itself and closes, or hands the socket to index `index_idx`;
3. the hand-over is a `CrossTaskSlots` slot holding a `CrossTask.PeerLink` plus a `MSG_RING` into the target index's
   ring, never an index-inbox message;
4. the index re-validates what it was told, checks for an existing link, and answers accept or reject in one 7-byte
   reply;
5. the dialer reads exactly 7 bytes, validates the accepter's identity and the verdict, and only then starts framing;
   the index starts framing only after its reply's send CQE.

### 4.1 The greet (dialer)

Unchanged from iteration 2 §4.1. The greet is not a frame: no `seq_id`, no reorder buffer, no length field. Its fixed
five bytes are a v1 property; `version` is its first field so an incompatible peer is detected before any frame is
parsed. `version` is a compile-time constant of `src/cluster_transport.zig`, bumped on an incompatible change. A failed
connect is a retry (U10), not a fatality.

### 4.2 Front intake (U4)

Unchanged except for the validation list, which the pad now makes the front's job:

1. the peer accept CQE carries the descriptor in `res`; the front takes a handshake entry (U20), records the fd, and
   arms a one-shot receive for exactly the five greet bytes with `cluster.handshake_timeout`. The entry owns the
   five-byte request buffer and a seven-byte reply buffer, so no kernel write targets a loop frame. Partial reads re-arm
   for the remainder; EOF, a short read at the deadline, or an error closes the fd and releases the entry.
2. on five bytes the front checks `version` first, because a foreign version makes the rest of the greet's layout
   unknown. If `version != local`, it writes the 7-byte reply
   `(local version, local host_idx, 0xFFFF, version_mismatch)` and closes after that send's CQE. If `host_idx >= hosts`
   or `host_idx == cfg.host_index`, it does the same with `invalid_host` (U25). If `index_idx >= cfg.indexes`, it does
   the same with `unknown_index`: there is no target ring. Otherwise it calls `std.posix.getpeername`, computes
   `source_ok` (true only when the four address bytes match the parsed `cluster.peers[host_idx]`), and routes. These
   three are the only replies the front writes, and it writes them only on a connection it will close instead of handing
   over.
3. the front acquires a `cross_task_slots` slot, writes `CrossTask.PeerLink`, and posts `MSG_RING` with
   `taskIdx = messages.CrossTaskMessageIdx` and `res = slot_idx` to `ctrl.rings[cfg.fronts + index_idx].ring.fd`, the
   exact shape of `snapshot.dispatch` (`src/snapshot.zig:360-386`). On `error.RingFull` or `error.CrossTaskFull` the
   entry keeps its payload and retries the post once per loop pass, never spinning the accept path
   (`src/snapshot.zig:390-406`).
4. the successful post is the ownership transfer: the front never reads, writes, closes or polls that fd again. A
   refused post keeps the fd and the slot in the entry until it lands; a shutdown closes it before posting, so a closed
   fd is never handed over.

The target ring is `cfg.fronts + index_idx` (`roleOf`, `src/lifetime.zig:1134-1160`), which is why the hand-over needs
no `index_per_front` arithmetic.

The `PeerLink` payload is `{ fd: posix.fd_t, host_idx: u8, index_idx: u16, version: u16, source_ok: bool }`, 12 bytes,
so the union stays at 16 (`src/cross_task.zig:118`). The four-byte address does not fit; the front reduces it to
`source_ok` and logs a mismatch at the index.

`FrontMessage` (`src/index.zig:21-36`) still gains nothing. The index's `CrossTaskMessageIdx` arm
(`src/index.zig:246-258`) keeps the stream-window `resync` and then switches on the payload tag: snapshot replies to
`snap.onReply`, `PeerLink` to the link intake. A peer slot misrouted to the snapshot handler would be read as a snapshot
reply and its fd leaked.

### 4.3 Index intake and the greeting (acceptor)

The owning index re-validates `version`, `host_idx < hosts`, `host_idx != own`, `source_ok`, and that `index_idx` is its
own number (true by construction). Then:

- **No link for that host.** The link entry moves to `greeting`; the index writes one 7-byte reply
  `(its version, its host_idx, its index_idx, verdict)` and, on that send's CQE, the link becomes `up`, the reorder
  buffer starts at absolute zero, and the receive is armed.
- **A link already exists for that host.** The candidate is parked without a receive arm and the predicate decides.
- **Any check fails.** The index writes the 7-byte reply with the failing verdict and closes after its CQE;
  `version_mismatch`, `invalid_host`, `peer_address_mismatch` and `unknown_index` are the codes it can emit here.

The index is the only writer of the greeting. No frame is submitted until the greeting's send CQE lands, because a frame
submitted earlier could be transmitted first and corrupt the dialer's fixed-length read. The greeting's buffer lives in
the link entry, so the CQE never races a freed buffer; a close after a rejection is deferred to the verdict's send CQE
for the same reason.

A greeting arriving at an index that is already draining is closed at once with the shape of the client refusal
(`src/index.zig:176-188`): the index closes the fd and releases the slot. No verdict is sent; the peer sees EOF.
`not_accepting` is defined but emitted nowhere in v1 (U25), and the dialer logs that EOF as `not_accepting`.

### 4.4 The switch predicate (U9)

Unchanged from iteration 2 §4.4; the pulse it sends is now the confirmed `0x00` op answered by `0x01` (§5.7):

1. a `Slots` context holds the host, the candidate's fd, its version and `source_ok`, and a per-link `epoch: u32` bumped
   on every phase change, so a late completion is attributable and ignorable;
2. a pulse frame goes into the existing link with `cluster.pulse_timeout` around the ack;
3. on an error, a missing ack or the timeout the old link is dead: install the candidate (7-byte reply with `ok`, then
   `up`), retire the old link with a dedicated `pushClose` context, discard its reorder buffer and any partial frame,
   reset `seq_id` to zero for the new connection, and log the replacement at warn. Nothing is replayed frame by frame;
   pending requests die with the old link, the transport exposes the link generation, and re-issuing is the consensus
   layer's;
4. on a successful ack the candidate is suspicious: 7-byte reply with `host_index_squatting`, close after that CQE, log
   at warn, keep the existing link untouched.

The candidate carries no traffic before promotion, and the dialer sends nothing after its greet until it reads the
reply, so a parked candidate needs no receive arm and "discard" is a plain close. The predicate never blocks the index
loop; only the candidate's promotion waits.

### 4.5 The dialer's acceptance

Unchanged from iteration 2 §4.5. The dialer reads exactly seven bytes with a deadline and re-arms partial reads; it
validates the peer's identity against the host it dialed and its own index, validates `version`, and reads the verdict:

- `ok`: install the link, create the reorder state at absolute zero, arm the receive, log at info, and send no frames
  before the reply is fully read.
- any other code: close, log at warn, re-arm the retry timer with the backoff in force. A non-zero verdict does not
  validate the peer's identity, so the log carries the code and the configured address, not a claimed identity.
- EOF, a short read at the deadline, or an error: the same, with the cause logged.

### 4.6 Failure, death and retry

Unchanged from iteration 2 §4.6, with two additions from U19 and U18: a missed keepalive ack is a link death, and an
over-cap or `frame_len < 24` frame is a protocol error that kills the link (§5). Death tears the link down (dedicated
close context, a `reset()` of the reorder buffer, buffers returned) and, on the lower host, arms a retry timer with
exponential backoff from 100 ms to 5 s, reset on success, logged at warn, never fatal. The higher host never dials: it
closes and waits for the lower to redial (U16, no goodbye op). The keepalive is what detects a silent one-sided death on
the higher host; without it the link would stay dark until the lower host sent something.

### 4.7 Teardown (U16)

Unchanged from iteration 2 §4.7: `shutdown_soft` closes the links after the index has no sessions left, before
`reportDrained` (`src/index.zig:207`, `:213`, `:227`); `shutdown_hard` closes immediately. The final full CQ drain
releases any `PeerLink` slot that raced the shutdown and closes its fd. The front stops posting hand-overs, cancels the
peer accept arm and the in-flight handshake reads, and closes their fds; a post already submitted is consumed by the
index's final drain or by `Controller.deinit`. A draining index closes a late greeting at once (§4.3). The peer sees
EOF; the lower host redials, the higher host's predicate replaces the stale socket.

## 5. The frame

### 5.1 The wire layout

The frame's first 22 bytes are fixed, and the whole frame is at most 4096 bytes:

| `seq_id: u16` | `frame_len: u16` | `vector_clock_frame: (u8, u128)` | `op_code: u8` | `op_payload: bytes` | `commit_envelope` |
| ------------- | ---------------- | -------------------------------- | ------------- | ------------------- | ----------------- |

- all scalars are little endian and packed; the encoder appends field after field, so there is no alignment padding;
- `frame_len` is the frame's total size in bytes including the four-byte prefix (proposed; U23 confirms the accounting).
  It is back-patched at offset 2 after the body is written, because the encoder cannot know the size before it has
  written the variable tail. This is one store, not a size-computation pass;
- `op_payload` is a slice written through `blog.append`, so its own `uvarint` length precedes the bytes (`blog`
  `encoding.zig:153-239`); an empty payload is the single byte `0x00`. The length prefix stays even though `frame_len`
  exists: the envelope after the payload is variable, so its start is only known from the payload's own length;
- `commit_envelope` is U6's `(no_of_decisions: uvarint, start_state_idx: u128, decisions: bitmap)`, bit `i` LSB-first,
  `1` confirmed and `0` not; zero decisions is the single byte `0x00`;
- the minimum frame is therefore 24 bytes: 4 prefix + 17 vector clock + 1 op + 1 empty payload + 1 empty envelope. A
  received `frame_len` below 24 or above 4096 is a link failure;
- the greeting is not a frame and does not use this layout; the 7-byte reply is not a frame either.

What the transport-format document still owns: the per-op payload codecs, the chunking of a logical transfer that does
not fit 4 KiB, the payload cap for each op, and any future field (which needs a version bump, never an implicit
extension).

### 5.2 The send path

The send context owns a 4096-byte buffer (U14: its buffer waits for its CQE, the operation context lives in `Slots`).
The encoder writes `seq_id` at offset 0, leaves offsets 2..4 for the length, writes the vector clock, the op code, the
payload and the envelope from offset 4, and stores `frame_len` at offset 2 from the final tail pointer. If the tail
exceeds 4096, the encoder returns `error.FrameTooLarge` before any SQE; in the stub this is a caller bug, and the format
document will replace it with chunking. `seq_id` advances only after the SQE was submitted successfully, so a local
`error.RingFull` never leaves a hole. A link with all `inflight` buffers busy returns `error.Backpressure` to the
control plane; only a negative CQE or a protocol error fails the link.

### 5.3 The receive path

The receive path is a prefix reader plus a direct write into the reorder slot:

1. each link has a four-byte header buffer and a `filled_hdr` count. Arm `pushRecv` for `4 - filled_hdr`; add `res` on
   each completion. A partial header re-arms for the rest, and the TCP guarantee means the remainder is the next bytes
   on the stream.
2. on a full header, parse `seq_id` and `frame_len`, validate the length (U23's accounting), and lift `seq_id` to an
   absolute index (§5.5). A length outside `24..=4096` is a protocol error and kills the link; no frame is delivered and
   no bytes are skipped.
3. `reserve(abs)` the reorder slot, copy the four-byte prefix into `slot[0..4]`, and arm `pushRecv` for `frame_len - 4`
   bytes into `slot[4..frame_len]`. Every subsequent short completion continues into `slot[filled..]`; the reservation
   pins the slot, so no other frame can reuse it, and there is no assembly buffer and no extra copy of the body. When
   `filled == frame_len`, call `commit(abs, frame_len)`; reset `filled_hdr` and go to 1. The slot therefore holds the
   frame exactly as it was on the wire, and the parser never has to know that the prefix arrived first.
4. the control plane drains synchronously in the same pass: `peekHeadCond(deliver)` + `dropHead`, or
   `popHeadCond(deliver)`, then `deliver += 1`. A frame the control plane cannot dispatch is peeked and retried on the
   next pass. A reorder violation (`OutdatedFrame`, `FramesAreTooFarAway`) or an unliftable ring number is a link
   failure, never a silent drop.
5. the receive is armed only while `pushed_absolute - delivered < window`. When the window is full the link stops
   arming, TCP backpressures the peer, and no frame is dropped. `FramesAreTooFarAway` therefore means a peer that
   ignored this backpressure (or a corrupted stream), not a slow local consumer.

A frame is delivered only when its body is complete; a partial frame at the head of the reorder buffer is not
deliverable, and the delivery cursor never sees it. On a link death or a connection replacement, `reset()` returns the
buffer to absolute zero with no reservations and no partial frame, and `filled_hdr` returns to zero.

The greeting's 5-byte and 7-byte reads are separate from this path: they are exact-length one-shot receives into the
handshake/link buffers, not frames.

### 5.4 The local reorder buffer (U18, U24)

`src/reorder_buffer.zig` is a copy of `zigring.ReorderBuffer` (`zigring` `iouring.zig:2229-2492`) with the fixed-item
`push` replaced by a reserve/commit API. What is preserved exactly:

- `init(allocator, size, max_item)` requires `size` a power of two no larger than `0xFFFF` and allocates `2 * size`
  slots of `max_item` bytes plus the two link arrays;
- an absolute `u64` `wave` starting at zero, `idx < wave` rejected as `OutdatedFrame`, `idx - wave >= size` rejected as
  `FramesAreTooFarAway`, and the wave advances across every consecutive committed item;
- delivery is the caller's cursor (`popHeadCond`, or `peekHeadCond` + `dropHead`); `wave` is not a delivery cursor and
  is never passed to `popHeadCond`.

What changes:

- `reserve(idx: u64) ![]u8` returns the slot's `max_item`-byte view without linking it or advancing the wave, and pins
  the slot until `commit`, `abandon` or `reset`; it applies the same two index checks;
- `commit(idx: u64, len: usize)` links the reserved slot, records `len` (a per-slot `u16`, the frame cap fits) and
  advances the wave;
- `abandon(idx: u64)` frees a reservation whose frame never completed; `reset()` clears the wave, the list, the lengths
  and every reservation in one pass;
- `peekHeadCond`/`popHeadCond` return the committed length, not `max_item`;
- `push(idx, data)` is kept as reserve + memcpy + commit so the original zigring tests port over verbatim and prove the
  copy is not a regression. The new tests feed one frame in three pieces and assert one delivered item, and feed a full
  frame through `push` as well.

The receive path reserves once per frame at the header; the reservation is what makes the direct write safe.

### 5.5 Sequence numbers, the window and the lift

Unchanged from iteration 2 §5.2 with the length prefix added:

- the sender keeps a `u64` counter per direction per connection, starting at zero, truncates it into the `u16` `seq_id`,
  and increments only after a successful SQE submit;
- the receiver keeps an absolute `u64` cursor `wave` and lifts `seq_id` to the unique absolute index in
  `[wave, wave + 0x10000)` congruent to the ring number. Since the window is a power of two no larger than `0xFFFF`, the
  lift is unambiguous at every wrap; an absolute at or beyond `wave + window` is rejected by `reserve`
  (`FramesAreTooFarAway`) and one below `wave` is `OutdatedFrame`;
- the window is `cluster.reorder_window`, default 16. It bounds both the reorder gap and, by gating the receive arm, the
  undelivered backlog; 16 leaves headroom over the per-link send budget of 8;
- the buffer is reset on a connection replacement: absolute zero, empty, no partial frame, no staged frame.

### 5.6 The encoder (U13)

Unchanged: all fixed-width fields little endian and packed, `blog.append` for scalars and slices, `blog.appendVarint`
for ULEB128, no checksum (TCP covers integrity), the version only in the greeting. Three consequences remain:

- **A `u128` is two `u64` appends.** `blog.append` asserts at most 64 bits and `appendVarint` narrows to `u64`;
  appending the low half and then the high half is exactly the 16-byte little-endian form;
- **The bitmap is raw.** `blog.append` on a slice prefixes a length; `decisions` already carries its length in
  `no_of_decisions`, so it is a raw copy;
- **An empty envelope is one zero byte.** `no_of_decisions == 0` writes exactly `0x00` and nothing after it. There is no
  padding now, so there is nothing to distinguish a zero byte from a padding byte.

An unknown or out-of-range `op_code` closes the link rather than being skipped: a frame we cannot interpret means the
peer speaks another version.

### 5.7 Op codes, verdicts, pulse and keepalive

The ranges are U13's, with the subranges U21 confirmed:

| range        | use                                                              |
| ------------ | ---------------------------------------------------------------- |
| `0x00..0x0F` | link liveness: `0x00` `pulse`, `0x01` `pulse_ack`, rest reserved |
| `0x10..0x1F` | catch-up and snapshot family                                     |
| `0x20..0x7F` | consensus (the consensus document owns the meaning of each op)   |
| `0x80..0xFF` | unused; an op here closes the link                               |

A pulse is a normal frame with the empty payload (`0x00`) and the empty envelope (`0x00`), handled on the transport path
and answered with `pulse_ack` without consensus ordering. Because the ack is a normal frame, it proves the old link's
reorder stream is advancing: a link blocked on a hole fails the probe by design, which is the outcome U9 wants. The
predicate's probe and the periodic keepalive share the opcode and differ only in which timer is armed.

The verdict is two bytes, the tail of the 7-byte reply:

| code | name                    | emitted by (U25)                                       |
| ---- | ----------------------- | ------------------------------------------------------ |
| 0    | `ok`                    | the owning index on acceptance                         |
| 1    | `host_index_squatting`  | the index when the pulse of the existing link succeeds |
| 2    | `internal_error`        | the index on a local failure it cannot recover         |
| 3    | `version_mismatch`      | the front (unroutable) and the index (defensive)       |
| 4    | `unknown_index`         | the front when `index_idx >= cfg.indexes`              |
| 5    | `not_accepting`         | defined; not emitted in v1 (a drain closes silently)   |
| 6    | `peer_address_mismatch` | the index when `source_ok` is false                    |
| 7    | `invalid_host`          | the front for `host_idx >= hosts` or `host_idx == own` |
| 8..  | reserved                |                                                        |

None of these is fatal to the process: the accepter logs at warn and closes, the dialer logs at warn and keeps retrying
with U10's backoff. A front-side reject is the same shape: warn, close, let the dialer's backoff run.

The keepalive is armed on every established link by both sides at `cluster.keepalive_interval` (5 s). A missed ack, a
send error, or a timeout kills that link: the lower host redials with backoff, the higher host closes and waits. This is
the only detection of a one-sided silent death, since there is no goodbye op.

## 6. Implementation surface

`src/reorder_buffer.zig` (new): U18's copy, the reserve/commit/abandon/reset API, the per-slot length, the ported
zigring tests and the partial-delivery test. No `zigring` import; the file owns the algorithm from here on.

`src/cluster_transport.zig` (new): the 5-byte greet codec and the 7-byte reply codec, the verdict map, the 4096 cap and
the length validation, the frame encoder and its back-patch, the header reader and the direct-into-slot receive, the
absolute lift, the link FSM and its epoch, the predicate and its pulse, the liveness/op-code map, the version constant
and the timeout defaults. Consensus is written over it later; it owns no consensus decision.

`src/lifetime.zig`: the per-index link tables (`indexes × hosts` entries, the own slot unused), each link's reorder
buffers and send ring, the lifetime tied to `Controller.init`/`deinit`; `createPeerServerSocket` beside
`createServerSocket` (`src/lifetime.zig:1191-1219`), binding `bind:cluster.peer_port` and existing only when
`hosts > 1`; the parsed peer addresses (`[hosts][4]u8`) derived once from `cluster.peers`; the `cluster` block in
`Config` and its validation; the `cross_task_slots` minimum if U26 keeps the shared pool. Link storage is allocated
lazily on promotion, because the controller allocator is already used from index threads (`src/index.zig:92`).

`src/config.zig`:
`pub const Cluster = struct { peer_port: u16, peers: []const []const u8, reorder_window: u16 = 16, inflight_frames: u16 = 8, handshake_slots: u16 = 64, handshake_timeout: Seconds = seconds(5), pulse_timeout: Seconds = seconds(1), keepalive_interval: Seconds = seconds(5) }`
and `cluster: ?Cluster = null`, with `ParseError` additions and validation: `peer_port > 0`, `peer_port != port`,
`peers.len == wal.hosts()`, `peers[host_index]` empty, every other entry non-empty and a parseable IPv4 address (or
`localhost`), no duplicates, `reorder_window` a power of two in `2..=0xFFFF`, `1 <= inflight_frames <= reorder_window`,
`handshake_slots >= 1`, `cluster == null` iff `hosts == 1`. The canonical document keeps `hosts = 1`, so its rendered
form does not grow a `cluster` block. The 4096 frame cap is not config.

## Open questions

- **U23 (blocking).** U18 fixes the 4 KiB cap and puts a two-byte little-endian frame length right after `seq_id`, but
  not what it counts. Proposed: `frame_len` is the frame's total size in bytes including the four-byte prefix, so the
  receiver reads exactly `frame_len - 4` bytes after the prefix and the cap is one `frame_len <= 4096` check; the
  minimum valid value is 24 (§5.1) and anything below it is a link failure. The alternative is that the field counts
  only the bytes after itself (`4 + frame_len <= 4096`, remaining `frame_len - 2`). Confirm the accounting and that the
  4096 cap is the wire size of the whole frame, not just its payload.
- **U24.** U18 instructs a copy of `zigring.ReorderBuffer` because partial deliveries need an API that the fixed-item
  `push` does not have. Proposed shape (§5.4): keep `init(size, max_item)`, the absolute wave, the two push errors and
  the `2 * size` slots; add `reserve(idx) ![]u8` (pins the slot, links nothing), `commit(idx, len)` (links, records the
  length in a per-slot `u16`, advances the wave), `abandon(idx)`, `reset()`, and deliver the committed length instead of
  `max_item`; keep `push` as reserve + memcpy + commit so the zigring tests port verbatim. Confirm the shape, and
  confirm `cluster.reorder_window = 16` at 4 KiB slots, which costs 128 KiB of receive buffer per direction (320 KiB per
  link with the 8 × 4 KiB send ring), or name a smaller default.
- **U25.** U21 adds `invalid_host` without saying who emits it. Proposed: code 7, emitted by the front for
  `host_idx >= hosts` and `host_idx == cfg.host_index`, since neither can name a target index; the index keeps both
  checks defensively and keeps `peer_address_mismatch` for `source_ok == false`, following U21's division that the front
  rejects only what it cannot route. `not_accepting` (code 5) is defined but emitted nowhere in v1: a draining index
  closes at once and the dialer logs that EOF as `not_accepting`. Confirm the code, the emitter, and that a front-side
  reject stays a warn plus a close, never a process failure.
- **U26.** U20's pad says "Confirmed", but its one sub-question, how the shared `cross_task_slots` pool accommodates 64
  pending hand-overs per front, is unanswered. Proposed: keep the one shared pool and the payload-tag switch, and add a
  parse-time validation `cross_task_slots >= fronts * cluster.handshake_slots` when `hosts > 1` (defaults: 4096 >= 2 ×
  64); a front that still fails to acquire retries the post once per pass, so a full pool delays a hand-over but never
  fails it. The alternative is a dedicated `SlotPool` sized `fronts * handshake_slots` plus a new reserved
  `PeerLinkMessageIdx` (`maxInt - 12`), isolating hand-overs from the other cross-thread traffic at the cost of a second
  pool and a second task index. Confirm the shared-pool minimum, or the dedicated pool.
