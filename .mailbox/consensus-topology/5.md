## 3. The implementation plan

### 3.0 How to work these steps (read once, obey always)

1. **No new APIs, no new names, no new files beyond the ones named.** The only new files are `src/reorder_buffer.zig`
   and `src/cluster_transport.zig`. `src/messages.zig` is not touched (U26): the shared `cross_task_slots` pool and the
   payload tag are the whole dispatch mechanism. Where a step names a variant or a constant, that name is fixed.
2. **Verify every symbol before use.** Grep (`rg -n`) for each name a step mentions. Line references are to the tree as
   of writing (zigring 0.0.15, Zig 0.17.1 std) and may drift; re-locate them by symbol name before use. If a referenced
   symbol does not exist as described, re-read the surrounding code and the design section it cites; never guess a
   signature.
3. **One step = one commit-sized change.** After each step: `zig build` clean, `zig build test` green. `build.zig` walks
   `src/*.zig` and wires every file into the `check` and `test` steps, so the new files' tests run with no build edits.
   Never start the next step with a red tree.
4. **The design doc's pinned rules are non-negotiable.** The handshake order (§3), the frame layout and the 24..=4096
   bounds (§4.1), reject-and-close-never-fail (§4.7), the reserve/commit receive path (§4.3), the backoff bounds (§3.6).
   If an implementation choice seems needed, the design already made it; search it again before deciding.
5. **No TODOs, no stubs left behind.** A step's tests are part of the step, not follow-ups.
6. Where a step says "pin", that value is final: the 4096 cap, the 24 minimum, window 16, inflight 8,
   `handshake_timeout` 5 s, `pulse_timeout` 1 s, `keepalive_interval` 5 s, backoff 100 ms..5 s, verdict codes 0..=7, op
   codes `0x00` pulse / `0x01` `pulse_ack`.

**Standing rules for the whole plan:**

- A front-side reject is a warn and a close; it is never a process failure (§4.7). Same for the index's verdicts and the
  dialer's rejections.
- fds cross threads exactly once. After a successful hand-over post the front never reads, writes, closes or polls that
  fd again; whoever closes one clears the field (`-1`), the snapshot precedent.
- Every kernel write targets a buffer that waits for its CQE: the handshake entry owns its five-byte request and
  seven-byte reply buffers, the link entry owns its greeting and frame buffers. No buffer returns to a pool before its
  completion (the logging audit's lesson). The same holds for timespecs: a spec the kernel reads asynchronously outlives
  its arming and lives in the owner's stable storage (`RingStuff.tick_spec`, `Controller.init_deadline_spec`,
  `src/lifetime.zig:125-126`), never on the arming pass's stack.
- A refused cross-task post keeps its payload in the owner's entry and retries once per loop pass; it never spins the
  loop and never stacks a second post. This is the `snapshot.dispatch` retry shape (`src/snapshot.zig:390-406`).
- Index pushes never spin; front and main pushes spin-retry on `error.RingFull` (the `reportDone` idiom). Existing house
  rule, unchanged.
- A link's `epoch: u32` bumps on every phase change, and every TaskCtx a link arms carries it; a late completion with a
  stale epoch is logged at debug and ignored, never misattributed (§3.4).
- Slot payloads and TaskCtx variants are plain data: a pointer or an index into stable storage, never an inline buffer
  (`src/slots.zig:42-83` keeps its shape).

### 3.1 Shared vocabulary (fixed for the whole plan)

**`src/cluster_transport.zig` (new).** `VERSION: u16 = 1`, bumped on any incompatible change. `GREET_LEN = 5`,
`REPLY_LEN = 7`, `FRAME_MIN = 24`, `FRAME_CAP = 4096`. `Verdict = enum(u8)` with the §4.7 table verbatim (`ok=0`,
`host_index_squatting=1`, `internal_error=2`, `version_mismatch=3`, `unknown_index=4`, `not_accepting=5`,
`peer_address_mismatch=6`, `invalid_host=7`). Op constants `OP_PULSE = 0x00`, `OP_PULSE_ACK = 0x01`. Backoff bounds as
link constants: `RETRY_MIN = 100 ms`, `RETRY_MAX = 5 s`, exponential, reset on success. Codecs: `encodeGreet` /
`decodeGreet` over the packed `{ version: u16, host_idx: u8, index_idx: u16 }`; `encodeReply` / `decodeReply` over
`{ version: u16, host_idx: u8, index_idx: u16, verdict: Verdict }` (seven bytes; the front's rejects carry `0xFFFF` as
`index_idx`). The frame encoder appends through `blog.append` / `blog.appendVarint` exactly per §4.1/§4.6 (a `u128` as
two `u64` appends, the decisions bitmap as a raw copy, an empty envelope as `0x00`), back-patches `frame_len` at offset
2, and returns `error.FrameTooLarge` past 4096 before any SQE. The lift:
`lift(wave: u64, seq_id: u16, window: u16) ?u64`, the unique absolute in `[wave, wave + 0x10000)` congruent to `seq_id`,
rejected by the reorder checks that follow. The link FSM lives here:
`LinkState = enum(u8) { none, greeting, parked, up }`, the epoch, and the per-link invariants (one open reservation, one
pending post, `pushed_absolute`, `delivered`, the ack flag).

**`src/reorder_buffer.zig` (new).** The copy of `zigring.ReorderBuffer` (zigring `src/iouring.zig:2229-2492`) with the
§4.4 API: `init(allocator, size, max_item)` unchanged in its requirements (`size` a power of two ≤ `0xFFFF`, `2 * size`
slots of `max_item` bytes, the same init error set), `reserve(idx: u64) ![]u8`, `commit(idx: u64, len: usize)`,
`abandon(idx: u64)`, `reset()`, `push(idx, data)` kept as the reserve + memcpy + commit shim, and `peekHeadCond` /
`popHeadCond` returning the committed length. No zigring import; the file owns the algorithm.

**`src/config.zig`.** The `Cluster` struct exactly as §6, `cluster: ?Cluster = null` on `Config`, the `ParseError`
additions, and the §6 validation list, including the parse-time `cross_task_slots >= fronts * cluster.handshake_slots`
when `hosts > 1` and `cluster == null iff hosts == 1`. The canonical config does not grow a cluster block.

**`src/cross_task.zig`.** Two variants:
`PeerLink: struct { fd: posix.fd_t, host_idx: u8, index_idx: u16, version: u16, source_ok: bool }` (12 bytes) and
`PeerServerSocket: struct { fd: posix.fd_t }`. The comptime plain-data and `@sizeOf(CrossTask) <= 16` asserts
(`src/cross_task.zig:107-120`) keep holding; the round-trip test grows both.

**`src/slots.zig`.** TaskCtx variants, each plain data, each a pointer or index into stable storage:
`peer_accept { generation }` (the front's second multishot), `greet_read { entry }` and `greet_deadline { entry }` (the
front's handshake), `reply_send { entry }` (a front reject; close after its CQE), `connect { host_idx }`,
`greet_send { host_idx }`, `verdict_read { host_idx }` and `reply_deadline { host_idx }` (the dialer),
`greeting_send { host_idx }` (the acceptor's 7-byte reply), `frame_send { host_idx }`, `frame_recv { host_idx }`,
`peer_close { host_idx, epoch }` (a dedicated close), `pulse { host_idx, epoch }`,
`predicate_timeout { host_idx, epoch }`, `keepalive_tick { host_idx, epoch }`, `retry_timer { host_idx }`.

**`src/lifetime.zig`.** `createPeerServerSocket` beside `createServerSocket` (`src/lifetime.zig:1191-1217`), binding
`bind:cluster.peer_port`, existing only when `hosts > 1`, sharing the listener lifetime of the client socket. The parsed
peer addresses, derived once at init: `[hosts][4]u8`, `localhost` folded to loopback exactly as `createServerSocket`
does. Per-index link tables: `indexes x hosts` entries, the own slot unused, one `LinkEntry` each (the FSM, the fd, the
`ReorderBuffer`, the send buffers, the counters), allocated lazily on the first promotion through the controller
allocator (`src/index.zig:92` precedent) and freed in `deinit` only if allocated.

**`src/front.zig`.** A `PeerHandshake` entry: the fd, the filled count, the five-byte greet buffer, the seven-byte reply
buffer, `source_ok`, the read and deadline slots, the pending post, a small state (`reading`, `replying`, `posting`,
`done`). The per-front table holds `cluster.handshake_slots` entries; an accept that finds none closes the fd with a
warn, the client inbox-full shape (`src/front.zig:251-266`). New Ctx fields: the peer listener fd, its accept slot, and
the table; `listening` and `accept_task_idx` stay single-purpose for the client arm (the R7 lesson), the peer arm gets
its own pair.

### 3.2 Stages and steps

Each stage lands green. Steps inside a stage are ordered; stages are ordered by dependency.

**§A The two new files, pure and testable.** No wiring, no behavior change yet.

- **A1. `src/reorder_buffer.zig`.** Copy `zigring.ReorderBuffer`; add `reserve`/`commit`/`abandon`/`reset` and the
  per-slot `u16` committed length; keep `push` as the shim. Port zigring's own reorder test verbatim through the shim
  (the copy is proven not a regression), then add: the three-piece test (a frame delivered through `reserve` + two
  partial body commits delivers exactly once, and `peekHeadCond` returns `frame_len`, not `max_item`); `OutdatedFrame`
  below the wave; `FramesAreTooFarAway` at `wave + size`; `abandon` frees the slot for reuse; `reset()` clears the wave,
  the lengths and every reservation.
- **A2. `src/cluster_transport.zig` codecs.** Constants, greet and reply codecs, the verdict and op maps, the length
  check as one comparison, the encoder with the back-patch, the lift. Tests, all pinned by §8: the codec test feeds
  frames at absolute 0, 2 and 1 through a `ReorderBuffer` and asserts delivery 0, 1, 2; the length test, 23 and 4097
  rejected, 24 and 4096 valid; the back-patch equals the validated length on every encode; a `u128` appends as the
  two-`u64` little-endian form; the bitmap is a raw copy (no varint prefix — `blog.append` prefixes slices and fixed
  arrays alike, so the envelope's bitmap is a `@memcpy`); an empty envelope is the single byte `0x00`; greet and reply
  round-trip; a reply with `index_idx = 0xFFFF` decodes as the front sentinel.

**§B Configuration.**

- **B1. `src/config.zig`.** The `Cluster` struct, the optional field, the parse (siggy's `x = { }` renders an absent
  optional as null; the block is absent when `hosts == 1`), the `ParseError` additions, and the §6 validation inside the
  existing single `validate` path (`src/config.zig:634-642` precedent): `peer_port > 0` and `!= port`;
  `peers.len == wal.hosts()`; the own slot empty; every other entry non-empty, a parseable IPv4 or `localhost`, no
  duplicates; `reorder_window` a power of two in `2..=0xFFFF`; `1 <= inflight_frames <= reorder_window`;
  `handshake_slots >= 1`; the cross-task pool minimum; `cluster == null iff hosts == 1`. Tests: one accept case (the §6
  three-host example) and one rejection per rule.

**§C Cross-task vocabulary.**

- **C1. `src/cross_task.zig`.** `PeerLink` and `PeerServerSocket`; the comptime asserts hold; the round-trip test grows
  both, and the 16-byte proof stays a comptime assertion (§8). `src/messages.zig` is not touched.

**§D Process resources.**

- **D1. `src/lifetime.zig`.** The parsed peer addresses at init; `createPeerServerSocket` (bind + listen through the
  same shapes as `createServerSocket`); the per-index link table storage and its lazy allocation; `deinit` frees what
  was allocated, after the threads have joined, before the rings go (the R1 ordering).
- **D2. `src/main.zig` and the front's receive arm.** The process thread creates the peer listener beside the client one
  (only `hosts > 1`), posts one `PeerServerSocket` slot per front with `taskIdx = messages.CrossTaskMessageIdx` and
  `res = slot_idx` through the `snapshot.dispatch` shape, **before** `broadcastStartWork` (`src/main.zig:301-312`):
  same-source-ring ordering is the guarantee the design cites. The front's `CrossTaskMessageIdx` arm (add the
  payload-tag switch if the arm is new; keep it if it exists) stores the fd. The START_WORK arm arms both accepts: the
  client fd from `res`, the peer fd from the stored slot; if `hosts == 1` no post ever arrives and no peer arm is taken.
  The process exit path closes the peer listener after the fronts have stopped. Tests: slot round-trip (C1), listener
  create/close as a lifetime test; the arrival ordering is asserted by the §K harness.

**§E Front intake (§3.2).**

- **E1. The arm.** The front's second multishot accept on the shared peer listener, its own Ctx fields and its own
  `peer_accept` slot; the handshake table; the empty-table close path (warn + close, the `src/front.zig:251-266` shape).
- **E2. The greet read and the rejects.** On an accept CQE the entry takes the fd and arms a one-shot `pushRecv`
  (`zigring` `iouring.zig:821`) for `5 - filled` bytes plus a one-shot deadline (U28 names the mechanism); partial reads
  re-arm for the remainder; EOF, deadline or error closes the fd and releases the entry. On five bytes the ordered
  checks run exactly as §3.2: `version` first, then `invalid_host` (`host_idx >= hosts` or own), then `unknown_index`,
  then `std.posix.getpeername` and `source_ok` against the parsed `peers[host_idx]`. A reject writes its 7-byte reply
  from the entry's buffer and closes after that send's CQE; the reply and the close both carry `reply_send` / `close`
  slots. Tests: greet decode and reply encode are unit-tested through the A2 codecs; the state machine (E1-E4) is
  exercised by §K.
- **E3. The hand-over.** Acquire a `cross_task_slots` slot, write `PeerLink`, post `MSG_RING` with
  `taskIdx = messages.CrossTaskMessageIdx`, `res = slot_idx` to `ctrl.rings[cfg.fronts + index_idx].ring.fd` (`roleOf`,
  `src/lifetime.zig:1129-1166`); the `resync` of the stream window first, the `snapshot.dispatch` retry on `RingFull` /
  `CrossTaskFull` with one pending post per entry. The successful post is the ownership transfer (standing rule).
- **E4. Front shutdown.** Stop posting; cancel the peer accept arm and the in-flight handshake reads and deadlines;
  close their fds; release the pool slots. Match completions by task_idx alone and keep the draining-close branch (the
  R3 shape).

**§F The index acceptor (§3.3, §4.3, §4.2).**

- **F1. The tag switch and the greeting.** The `CrossTaskMessageIdx` arm keeps its `resync` (`src/index.zig:246-258`)
  and switches on the payload tag: the snapshot replies go where they go today, `PeerLink` goes to the link intake. The
  intake re-validates (`version`, `host_idx < hosts`, not own, `source_ok`, the index number is its own), checks the
  link table, and answers: no link, the entry moves to `greeting`, one 7-byte reply from the link entry's buffer, and on
  that `greeting_send` CQE the link is `up`, the reorder buffer starts at absolute zero, the first receive is armed; a
  duplicate, §H decides; any failure, the reply with the failing verdict and a close after its CQE. A greeting at a
  draining index closes at once, no verdict (`src/index.zig:203-227` shape); the dialer logs that EOF as
  `not_accepting`.
- **F2. The receive path.** Per §4.3, exactly: the four-byte header buffer and `filled_hdr`; `lift` and the
  one-comparison length check (`24 <= frame_len <= 4096`, outside is a link death, no bytes skipped); `reserve(abs)`,
  the prefix copied to `slot[0..4]`, `pushRecv` for `frame_len - 4` into `slot[4..frame_len]`, short completions
  continuing at `slot[filled..]`, `commit(abs, frame_len)` when full, at most one open reservation per link; the
  synchronous drain (`popHeadCond` with the dispatcher as the condition, or `peekHeadCond` + `dropHead`, then
  `delivered += 1`), a frame the dispatcher cannot hold is peeked and retried next pass; the arm is gated by
  `pushed_absolute - delivered < window`; `OutdatedFrame`, `FramesAreTooFarAway`, an unliftable ring number and an
  unknown op code are link deaths. `pulse` answers `pulse_ack` on the transport path; `pulse_ack` sets the link's ack
  flag (§I); both timers may be outstanding at once, and any ack satisfies every outstanding probe (iteration 4's pinned
  reading, as a test assertion in §K).
- **F3. The send path.** Per link: a fixed array of `inflight_frames` 4096-byte buffers in the link entry (not
  `blog.BufferPool`, §4.2), a busy mask, `seq_abs: u64` advanced only after a successful submit, the back-patched
  encoder, `error.Backpressure` when all buffers are busy. The send context waits for its CQE (standing rule).

**§G The index dialer (§3.1, §3.5, §3.6).**

- **G1. Dial and greet.** The first dial is issued once the index has finished recovery and before the service loop:
  after `snapshot.armTicker` (`src/index.zig:143`), before the `while (true)` at `:145`, for every host > own:
  `pushConnectIp4` (`zigring` `iouring.zig:1174`) on the index's own ring with a `connect` slot, the configured
  `peers[host]` address. On the connect CQE, the 5-byte greet from the link entry's buffer; nothing else until the
  reply. The reply: a one-shot `pushRecv` for exactly seven bytes with re-arm and a deadline (U28); only an `ok` verdict
  is validated (`version == local`, `host_idx == the host dialed`, `index_idx == its own`; the `0xFFFF` sentinel is
  never validated as an identity, iteration 4's pinned reading, as a test assertion), then the link is installed, the
  reorder state created at absolute zero, the receive armed, an info log. Any other code, EOF, a short read at the
  deadline or an error: warn, close, arm the retry.
- **G2. Retry.** The backoff as a one-shot re-armed timer (`retry_timer` slot), `RETRY_MIN` doubling to `RETRY_MAX`,
  reset on success, never fatal, logged at warn. The higher host never dials; its side waits (§3.6).

**§H Duplicate links: the predicate (§3.4).**

- **H1.** The candidate parks without a receive arm. The existing link's entry bumps its epoch; a `pulse` frame goes out
  through the send path with a `predicate_timeout` one-shot carrying `{ host_idx, epoch }` at `cluster.pulse_timeout`.
  On an error, a missing ack or the timeout: the old link is dead, the candidate is installed (the 7-byte `ok` reply,
  then `up`), the old fd retired with a dedicated `peer_close`, the reorder buffer `reset()`, `seq_abs` to zero, the
  replacement logged at warn, nothing replayed. On an ack: the `host_index_squatting` reply, a close after its CQE, the
  existing link untouched. A stale timeout and a pulse completion after the timeout are both ignored by epoch. The
  predicate never blocks the index loop; the existing link keeps serving.

**§I Liveness (§4.8).**

- **I1.** `pulse` and `pulse_ack` as F2 handles them; the keepalive as a repeating per-link ticker (`keepalive_tick`
  slot) armed on `up` by both sides at `cluster.keepalive_interval`: on each tick, if the ack flag is set, clear it and
  send a pulse; if not, the link is dead, §3.6's teardown runs. A send error or a timeout kills the link the same way.
  On a link death the ticker is canceled (the `beginShutdown` cancel idiom, `src/front.zig:187-224`).

**§J Teardown (§3.7).**

- **J1. Index.** Every drain path (`src/index.zig:203-227`, the three `reportDrained` callers) closes the links first:
  `shutdown_soft` keeps them until the sessions are gone then closes each with `pushClose`; `shutdown_hard` closes
  immediately; before reporting, one final full CQ drain releases any `PeerLink` slot that raced the shutdown and closes
  its fd.
- **J2. Front.** E4's path stands; a post already submitted is consumed by the index's final drain or, in the last race,
  by `Controller.deinit`, which frees the pool after every thread has stopped (the R1 ordering).

**§K End-to-end (§8) and the landed record.**

- **K1. The harness.** Two independent `Controller`s in one process, `host_index` 0 and 1, one-core masks, four distinct
  loopback ports (client and peer per controller), `peers` empty at the own slot, one index thread each, `hosts = 2`.
  The harness waits on the in-process link tables (both sides to `up`) with a generous deadline; the dial lands inside
  the backoff bounds.
- **K2. The scenarios, each a test: greeting and link-up both sides; a pulse round-trip with the keepalive at a tiny
  configured interval; the squat, a second greet injected from a raw test socket while the link is up, answered
  `host_index_squatting` with the existing link untouched; the replacement, the same injection after the test shuts the
  live socket down from the dialer's side, so the probe times out, the candidate is promoted, the test's raw socket
  reads `ok`, and the entry's epoch and zeroed sequence are asserted; the silent death, the keepalive misses, the higher
  host closes and waits, the lower redials and the link re-establishes at absolute zero; soft teardown with links up
  closes them before the drain report; hard teardown closes immediately; both exit clean.**
- **K3. The landed record.** After §A-§K land: record the as-built anchors into the promoted document (each design
  section gains its landed file:line references), the shape `wal-steps` §Z set. This is the table the consensus document
  cites.

## 4. Two pins the plan had to make

1. **The document's shape (U27).** The re-compilation restructures the promoted document in place: §1-§6 and §9 stay as
   the normative authority, and the plan of section 3 replaces §7-§8. The alternative, the repo's `wal`/`snapshots`
   precedent, is a split: the design stays as it is and the steps live in a companion
   (`docs/CONSENSUS-TOPOLOGY-AND-TRANSPORT-steps.md`). Proposed: the in-place restructure, because the critical item
   names the document itself, and one artifact keeps the authority and the plan from drifting apart. Confirm or
   override.
2. **The timer mechanisms (U28).** The design pins deadlines and intervals but not the io_uring mechanism. Proposed,
   from the repo's own precedents: one-shot deadlines (the front's greet-read deadline, the dialer's reply deadline, the
   predicate's `pulse_timeout`) are a one-shot `pushTicker` (ticks = 1) with a TaskCtx slot, canceled through
   `pushCancel` when the guarded op completes first, the `beginShutdown` cancel idiom (`src/front.zig:187-224`);
   repeating timers (the keepalive) are `pushTicker` at ticks = 0, the `snapshot.armTicker` precedent
   (`src/index.zig:143`); the dial retry re-arms a one-shot ticker with the current backoff. Linked timeouts
   (`pushTimeoutForOp`) are rejected: nothing in the tree uses them, the zigring SDK constrains them to a shared batch,
   and `pushTimeout` with a zero length is rejected by this kernel (`src/main.zig:261-262` names the trap). Confirm or
   override.

Both are non-blocking for the plan's content; they block only its compilation into the document.
