## 2. What the pad changes in the plan

Nothing structural. The four answers close the last conditional points, with these consequences:

1. The codec's length check is one comparison, `24 <= frame_len <= 4096`, and the encoder back-patches the same number
   it validates; there is no "payload only" alternative left to guard against.
2. The reorder copy's API is fixed before it is written, so the parity tests can be written against the final shape:
   `reserve` + `commit` for the receive path, `push` as the compatibility shim, `reset` for a connection replacement.
3. `src/messages.zig` leaves the implementation surface. The cross-task slot payload tag is the only dispatch key the
   index needs.
4. The pad adds exactly one validation rule, the cross-task pool minimum; the rest of the cluster validation was already
   pinned. The frame cap is a codec constant and appears in no config struct.
5. The length test is pinned: 23 and 4097 are link failures, 24 and 4096 are valid.

## 3. Two readings pinned while compiling

Neither is a new question; both follow from confirmed text, and both are stated in the promoted document so an
implementer does not have to guess.

1. **The dialer reads the verdict before it validates the peer's identity.** A front-side reject carries `0xFFFF` in
   `index_idx` because the front has no target index, yet iteration 3's confirmed §4.5 says a non-zero verdict does not
   validate the peer's identity. The two facts together mean identity and version are the conditions for accepting `ok`,
   not preconditions for reading the seven bytes. The dialer reads the reply, and only an `ok` verdict is subject to
   `version == local`, `host_idx == the host dialed` and `index_idx == its own`.
2. **A `pulse_ack` is not correlated with a specific pulse.** Acknowledgements carry an empty payload, and none is
   needed: an ack can be delivered only after our receive stream from that peer has advanced past any hole, which is
   exactly the property the probe tests. Any ack that arrives while a probe is outstanding satisfies every outstanding
   probe, whether the predicate's timer or the periodic keepalive armed it. Both timers may be outstanding at once.

If either reading is wrong, the next letter overrides it; the thread itself is closed.
