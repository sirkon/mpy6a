## 1. The critical item, restated

> We missed a part where the state of index (just index) is cloned to be make a snapshot for it.
> There should be an a method to clone. Arena-driven: once it done cloned copy and snapshot
> buffers are cleaned.

## 2. The answer

The clone method was already on the iteration 2 surface — `cloneIndexState`, a `lifetime.Controller`
method per U1 — but the letter never stated the discipline around it: **which** state is cloned, **who**
owns the arena, and **when** the cleanup happens. That discipline is now normative:

- **Scope: the own data set, just index.** The snapshot procedure clones the index thread's **own**
  `IndexState` — the data set at `cfg.host_index`. The mirror data sets are never cloned by this
  path: their snapshots are their own hosts' procedures, over their own hosts' WAL pairs.
- **`cloneIndexState` deep-copies everything into the arena.** Every active `Session` (the struct
  itself, the session-owned compensator name bytes, the `Buffer` backing of `data.data`) and every
  blob held by the replay queue is copied into arena memory. The returned `IndexState` is fully
  self-contained: it shares no allocation, no backing, no name byte with the live state.
- **The snapshot buffer rides the same arena.** `dumpIndexState` keeps its shape; the elephant
  constructs the `std.ArrayList(u8)` with the arena's allocator, so the dump bytes and the clone
  have exactly one owner between them.
- **One cleanup point.** After the elephant has written the snapshot file and fdatasynced it (the
  wal-design §12 procedure), a single `arena.reset(.free_all)` — or `arena.deinit()`, the order's
  last act — releases the cloned copy and the snapshot buffer together. Nothing on this path is
  freed field by field; the arena is the whole ownership story, exactly as the pad demands.
- **The dump is of the clone, never the live state.** The clone is taken on the owning index thread
  inside the snapshot order, so it is a consistent point-in-time copy by construction (G1: one
  thread owns the state; no locks, no atomics). The elephant dumps the clone synchronously, per
  the wal-design §12 sketch; the live data set keeps serving the loop meanwhile.
