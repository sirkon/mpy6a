## 1. The source design, restated in English

### 1.1 What an index is

An index is an execution flow (code plus metadata) **and** data. The data is itself split by origin host. With
replication factor 2, on the host owning index 1, inside index number 4:

| Index-4 data of host 0 | Own index-4 data (host 1) | Index-4 data of host 2 |
| ---------------------- | ------------------------- | ---------------------- |

The execution flow for `(host_idx = 0, index_idx = 4)` differs on host 0 and on host 1: on host 0 it reacts to client
requests and to internal computed states ("send session X to replay in T seconds", "start the replay/compensation of the
first session of the replay queue"); on host 1 it processes the operations arriving over host 0's connection, filtering
them through the consensus logic and applying them. How many such data sets one index thread holds, as a function of the
replication config, is pinned as **U10**; the epoch and isolation machinery layered on top of the data sets belongs to
`consensus-driver` and is out of scope here.

### 1.2 `IndexState`

Each index contains active sessions (currently being worked on) and sessions awaiting replay, the latter ordered
lexicographically by the tuple `(retry_time: u64, session_id: u128)` — 20 bytes: 8 of retry time, 16 of session id:

```zig
const IndexState = struct {
    /// Kept separately, says the source, because the verztable HashMap gives no count.
    sessions_count: u64,
    sessions: verztable.HashMap(u128, *SessionData),

    /// Each entry is at least 20 bytes long; the first 20 bytes hold
    /// (retry_time, session_id), the remaining bytes the serialized SessionData.
    replay_queue: std.PriorityQueue([]u8, void, lessThan),
};
```

`std.PriorityQueue` is the stage-one choice. Later it is replaced by an object with a strongly identical interface but
composite internals, where the priority queue (or its extension) is only one provider among several, plus ordered files.
To reflect the file work from day one, the queue is used through a wrapper whose peek is failable:

```zig
pub const PriorityQueue = struct {
    pub fn peek(self: *Self) !?[]u8
    // ...
};
```

where `!` expresses problems arising while working with the backing storage.

### 1.3 `SessionData`

```zig
const SessionData = struct {
    const Self = @This();

    /// A session may be a restored one, brought back for replay-compensation.
    /// Work on it then happens in a NEW session — the data may have been moved
    /// to a completely different shard with its own settings, where this index
    /// simply does not exist and the front would go crazy figuring out which
    /// index to push the client's next portion of data into. For a freshly
    /// created session this is, of course, a duplicate of the session's own id.
    original_id: u128,

    /// Compensator: the identifier of the service that must perform
    /// compensations for this session. Set by the user at session creation.
    /// Validated by the service: it must check that such a compensator is
    /// configured. "Configured" means a network address of the compensator is
    /// given, and the compensator implements the compensation-replay protocol.
    /// A string rather than a number: the operation is rare, and on the logging
    /// path fetching a name by identifier would be the pain. The natural
    /// requirement: in the once-created compensators map the key names must
    /// NEVER change.
    ///
    ///     compensators = fixed {
    ///         marker = bind { bind = "10.0.0.1", port = 20301 }
    ///         viper  = bind { bind = "10.0.0.2", port = 20301 }
    ///         hermes  = bind { bind = "10.100.10.10", port = 20301 }
    ///     }
    ///
    /// Mind the extensions toward "cloud native": besides `bind` there will be
    /// `dns`, `grpc` (meaning xDS or etcd for the latter), and eventually the
    /// compensators block becomes a runtime resolver of compensator endpoints.
    compensator: []const u8,

    /// Count of compensation attempts. 0 for new sessions. A failed
    /// compensation increases it by 1.
    retry_count: u32,

    /// The session's own data. This field changes under the operations:
    /// - `Create`. Semantically Create would better be payload-free, but then
    ///   we would pay an extra hop.
    /// - `Append`. Adds a new piece of data.
    /// - `Overwrite`. The whole data content is replaced by the new piece.
    /// All other operations touch metadata only.
    data: []u8,
};
```

### 1.4 Codecs

**`data` chunks.** One piece of payload is always encoded as `uvarint(payload.len)` followed by the payload bytes.
`Create(payload)` initializes `data` with one such chunk; `Append(payload)` appends one to the tail;
`Overwrite(payload)` replaces the whole buffer with one.

| `uvarint(payload.len)` | `payload...` |
| ---------------------- | ------------ |

**`SessionData`.** Exactly these bytes are the stored representation:

| `original_id: LE(u128)` | `uvarint(compensator.len)` | `compensator...` | `retry_count: LE(u32)` | `uvarint(data.len)` | `data...` |
| ----------------------- | -------------------------- | ---------------- | ---------------------- | ------------------- | --------- |

**Replay-queue blob.** The queue entry carries the ordering key and the length-prefixed serialized session:

| `retry_time: LE(u64)` | `session_id: LE(u128)` | `uvarint(session_data.len)` | `session_data...` |
| --------------------- | ---------------------- | --------------------------- | ----------------- |

**Queue dump.** The built-in bulk unload of a priority queue is unordered, and the future composite minheap spills to
ordered files precisely because the heap grew too big — reloading an unordered dump would mean pulling all of it back
into memory. So the dump is taken as the ordered output of an iteration over a cloned queue, and since the compensation
session is already represented as the blob above, the entries are written verbatim:

| `uvarint(minheap.count())` | `minheap iteration...` |
| -------------------------- | ---------------------- |

**`IndexState` dump.**

| `version: LE(u16)` | `uvarint(sessions_count)` | `session by session...` | `PriorityQueue dump` |
| ------------------ | ------------------------- | ----------------------- | -------------------- |

The source pins the container but not the per-session record inside it; that record is pinned in this thread as **U4**.

## 2. The implementation plan

### 2.1 The split: shapes in `state.zig`, behavior in `lifetime.zig` — **U1 (blocking)**

- `src/state.zig` holds **shapes only**: the types of §2.2 with their fields, the format constants, the error set of the
  queue wrapper, and the blob comparator. The comparator is included because it is a comptime argument of the queue
  _type_ (`std.PriorityQueue([]u8, void, blobOrder)`) and therefore part of the structure, not behavior. No function in
  `state.zig` computes, mutates or allocates anything beyond what the type declarations themselves need.
- `src/lifetime.zig` holds **every behavioral function**: init/deinit of the state, application of operations, the
  lifecycle transitions, all codecs (uvarint, chunks, `SessionData`, blob), the dump and load of `IndexState`, the queue
  drain, compensator validation, and session-id allocation. They are free functions in a new banner section of
  `lifetime.zig`, beside the existing `Controller`; the process-lifetime code already there is untouched. Naming follows
  the file's existing convention (plain `pub fn`s, no new singleton).
- The current draft contents of `state.zig` are superseded: `WALOperation` becomes the `Op` union of §2.2 (**U11**),
  `Session` is absorbed into the map value (**U2**), `Buffer` survives as the capacity holder for `data` (**U2**).

Proposed, to be confirmed in **U1**: the wrapper's own methods (`peek`, `push`, `pop`, removal, `deinit`) are mechanical
one-liners over `std.PriorityQueue` plus memory ownership, shown by the source itself as part of the type, and therefore
live in `state.zig`; everything else is in `lifetime.zig`. If a stricter line is wanted (every `fn`, including the
wrapper's, in `lifetime.zig` as free functions taking `*PriorityQueue`), say so in the pad.

### 2.2 The structure inventory (`src/state.zig`)

```zig
    /// of the composite queue.
    pub const Error = error{OutOfMemory};

    pub fn peek(self: *Self) Error!?[]u8;
    // ... push, pop, removeSessionId, count, snapshotHandles, deinit — U3.

/// Numeric tuple order on the blob heads: retry_time first, session_id second.
/// NOT a memcmp over the LE bytes — see U7.
fn blobOrder(_: void, a: []u8, b: []u8) std.math.Order;

fn hashSessionId(id: u128) u64; // U5: proposed verztable.wyhash over the 16 bytes

```

Notes bound to the sketch:

- **U5.** The map cannot be the plain `verztable.HashMap(u128, *SessionData)` written in the source: the vendored
  `AutoHashFn` hashes an integer key as `hashInteger(@as(u64, @intCast(key)))`, and the checked cast truncates — a panic
  in safe builds for any id ≥ 2^64, silent wrong hashing in ReleaseFast. Session ids are
  `(host_id: u8, epoch_id: u56, index: u64)` per the HLD, so the high bits are populated as a matter of course.
  Proposed: `HashMapWithFns` with `hashSessionId = verztable.wyhash(std.mem.asBytes(&id))` and `eqlSessionId = a == b`.
  Confirm, or name a different mix.
- **U6.** The source's stated reason for the separate `sessions_count` ("verztable gives no count") is stale: the
  vendored copy has `pub fn count() usize` over a `key_count` field, O(1). Proposed: drop the field, and let the dump
  writer emit `uvarint(sessions.count())`. Alternative: keep it per the source's field list and maintain it on every
  insert/remove. The dump format is identical either way; only the field's existence is at stake.
- **U7.** "Ordered lexicographically by `(retry_time: u64, session_id: u128)`" is tuple order — compare the times
  numerically, break ties by the ids numerically. A `memcmp` over the little-endian head bytes is NOT that: for
  multi-byte LE numbers byte-lexicographic order disagrees with numeric order (e.g. retry times 0x0102 vs 0x0201).
  Proposed: `blobOrder` decodes both heads with `std.mem.readInt` and compares numerically. Confirm, or say that raw
  byte comparison was meant after all.

The queue's own `push`/`pop`/`peek`/removal are the wrapper's methods (§2.1, **U1**); the ordered dump works off the
wrapper's `snapshotHandles()` (**U3**): a duplicate of the handle slice only — blobs are borrowed, not copied — which
`dumpIndexState` sorts with `state.blobOrder` and emits. Zig 0.17's `std.PriorityQueue` has no `clone()`, so the
source's "iteration over a cloned queue" is realized as dupe-handles + sort + emit: same ordered output, same
non-destructive property, no blob copies.

### 2.4 The lifecycle, as the plan reads the source

1. **`Create(compensator, payload)`.** Validate the compensator against the configured registry (**U11**); allocate a
   session id (own index's counter — **U9**); insert into `sessions` with `original_id` = the new id and `data` = one
   chunk.
2. **`Append` / `Overwrite`.** Chunk-append at the tail, or replace the whole buffer with one chunk. Growth uses the
   capacity field of **U2**; the chunk codec is `uvarint(len) || payload`.
3. **`Close`.** Free the session's memory and remove it from `sessions`. A queued (evicted) session can also be closed
   by id: the wrapper's removal (**U3**) drops its blob.
4. **`RestartIn(session_id, seconds)`.** Serialize the session, build the blob with `retry_time = now + seconds`, push
   it into `replay_queue`, remove the session from `sessions`. This transition IS the source's "send session X to replay
   in T seconds" — the queue entry itself carries the future due time, so no separate timer is needed for the queue; the
   `timing-wheel` subject stays responsible for the other computed lifetimes (mirror silence, session liveness), not for
   this ordering. The clock behind `now` is pinned as **U8**.
5. **Drain.** Each pass of the index service loop (**U12**): while `peek()`'s head has `retry_time <= now`, `pop()` it,
   decode the `SessionData`, allocate a fresh session id (**U9**), re-insert as active. `retry_count` survives the trip
   (it is serialized in the blob) and is incremented only on a failed compensation, never on the round-trip itself.
6. **Compensation failure.** `retry_count += 1`, then the session is re-armed through the `RestartIn` transition. The
   compensator protocol on the wire is out of scope for this thread.

### 2.5 Invariants

1. The map key is the session's **current** id; at evict time it equals the blob's `session_id`.
2. `original_id` names the lineage root of the session (**U9**); for a fresh session it duplicates the session's own id.
3. Every blob is at least 20 bytes; its first 20 bytes are the LE `(retry_time, session_id)` head; the remainder is a
   length-prefixed `SessionData` codec.
4. Queue order is the numeric `(retry_time, session_id)` tuple order (**U7**); the dump is emitted in exactly that
   order; load accepts nothing else.
5. The dump begins with `version: LE(u16)`; a loader rejects unknown versions (**U4**).
6. The compensator registry's key names are immutable once created (source requirement); a `Create` naming an unknown
   compensator is rejected before any state changes.
7. All of this state is owned by exactly one index thread; no locks, no atomics (the G1 discipline already documented in
   `src/timing_wheel.zig`).
8. The queue wrapper owns every blob it holds (**U3**): `push` copies, `pop` and removal transfer, `deinit` frees what
   is left.

### 2.6 Tests (`zig build test`)

- **Chunk codec:** round-trip of `data` after Create/Append/Overwrite, including empty payloads and multi-byte uvarint
  lengths.
- **`SessionData` codec:** round-trip; compensator bytes with hostile contents; exact byte layout against a golden
  vector built from the source's field table.
- **Blob codec and `blobOrder`:** numeric tuple order, explicitly including pairs where a memcmp over the LE bytes would
  give the wrong answer (**U7**).
- **Queue:** N random inserts, drain yields the sessions sorted by `(retry_time, id)`; removal by session id; peek does
  not disturb order; failable surface returns `error.OutOfMemory` under a failing allocator.
- **Lifecycle:** create → `restart_in` → drain → the session is back with a new id, the lineage `original_id` and the
  `retry_count` intact; close of a queued session; re-arming a queued session (remove old blob, push new deadline).
- **Dump/load:** whole-`IndexState` round-trip; empty queue; zero sessions; a dump from an unknown future version is
  rejected (**U4**).
- **uvarint edges:** 0, 127, 128, `u64` maximum.

### 2.7 Where it plugs in

- `src/index.zig`'s `run` loop owns the state on its stack and calls `lifetime.applyOp` / `lifetime.popDue` from its
  batch handling; the placeholder session counting of the current skeleton is replaced. Whether this wiring lands in the
  same change or a follow-up is **U12**. The front→index op plumbing and the consensus reactions stay with
  `consensus-driver`.
- The mirror data sets (**U10**) are additional `IndexState` values in the same thread; mirror application is the same
  `applyOp` path reached by the replication inbox instead of the front.
- `dumpIndexState` feeds the snapshot side of the startup sequence (HLD §2: "read the last immutable snapshot, then
  replay the WAL over it"); `loadIndexState` is its first step. The WAL integration itself belongs to `wal-design`.
- The compensator registry is built from the config's `compensators` block at index startup (**U11**); the config
  grammar work is a follow-up.

## Open questions

- **U1 (blocking).** The structure/logic boundary. Proposed: `state.zig` = shapes, constants, error sets, the
  comparator, and the queue wrapper's mechanical methods (the source itself shows `peek` on the type); `lifetime.zig` =
  every behavioral function listed in §2.3, as free functions beside the existing `Controller`. The stricter alternative
  — the wrapper's methods also move to `lifetime.zig` as free functions over `*PriorityQueue` — keeps `state.zig` free
  of any `fn` bodies. Confirm the proposed line, or draw yours.

- **U2 (blocking).** The map value and the runtime session shape. The source pins `HashMap(u128, *SessionData)` with a
  pure four-field `SessionData`, but the working session also needs consensus runtime state (the op-state machine,
  consensus progress, the timing-wheel handle of the current draft `Session`) and a growth capacity for `data` (the
  draft `Buffer`). Options: (a) map value is a runtime `Session` wrapper embedding a pure `SessionData` — the source's
  map line deviates in the value type; (b) doc-literal `*SessionData` with exact-size `data` and runtime state in a side
  structure — two lookups, and every `Append` pays a full realloc; (c) `*SessionData` extended with never-serialized
  runtime fields (state machine, progress, wheel handle, `data_cap`), the codec still encoding exactly the source's four
  fields. Proposed: **(c)** — one lookup, one allocation, the source's map line stays literally true, the draft
  `Session` is absorbed field-for-field, and the explicit codec keeps the persisted shape pure in practice. Confirm, or
  pick another option.

- **U3 (blocking).** The replay-queue wrapper contract. Proposed surface in `state.zig`: `peek() Error!?[]u8` (borrow of
  the head, per the source's code block; the source's prose says `peekOrNull` — the code block wins unless you say
  otherwise), `push(blob) Error!void` (copies the blob; the queue owns it), `pop() Error!?[]u8` (removes and transfers
  ownership), `removeSessionId(id) Error!?[]u8` (O(n) scan of the heap comparing the id at blob bytes 8..24, then
  `popIndex` — needed for closing or re-arming a queued session; std's `update` only matches a full `(time, id)` pair
  and is useless here), `count()`, `snapshotHandles() Error![][]u8` (ordered-dump support: duplicates the handle slice
  only, blobs borrowed — Zig 0.17's `std.PriorityQueue` has no `clone`, and this is the concrete realization of the
  source's "iteration over a cloned queue"), `deinit()`. `Error = error{OutOfMemory}`, extended when the
  composite/file-backed providers land. Also: the source names the wrapper type `PriorityQueue`, shadowing
  `std.PriorityQueue` in the very file that imports it — proposed rename to `ReplayQueue`, doc-literal `PriorityQueue`
  as the alternative. Confirm the surface and the name.

- **U4 (blocking).** The per-session record inside the `IndexState` dump, and the version value. The source pins the
  container (`version: LE(u16)`, `uvarint(sessions_count)`, then "session by session", then the queue dump) but never
  the per-session record. The current id must be written explicitly: for a re-activated session it differs from
  `original_id`, and it is the map key. Proposed record: `session_id: LE(u128)` (the current id, the map key) followed
  by `uvarint(len)` and the `SessionData` codec bytes — i.e. the replay blob minus `retry_time`. Proposed
  `SNAPSHOT_VERSION = 1`, unknown versions rejected by the loader with `error.UnsupportedVersion`. Confirm, or give your
  record layout.

- **U5.** The u128 key hash. The vendored verztable's `AutoHashFn` would truncate the key via a checked `@intCast`
  (panic in safe builds) for every id ≥ 2^64 — and ids carry `epoch_id` in the high bits, so such ids are the norm.
  Proposed: `HashMapWithFns(u128, V, hashSessionId, eql)` with `hashSessionId = verztable.wyhash(std.mem.asBytes(&id))`
  and `eql = a == b`. Confirm, or name a different mix.

- **U6.** The `sessions_count` field. The source keeps it "because the verztable HashMap gives no count", but the
  vendored copy now has an O(1) `count()`. Proposed: drop the field and derive the dump's `uvarint(sessions_count)` from
  `sessions.count()`. Alternative: keep it per the source's field list and maintain it on every insert/remove. The dump
  format is identical either way. Confirm one.

- **U7.** The comparator. "Ordered lexicographically by `(retry_time: u64, session_id: u128)`" is read as tuple order:
  numeric by time, ties numeric by id. A `memcmp` over the LE-encoded head is NOT numeric order for multi-byte integers
  (0x0102 < 0x0201 numerically, but the byte-lexicographic comparison says the opposite). Proposed: `blobOrder` decodes
  both heads with `std.mem.readInt` and compares numerically. Confirm, or state that raw byte comparison was the intent.

- **U8.** The clock behind `retry_time`. The queue's due times must survive a dump/reload across a restart, so a
  monotonic clock is wrong (a reboot resets it). Proposed: `retry_time` is CLOCK_REALTIME nanoseconds, `nowRealtimeNs()`
  in `lifetime.zig` (over `clock_gettime`; zigring's `monotonicNs()` is explicitly not used here). `RestartIn` computes
  `retry_time = now + seconds * 1_000_000_000`. Confirm, or name a different domain.

- **U9.** Re-activation identity. A replay-born session gets a **new** session id (the source's "work on it happens in a
  NEW session"), allocated by the index thread itself — there is no front in the picture. Proposed: `IndexState` gains
  `session_seq: u64` (this is one of the `// ...` elisions of the source's struct), fresh ids compose it per the HLD's
  `(host_id: u8, epoch_id: u56, index: u64)` layout; the exact epoch wiring is `consensus-driver`'s business.
  `original_id` semantics: proposed **lineage root** — a re-activated session copies `original_id` from the blob (so the
  root survives any number of generations), while the alternative is immediate predecessor (copy the blob's
  `session_id`). Root is proposed because the compensator must address the original business session, and `retry_count`
