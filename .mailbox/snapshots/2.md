## 1. The pad's answers, restated as fact

- **U1 — any hosted pair is a snapshot subject.** The candidates are all pairs `(host_idx, index_idx_0)` the thread
  hosts, own and mirror alike: they are the same `IndexState` values, equally thread-local and equally quiescent, and
  `cloneIndexState` (`src/lifetime.zig:969`) deep-copies any of them. This supersedes `sdks/state-snapshot.md` §1's and
  §6 rule 5's "own data set only" and `designs/INDEX-STATE.md` §12's own-scope bullet; §12 gains the one-line amendment
  at promotion, as iteration 1 promised.
- **U2 — the tag is an ordered marker, not a content binding.** The tag is the pair's `state_idx` at the first dispatch,
  fixed in the job, and both names carry it. The pair is **not pinned** for the window: events keep flowing between
  dispatch and the handler, so the snapshot content sits at a state `Y ≥ X` while both names say `X` — by design,
  because equal tags make the snapshot+WAL pair detectable by name if the fixed file is ever lost, which is more
  reliable than reconstructing a `W1 < S1 < W2 < S2` ordering. Iteration 1's pin reading is dropped. The consequence —
  the chain anchor and the loader's `st.state` must move off the name tag — is worked out in §3.2 and proposed as **U13
  (blocking)**.
- **U3 — close is hygiene, not durability; a final elephant closes the old file.** Writes are `O_DIRECT` (with
  `RWF.DSYNC` in PMEM mode, `src/wal.zig:538`), so `close(2)` manages only the OS file object's lifetime. At the swap
  the index thread therefore does **not** run the landed writer `close` (which drains and awaits on the caller's ring,
  `src/wal.zig:1262`); instead, after switching the interface from composite to single-new, it sends yet another
  elephant — cursor pick 3 — a final message: close this file. The elephant closes the old fd best effort, warns on
  failure, keeps working, and **releases the snapshot slot** — the procedure's last act. The demanded intermediate-steps
  proposal is §6 (**U5**).
- **U4 — freeze and revival as proposed, confirmed.** During the window, the **old side's** refusal set freezes the
  front: a negative flush CQE faults that writer, and `WalFull` (the oversized old file hitting capacity) freezes too,
  because the swap is what retires the old file. Pure submission backpressure stays park-and-retry. A fault on the
  **new** side is the ordinary terminal stop (`src/wal.zig:1206-1222`, unchanged). Revival at the swap: the old writer
  is retired and gone, the surviving writer is healthy, the frozen window's events were written new-first — the front
  reopens; a relapse re-freezes terminally. A failed procedure while frozen leaves the stop standing. The assumption
  stands as confirmed: only the front advances a thread's pairs today, and the consensus design must preserve it.
- **U6 — the fixed file lives in an index directory; compaction at ~128 KiB.** Everything an index controls lives in
  `some/root/indexDirName(index_idx)/`, with the fixed file inside — preferred over a root-level name, because whole
  index directories can be mapped onto different drives at the hardware-setup level. The name functions are templates
  like `index.{index_idx}`; exact spellings are the staged plan's. Compaction (keep the last `N` per `host_idx`,
  write-temp/fill/rename) runs once the file hits ~128 KiB, not on every change — so appends between compactions are
  **bare appends**. The elephant stays the append actor and the commit point, before the completion message (iteration
  1's bundle, unobjected). The bare-append consequence is **U17**; the directory's full scope is **U16**.
- **U7 — the snapshot slot is a Controller-owned limiter.** The process-wide "at most one" rule and iteration 1's
  one-held-message-slot reading are both superseded: a new `snapshot_slots` pool on `lifetime.Controller`,
  `init(allocator, N)` at `Controller.init` beside `cross_slots` (`src/lifetime.zig:155`), acquired at the tick when a
  procedure is wanted; `CrossTaskFull` → the tick skips. `N` is the process-wide bound on parallel procedures — several
  index threads may run concurrently, capacity permitting. The doc's per-index invariant still holds on top of it, as a
  correctness rule rather than a resource one: one composite per thread, guarded by the thread's own in-flight flag (the
  pair's writers belong to it). Why slots and not an atomic counter in a critical section: the acquire must hand the
  procedure a **stable, exclusive index for its whole duration**, and that index is exactly the temporary-WAL buffer
  area slot (the pad's critical) — a counter can neither guarantee exclusivity across the window nor hand the index back
  exactly once from wherever the procedure ends. The polished discipline is proposed as **U15**.
- **U8 — global knobs, writer-extent metric.** The period `T` and the size barrier `S` are single global config fields,
  the same for all indexes. The metric stands as proposed: the writer's tracked write extent, buffered tail included
  (`current`/`cursor`, `src/wal.zig:608-611`) — thread-local, no syscalls, no `fileSize` on the hot path. Field names
  are the staged plan's.
- **U9 — an io_uring timeout ticker.** Each index thread arms a repeating timeout op on its own ring at startup —
  `pushTicker(taskIdx, spec, count, flags)` with count 0, the `front.zig:221` pattern (count 1 is the one-shot deadline
  shape, `src/main.zig:212`), the timespec parked in `RingStuff.tick_spec` (`src/lifetime.zig:1226`), the period from
  config. The tick is the timeout CQE itself under a new reserved `taskIdx` — `messages.zig`'s top-half space has room
  (`maxInt(u64)-2`, `-3` and `-7` are free, `src/messages.zig:39-74`). No new thread, no shared timer service; the
  timing wheel stays out of it.
- **U10 — one atomic cursor.** Plain round-robin over the elephants, one atomic cursor in `lifetime.Controller` shared
  by all threads; the tasks are rare, so contention is a non-issue. The second and third picks naturally land on other
  elephants, which satisfies the doc's "may be a different one" without load tracking.
- **U11 — the process-stop request.** A reserved stop-request `taskIdx` into the init ring; main's park widens from
  signalfd (`src/main.zig:176-188`) to signalfd **and** init-ring CQEs; on the message main runs the existing
  `shutdown()` (`src/main.zig:261-306`) — the graceful path, fronts and elephants included, with the faulting elephant's
  log entry as the operator's breadcrumb. The exact poll shape over the two fds is the staged plan's.
- **U12 — scope as proposed, confirmed.** The recovery contract stays and is pinned as §3.5 states it; retention and
  orphan cleanup, and the post-restart epoch bump's sequencing, are deferred to a later material — this design only
  guarantees orphans are never registry-referenced. The split of the implementation plan into stages stays out.

## 2. The critical items, addressed

### 2.1 Buffers for the temporary WALs

> They'll need it, to ensure same guarantees as for existing WAL files. Extend the PMEM-mapping:
> `| area for (host_idx, index_idx) buffers | buffers for temporary WALs |`. The amount of temporary buffers is `N`,
> indexed by `snapshot_slots.acquire()`. Introduce a new `lifetime.Controller` constructor method, which constructs a
> WAL file with a buffer in the new area.

Adopted, with the seam split the landed rules force:

- **The temp area.** The battery mapping gains a second section — `indexes × hosts` pair areas, then `N` temp rings —
  each ring geometrically identical to a pair area (the data array plus the header array of `buffers × (lba + 64)`,
  `src/wal.zig:230-249`). The window's new writer lives on ring `k`: PMEM-published control lines (`CLWB`+`SFENCE`,
  `src/wal.zig:925-931`), a crash-durable un-flushed tail, `O_DIRECT`+`DSYNC` flushes — the same guarantees as a home
  writer, which is the whole point: a mid-window power cut must leave the new file's tail recoverable exactly as the old
  file's is. Plain mode keeps the same geometry in DRAM, where durability stays file-only (its contract,
  `src/config.zig:89`). `openBattery` maps the larger total — the `WalBatteryTooSmall` check (`src/wal.zig:302`) grows
  with it; the walk and `chainLen` never touch the temp section, which is reached only through a writer wired to it or
  through the adoption mark of §2.2.
- **The mint.** Ring `k` is reused procedure after procedure, and the walk trusts `buffer_seq` (`walkVerdict`,
  `src/wal.zig:388-395`; `isFilled`, `:1127-1130`), so a previous procedure's stale lines must never be reachable. The
  adopt therefore **mints** the ring before wiring the writer: clean the header array, one barrier, then publish the
  ordinal-0 terminator. A zeroed line classifies as stale at any nonzero ordinal, and the writer's own
  terminator-before-bytes invariant (`closeBuffer`, `src/wal.zig:1091-1114`) covers the rest.
- **The constructor split.** "The elephant never touches the battery" (`designs/wal-impl.md` §1.1's third pin, landed in
  the comments at `src/lifetime.zig:369-371`) splits the requested constructor across the two actors: **(a)**
  elephant-side, a create method on the Controller — `wal.<host>.<index>.<X>` under its final name, `O_CREAT | O_TRUNC`
  plus one `fdatasync` before the fd reply. The truncate is load-bearing: a same-tag retry (the pair's state may not
  have advanced after a failed procedure) reopens a file that may hold the failed attempt's flushed prefix, and a stale
  flushed prefix would survive the plain-mode walk as if it were content; truncating and syncing the empty length kills
  it, and an unreferenced file is retention's anyway. **(b)** index-thread-side, the reshaped `walAdoptWrite` — the
  adopt: mint ring `k`, open the writer over the transferred fd on ring `k`, publish the ordinal-0 terminator, set the
  head (**U13**). The confirm is folded into **U14**.

### 2.2 The adoption field and its dance

> We introduce a new field `adoption: i16` into a buffer header — `-1`, no migration in flight, or `0..N-1`, a WAL
> adoption in process. The adoption: (1) barrier rewrite of the header with `adoption` set to buffer index; (2)
> `@memcpy` of data from a temporary WAL buffer to a `(host_idx, index_idx)` area, barriered; (3) barrier rewrite with
> `adoption` set to `-1`. This means we can detect incomplete adoptions after a restart and may finish them there.

Adopted in full. The crash analysis below forces two refinements — where the mark is **published**, and where it
**lives** — and both are bundled into **U14 (blocking)** for confirmation rather than slipped in.

**(a) The mark must be published at the handler, not at the swap.** The recovery's read is a merged stream: the file's
flushed bytes, then the battery's chain walked by `buffer_seq` (`chainLen`, `src/wal.zig:1591-1610`; `beginRead`,
`:1670-1679`). A pair whose winning registry line names the new WAL must therefore find the **new** chain in the pair
area — but until the copy runs, the pair area holds the **old** file's chain, and the walk would take it: the old file
is the big one, its ordinals overlap the new file's frontier, and `deliver` does no state arithmetic ("a jump is
legitimate inside one file", `src/wal.zig:1485-1493`). A crash anywhere between the elephant's append and the swap's
completed copy would replay the old chain on top of the new snapshot — double-apply, silent corruption. A mark published
only at the swap leaves that window unguarded. Published at the **handler** — barriered, before the composite serves and
hence before the dump dispatch, which is before any registry line can exist — the mark covers every crash point:

| crash at          | pair area | fixed file | mark | recovery                                            |
| ----------------- | --------- | ---------- | ---- | --------------------------------------------------- |
| create → handler  | old chain | old line   | -1   | the old pair, exactly as today                      |
| handler → append  | old chain | old line   | k    | old pair; clear the mark, reclaim ring `k`          |
| append → copy     | old chain | new line   | k    | **finish**: copy ring `k` home, clear, the new pair |
| mid-copy          | torn mix  | new line   | k    | **finish**: idempotent re-copy, the new pair        |
| copy → mark clear | new chain | new line   | k    | **finish**: re-copy (no-op data), clear             |
| post-swap         | new chain | new line   | -1   | the new pair                                        |

The finish decision needs the migrating file's identity, so the temp ring's own control line carries
`(host_idx, index_idx, tag)` published at the adopt: at startup, a pair area marked `k` whose winning line names that
same file gets the finish (re-copy ring `k` into the pair area — idempotent, the source is intact until the slot is
reused — then clear the mark); a marked pair whose winning line is the **previous** one is an aborted migration — the
mark alone never moved bytes, the old chain is intact — so clear the mark and reclaim ring `k`. Copy-start implies
line-committed, by construction: the elephant appends and `fdatasync`s before the completion message, and the swap runs
only on the completion. A torn pair area therefore always exists **after** the new line, so it is always finished
forward and never read as the old pair. The finish runs before any `walOpenWrite` / `walOpenRead` of the pair.

The mirror-image order — copy first, append after, which is `sdks/state-snapshot.md` §3.6's shape — is unsound under the
temp ring: a crash between copy and append would leave the **new** chain under the **old** line, the opposite
corruption. The source doc's order survives (append elephant-side, then the swap); the SDK's §3.6 ordering joins its
actor and format as superseded — already flagged in iteration 1's U6.

**(b) The mark cannot live in one of the ring's buffer headers.** `writeHeader` rewrites the whole line — "a stale lap
cannot leak a field into the new one", `src/wal.zig:886-905` — so the still-live old writer's next publish of the marked
slot would erase the mark (its ring wraps onto every slot eventually). Proposed: a dedicated 64-byte **per-area control
line** — the area's own header, outside the ring's `buffers` lines, the area stride growing by one line — holding
`adoption: i16` exactly as specified (plus the temp rings' identity fields). No writer touches it; the dance rewrites
only it. The field matters precisely where the line persists — the pad's "coupled buffers": PMEM, where the control line
and its data survive together. Plain mode never reads it, but its copy still runs (DRAM to DRAM, no barriers) — the
writer's un-flushed tail must move home regardless, or the rewired writer would point at the old file's bytes.

The dance, restated with both refinements: (1) at the handler, barrier-publish `adoption = k` on the pair area's control
line; (2) at the swap, after the drain below, one barriered `@memcpy` of the whole temp ring — data and headers — into
the pair area; (3) barrier-rewrite the control line with `adoption = -1`.

**The drain.** The copy needs both the retiring old writer's and the migrating new writer's in-flight flushes landed
first: a late `flushComplete` would publish a terminator into the pair area **after** the copy clobbered it
(`src/wal.zig:1169-1189`), and a new-side DMA still reading ring `k` must be done before `release(k)` can be safe from
any later acquirer. At most one flush is ever in flight per writer (`src/wal.zig:602-603`), so the wait is bounded — but
it cannot be `close`'s `awaitFlush`, which retires and **drops** foreign completions (`src/wal.zig:1238-1253`):
mid-service that would strand another pair's writer with `flush_in_flight` stuck. The swap drains by stepping every CQE
through the thread's ordinary dispatch (the `index.zig:106-157` arms) until both writers are quiet; control-plane
messages that land during the drain are handled by the loop pass that follows.

## 3. The choreography, reshaped end to end

Iteration 1's §4 is superseded by this section wherever they differ. Every `**U**` marks a point that still needs the
pad.

### 3.0 The tick

Each index thread arms its repeating ticker at startup (U9) and gains the dispatch arm for its reserved `taskIdx` —
today reserved indices fall into `else` and are dropped (`src/index.zig:118-126`). On the tick: skip if the thread is
stopped (§3.5's terminal stop — a stopped thread's files do not grow) or a procedure is already in flight for this index
(the thread's own flag; the doc's per-index invariant, kept on top of U7's global bound). Then read the hosted pairs'
tracked extents (U8); pairs above the global `S` are candidates and the largest wins. Then `snapshot_slots.acquire()` →
`k`, or skip the tick if the limit is hit (U7). The tick never retries.

### 3.1 Dispatch: the file

The job — heap, `ctrl.allocator`, the SDK §3.2 integer-handle pattern — carries `host_idx`, `index_idx`, the tag minted
now (the pair's `state_idx`, U2), `k`, the phase, the fd, the arena, the clone, `old_fd`, and the paths. Cursor pick 1
(U10). A message slot from the ordinary `cross_slots` pool: `acquire()`, write `{ job }` — well under the 16-byte cap
(`src/cross_task.zig:67`) — and `MSG_RING` the slot id into the elephant's ring; receiver-released on read, exactly as
today (`src/elephant.zig:29-32`). Elephant-1 runs the create constructor of §2.1 and replies `{ job, fd }` by the same
machinery. The fd is the only thing that crosses threads; the elephant never touches the battery or the live state.

### 3.2 The handler: one synchronous pass

No front message is processed inside the pass, so nothing slips between its steps:

1. **Clone.** The chosen pair — any hosted pair, own or mirror (U1) — is deep-copied into the job's arena. Its state is
   `Y`, at or ahead of the tag `X` (U2: the pair kept serving; no pin). An allocation failure unwinds quietly (**U5**,
   §6 step 3).
2. **Adopt.** Over temp ring `k`: mint the ring (§2.1), open the writer on the transferred fd, publish the ordinal-0
   terminator with `last_state = Y`, and set the writer's head to `Y`. The chain anchors at the **clone state**; the
   file's **name** keeps the dispatch tag `X` — the decoupling U2's thesis demands, proposed as **U13 (blocking)**. The
   old writer is **not** closed: the landed close-first contract (`src/lifetime.zig:444-448`, asserted at `:2038-2098`)
   is reshaped — and the temp ring is what dissolves `wal-impl` §3.4's structural objection ("two writers would share
   the pair's one ring and collide"): they no longer share one. The `WalOpen` one-writer-per-pair guard yields to the
   procedure's second writer for the window's duration.
3. **Mark.** Barrier-publish `adoption = k` on the pair area's control line (§2.2) — before the composite serves, hence
   before any registry line can exist.
4. **Composite.** The pair's write interface writes every event **new first, then old** (U3/U4). Both writers chain
   independently (`floor == head` per side, `src/wal.zig:955`) and both heads sit at `Y`, so the first event is `Y+1` on
   both sides; the old file stays a complete history, the new file accumulates the post-clone tail. The new writer
   flushes new-side normally — one flush in flight, like any writer.
5. **Re-dispatch.** Cursor pick 2 — possibly a different elephant, the doc says so — `{ job }` again; a refused push
   parks and retries while the window keeps serving.

### 3.3 The dump elephant

Synchronous, the SDK §3.3-3.5 discipline verbatim: `dumpIndexState` over the clone, write `snapshot.<host>.<index>.<X>`
— the tag from the job — under its final name, one `fdatasync`, one `arena.reset(.free_all)`. Then the registry, in
`<indexDir(index_idx)>/` (U6): a bare append of

```json
{"host_idx":H,"snapshot_path":"...","wal_path":"..."}
```

with its mandatory `\n`, then one `fdatasync` — the commit point, elephant-side, before the completion message (U6's
unobjected bundle). `wal_path` names the **new** WAL; both paths carry the tag `X`, which is the whole pairing property
(U2). If the file has hit ~128 KiB, compact transactionally: write-temp, fill with the last `N` lines per `host_idx`,
rename. An unparseable line met while compacting → the stop-request (U11). Reply "complete" with the spin-wait retry on
a refused push (the `reportDone` idiom, `src/elephant.zig:67-75`).

### 3.4 Completion: the swap and the final close

One synchronous pass on the index thread: the composite collapses to the single new writer; the bounded drain of §2.2
runs; the adoption dance runs — copy ring `k` into the pair area, clear the mark; the writer rewires its buffers to the
pair area. If the thread was frozen, revival (U4): the front-denial rule becomes "any **live** writer's fault denies the
front", and retirement removes the old writer from that set — the frozen window's events were written new-first and the
registry line is committed, so the front reopens. The old fd is stored in the job; cursor pick 3; `{ job }` to the final
elephant: `close(2)` the old fd — best effort, warn on failure, keep working (U3) — then destroy the job and
`snapshot_slots.release(k)`. The per-index in-flight flag clears at this dispatch. The old WAL is now an unregistered
orphan — retention's, never recovery's. The temp ring's contents are dead but harmless until some later procedure mints
ring `k` again.

### 3.5 The recovery contract

At startup an index thread, per hosted pair, in order: run the adoption-finish rule of §2.2 (before any open of the
pair); read the fixed file — the **last** line with that `host_idx` wins, naming the snapshot and the WAL; an invalid
line is fatal (**U17**'s tail exception proposed); load the snapshot (`loadIndexState`, `src/lifetime.zig:890`); open
the writer (`walOpenWrite`, `src/lifetime.zig:394` — the walk supersedes its head) and set `st.state` from the **walked
head** — from the persisted ordinal-0 terminator in PMEM mode, never from a name tag (**U13**); `attachStream`; replay
via `walOpenRead` with `seek_then_read(st.state)` (`src/wal.zig:1299-1304`). The registry-lost arm — the index directory
is scannable, snapshot and WAL pair by equal tag, the max complete pair per `(host, index)` wins — is **U18**. The full
startup choreography stays with the startup material (U12).

## 4. Invariants

- At most one procedure per index thread (the thread's in-flight flag) and at most `N` process-wide (`snapshot_slots`);
  a tick that hits either bound is skipped, not queued (U7).
- The snapshot slot `k` is occupied for the whole procedure, regardless of outcome; the final close elephant releases it
  on success, the index thread on failure (U3/U7).
- The tag is minted at the first dispatch, fixed in the job, and carried by both names; the snapshot content may run
  ahead of it; the chain anchor is the clone state `Y`, persisted in the new WAL's ordinal-0 terminator (**U13**).
- The pairing property: `snapshot.h.i.X` pairs with `wal.h.i.X`; equal tags, unique among live files because a same-tag
  retry truncates its own orphan (U2, §2.1).
- `adoption == -1` on every pair area outside a procedure; `adoption == k` means the pair's migration from temp ring `k`
  is in flight and its completion is restart-detectable and idempotent (§2.2).
- Copy-start implies line-committed: the registry append and its `fdatasync` precede the completion message, which
  precedes the swap (§2.2).
- A registry-visible file implies its ordinal-0 terminator was persisted (carried from `wal-impl`; the publish moves to
  the adopt, still before the append).
- The elephant sees only the clone; the fd is the only thing that crosses threads; the battery is never touched by the
  elephant — the mint and the terminator are index-thread acts (§2.1).
- The composite writes new-first-then-old; the old side's refusals freeze the front, never the control plane; the new
  side's fault is the ordinary terminal stop (U4).
- The last line per `host_idx` is the pair's committed snapshot; an invalid line is fatal at startup and at runtime (U6,
  **U17**).
- The durability contract is unchanged: a record is durable when its flush completes; the overlay adds no barrier and
  removes none.

## 6. The failure ladder

U3's pad demanded it; U5's pad deferred to it. Every phase, what can fail, who unwinds, and how the thread ends up.
Crash (power-cut) cases are not listed per step — they are §2.2's table, uniformly.

0. **`snapshot_slots.acquire()` fails.** Not a failure: the tick ends. The limit is the design working.
1. **The dispatch push is refused.** Ring backpressure: park and retry, holding `k`. The thread keeps serving.
2. **The create fails** (open, write, or the truncate's `fdatasync`). The elephant replies failure through the same
   slot. **Unwind A** (index thread): `snapshot_slots.release(k)`, destroy the job, log. End state: serving on the old
   pair; a zero-length or truncated orphan under a tag no line references — retention's.
3. **The clone cannot be allocated.** **Unwind A** — no mark exists yet, ring `k` is untouched, nothing was installed.
   Proposed: a quiet unwind with a log line, not the process-fatal idiom — the tick retries on its own schedule
   (**U5**).
4. **The adopt cannot be allocated.** The adopt is memory-only (the mint, the terminator, the writer object), so this is
   the clone's twin: **unwind A**. The mark is published only after the adopt (§3.2's step 3), so nothing needs
   clearing; ring `k` holds at most a minted header array, referenced by nothing. End state: as 2.
5. **The dump fails** (`OutOfMemory`, write, `fdatasync` of the snapshot). The elephant replies failure after the arena
   reset. **Unwind B** (index thread): revert the composite to the old single writer; close the new writer — healthy, so
   its drain is the bounded drain of §2.2 — and orphan the new WAL (no registry line exists: the failure precedes the
   append); clear the mark (barrier); release `k`; destroy job and arena; log. If the thread was frozen, the stop stands
   (U4) — the unwind runs on the control plane, which keeps flowing. End state: serving on the old pair, or frozen until
   restart.
6. **The registry append fails.** The line must not survive torn: best-effort `ftruncate` back to the prior length plus
   `fdatasync`; if even the truncation fails, the stop-request (U11) — a torn line is a startup fatality (**U17**). Then
   **unwind B**; the snapshot file exists but gains no line — unreferenced junk, exactly the `state-snapshot` §3.5 rule.
   End state: as 5.
7. **The compaction fails.** Log-only: the rewrite is transactional, the old file stands, the line was already appended
   — the procedure **succeeds**; the reply is "complete". The next procedure's compaction retries. End state: normal
   completion.
8. **The completion reply push is refused.** The elephant spin-retries (`src/elephant.zig:67-75`).
9. **The swap.** Memory only — the drain, the copy, the mark — and cannot fail; its crash cases are §2.2's.
10. **The final close fails.** `close(2)` on the old fd: warn, keep working (U3); `release(k)` regardless. End state:
    the procedure is done.
11. **The thread stops outside any procedure.** Ticks skip it (§3.0); the stop's terminal semantics
    (`src/wal.zig:1206-1222`) are unchanged. **The thread faults during a window**: the procedure still completes on the
    control plane, and the revival follows U4's side rule — old-side freeze revives at the swap, new-side fault leaves
    the stop standing. End state: revived, or stopped until restart.

## Open questions

- **U5.** The failure ladder. Iteration 1 asked for the unwind shape; the pad answered "reshape in accordance with U3",
  and U3's answer demanded "intermediate steps what we will do if we fail on some preliminary step, how we will end up".
  §6 above is that ladder: every phase from the tick to the final close, the unwinding actor, and the end state. Two
  judgment calls need the pad's eyes: (a) step 3 — a clone that cannot be allocated unwinds quietly (release the slot,
  log, let a later tick retry) rather than taking the process down; (b) step 6 — a failed registry append best-effort
  truncates the fixed file back to its prior length and escalates to the stop-request only if the truncation itself
  fails, because a surviving torn line is a startup fatality. Confirm the ladder, including (a) and (b).
- **U13 (blocking).** Where the chain anchors, now that names are only markers. U2's confirmed thesis decouples the
  names from the content: the snapshot file holds state `Y` while both names say the dispatch tag `X`. The new WAL's
  records are `Y+1..`, so its base — the ordinal-0 terminator's `last_state` and the writer's head — must be `Y`, not
  `X`, or the first post-composite event is refused (`floor == head`, `src/wal.zig:955`) and the recovery walk resumes
  from a lie. Proposed: the adopt publishes the terminator with `last_state = Y` (the clone state) and sets head to it,
  in both modes; the loader takes `st.state` from the walked head — the persisted terminator in PMEM mode — superseding
  `state-snapshot` §5's "set it from the file-name tag" rule and `INDEX-STATE` §12's matching phrase (the name becomes
  purely a pairing marker; §5's own warning, "losing the tag loses mint continuity", is honored by the terminator
  instead). The landed close-first tests at `src/lifetime.zig:2065-2098` (which assert `last_state == tag`) are reshaped
  with the seam. One hole remains, and it is plain mode's: its battery is DRAM, so after a restart nothing durable
  carries `Y` — an empty new WAL walks to head `X` (`walkPlain`, `src/wal.zig:767-781`), and a pair whose replay
  delivers nothing would mint `X+1` on top of content that already absorbed it — the duplicate-session-id corruption §5
  warns about. Proposed fix: the registry line gains a fourth key, `"state":Y` (the file is new, nothing deployed); the
  loader sets both `st.state` and the reopened writer's head from it in plain mode, and ignores the redundant key in
  PMEM mode. Alternative: pin the pair for the window in plain mode only, forcing `X == Y` there. Confirm the anchoring
  and pick the plain-mode fix.
- **U14 (blocking).** The adoption mechanics, as reshaped from the pad's critical. Both refinements of §2.2 are forced
  by crashes, but both refine the pad's own words, so they are surfaced rather than assumed: (a) the mark's **publish
  point** moves from the swap to the handler — the pad's three steps survive as mark-at-handler / copy-at-swap /
  clear-at-swap, because a mark that first appears at the swap leaves the append→copy crash window unguarded, and the
  merged read would replay the old chain on top of the new snapshot (§2.2's derivation and table); (b) the mark's
  **placement** is a dedicated 64-byte per-area control line rather than one of the ring's buffer headers, because
  `writeHeader` rewrites whole lines (`src/wal.zig:886-905`) and the still-live old writer would erase a per-slot mark
  on its next lap — the area's own line is still "a buffer header" in every sense the field cares about, and it also
  hosts the temp ring's `(host, index, tag)` identity that the restart-time finish decision reads. Also bundled: the
  finish rule itself (marked `k` + winning line names the migrating file → idempotent re-copy; marked `k` + previous
  line → aborted migration, clear and reclaim), the mint of a reused temp ring before first use, the swap's bounded
  well-mannered drain (`close`'s `awaitFlush` drops foreign completions, `src/wal.zig:1238-1253` — unusable
  mid-service), and the §2.1 constructor split (elephant creates and truncates+fdatasyncs the file; the index thread
  mints, adopts and publishes the terminator — the elephant still never touches the battery). Confirm the bundle.
- **U15.** The polished procedure discipline. U7's pad asked for the polishing after the U3 input; proposed shape:
  `CrossTaskSlots` is generalized over its payload type (today it is concrete over `CrossTask`,
  `src/cross_task_slots.zig:16-25`); the Controller gains `snapshot_slots: CrossTaskSlots(usize)` — the payload is the
  job handle, "just use usize" — initialized `init(allocator, N)` beside `cross_slots` at `Controller.init`
  (`src/lifetime.zig:155`), and `N` is a config field (naming is the staged plan's). The procedure's long-lived context
  is the **snapshot slot**: acquired at the tick (its index selects the temp ring), carrying the job handle, released
  exactly once — by the final close elephant on success, by the index thread on failure. The per-phase **messages** use
  the ordinary `cross_slots` pool with `{ job }` payloads (`SnapshotCreate`/`SnapshotDump`/`SnapshotClose` variants,
  plus the reply variants carrying `fd` or status; all plain data under the 16-byte cap, `src/cross_task.zig:56-68`),
  receiver-released on read in both directions — the existing discipline, so the elephant's arm only grows task kinds,
  not a new slot etiquette. The index loop's `CrossTaskMessageIdx` arm is implemented (today reserved indices fall into
  `else` and are dropped, `src/index.zig:118-126`), dispatching by payload variant; the job's fields are written by the
  index thread between phases and read by an elephant only within one, so the ring's ordering is the whole
  synchronization. Confirm the discipline.
- **U16.** The index directory's scope. U6's pad chose "everything that is controlled by an index lies in its index
  directory", with the drive-mapping rationale — which only pays off if the directory holds the **data**, not just the
  tiny fixed file. Proposed: `<wal root>/<indexDirName(index_idx)>/` hosts the pair's WAL files, the snapshot files and
  the fixed file alike; `walPath` keeps its `wal.<host>.<index>.<state>` leaf names (the `index_idx` in them stays,
  keeping names globally unique for tools and retention) and its `dir` argument becomes the index directory at the three
  Controller call sites (`src/lifetime.zig:399`, `:480`, `:509`) plus the snapshot-path helper. Nothing is deployed, so
  there is nothing to migrate. Alternative: the fixed file alone moves, and WALs stay in the shared root. Confirm the
  scope.
- **U17.** The registry's torn tail. The doc makes an invalid line a fatal error of startup and of functioning; the
  pad's 128 KiB compaction choice (rightly) rejects rebuilding the file on every append, so appends are bare — which
  means a power cut mid-append can leave a torn last line and the next start bricks until manual repair. The same
  exposure exists for a failed append at runtime (the ladder's step 6 truncates, but the truncation can fail). Proposed:
  a **torn-tail exception** — at startup, an unparseable **last** line that also lacks its mandatory trailing `\n` is
  truncated away with a warning and the start proceeds; every other invalid line stays exactly as fatal as the doc
  demands (it means the file was corrupted some other way). Alternative: accept the brick as the doc's letter.
  Non-blocking either way; the runtime fatality (compaction meeting an invalid line) is untouched.
- **U18.** The registry-lost fallback. U2's pad made the equal-tag pairing the mechanism for recovering the pairs "if
  that JSONL log file was lost for some reason" — the property is pinned as an invariant, but the procedure that uses it
  is not yet anywhere. Proposed: pin it in §3.5 as one rule — when the fixed file is absent or unreadable, scan the
  index directory, group `snapshot.*` and `wal.*` by equal tag, and per hosted pair adopt the **max-tag complete pair**
  (a snapshot at tag `t` plus a WAL at tag `t`; unpaired files are skipped). Notably this can adopt a procedure whose
  dump and `fdatasync` succeeded but whose registry append failed — that pair is complete on disk and recovery-correct,
  so adopting it loses less than falling back. Alternative: defer the procedure to the startup material and keep this
  design to the property. Non-blocking.

## U5.

### If an index failed to create a deep copy.

1. Move to a single (old) file WAL interface.
2. Sets a proper status in a slot (rollback or such).
3. Push a task to any elephant, so it will clean things up: remove that new file and release the slot.

If we failed to push (`RingFull`), we use a special "pending" op in the index state. This will work as there's no more
than a single snapshot process per index. At each processing step we look at pending and if it is not a null, we tries
to push it again. Something like

```zig
var snapshot_pending: ?CrossTask = null; // will have exactly that op we tried to push.
```

alternatively, we may use a special type that will dispatch the op needed. This seems unnecessary at the moment though.

### If we failed to append.

Let's reconsider how we do things. I propose a new approach: we rewrite this file on each step:

1. We read the old file and leave only last N entries per each `(host_idx, index_idx)` pair.
2. Create a new file under a temporary (FIXED!, e.g. `/some/fixed/path.pending`) name which will have a new data.
3. Rename pending file name into that fixed name.

An error on each step will result into a seq:

1. Push "abandon new WAL file" task into the index.

And index will do the same back-task "clean up the mess" where we are leaving the new WAL file out of the equation.
