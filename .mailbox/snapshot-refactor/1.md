`src/elephant.zig` and becomes `src/snapshot.zig`, with the two existing files calling into it, and with the index and

plan adds is a `U`, including the two that set the file boundary.

## 1. The request and the tree as it stands

The procedure semantics are pinned by `designs/SNAPSHOTS.md`: the tick (§1.1-§1.2), the handler pass (§3.2), the dump
(§3.3), the swap (§3.4), restart (§3.5), the bring-tail (§3.6), the message discipline (§4), the completion, freeze and
revival rule (§5), the failure ladder (§8), and startup recovery (§7.1). None of those semantics change in this
refactor. What changes is where the transition function lives.

Two existing statements become false by construction and must be reconciled rather than silently ignored.
`designs/SNAPSHOTS.md:14` says "**No new files are created**" and assigns the handlers to `src/elephant.zig` and the
loop wiring to `src/index.zig`. The author's new request overrides that file-split paragraph; the design's behavioural
text still stands. How to record the supersession is U6.

The largest boundary question is whether "snapshot logic" includes the `Controller` resource operations. The request
names only `index.zig` and `elephant.zig` as the places the logic is smeared across, and `designs/SNAPSHOTS.md:11-15`
already assigns the writers, composite, battery windows and fixed-file helpers to `lifetime.zig`. I propose keeping that
resource layer where it is and making `snapshot.zig` the policy layer. U1 asks for confirmation because it decides how
much of `lifetime.zig` moves.

## 2. Target architecture

Three layers, with dependencies pointing one way:

```text
index.zig     --imports--> snapshot.zig --imports--> lifetime.zig
elephant.zig  --imports--> snapshot.zig --imports--> lifetime.zig
```

`snapshot.zig` never imports `index.zig` or `elephant.zig`. The `snapshot -> index -> snapshot` walk is expressed
through a structural host interface, not a module import: the index supplies an object with the methods the snapshot
driver needs, and the driver is generic over that object with `anytype`. The reverse edge exists because the host's
`step` method calls the index's ordinary CQE dispatcher, which routes snapshot replies back into the same driver. That
is the finite state machine expressed in the API, and it is also what keeps the dependency graph acyclic.

The three sealed objects are:

- **`snapshot.State`** — the procedure's state and transition function: the in-flight job, the pending push, the live
  window, the tick counter and the serve gate. It is a plain value stored in the index thread's frame; no allocation, no
  virtual dispatch.
- **`index.SnapshotHost`** — a private adapter around `index.Frame`. It exposes only the resources the driver needs:
  controller, ring, logger, ring/index identity, one data set, and the bounded-drain step. This is the "seal" that lets
  snapshot call index without knowing `Frame`.
- **`snapshot.Elephant`** — the cold-actor object: controller, logger and the elephant's own ring identity. The elephant
  thread constructs one and hands it tasks; all `Snapshot*` handling lives behind it.

The state ownership question is U2: I propose that `wal_serve` (`serving`, `frozen`, `stopped`) becomes
`snapshot.State.serve`, because the freeze and revival rule is §5 and the tick's skip condition is §1.2. The index's
front-intake guard then reads the same field, so the gate has one owner and one transition set.

### 2.1 The finite state machine, explicitly

The machine's stable state is `procedure == null`; an in-flight procedure carries `Job.phase`. The event set is the
reserved tick, the six reply variants, a flush completion and the pending-push retry.

| Current state  | Event                                       | Next state     | Action                                                                                                                          |
| -------------- | ------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| idle           | tick                                        | `create_sent`  | Check serve/procedure/pending, select the largest pair over the barrier, acquire `k`, mint the job, dispatch `SnapshotCreate`.  |
| `create_sent`  | `SnapshotFd`                                | `dump_sent`    | Publish the mark, clone, adopt temp ring `k`, install the composite, dispatch `SnapshotDump`.                                   |
| `create_sent`  | `SnapshotCreateFailed`                      | `cleanup_sent` | `unwindA` with no mark and no writer.                                                                                           |
| `dump_sent`    | `SnapshotDumped`                            | `close_sent`   | Bounded drain, copy temp ring into the pair, clear the mark, revive if frozen, retire the old writer, dispatch `SnapshotClose`. |
| `dump_sent`    | `SnapshotDumpFailed`, `SnapshotAbandon`     | `cleanup_sent` | `unwindB`: drain, revert to the old writer, close and destroy the new one, clear the mark, dispatch `SnapshotCleanup`.          |
| `close_sent`   | `SnapshotDone`                              | idle           | Clear `procedure`; the elephant has released `k`.                                                                               |
| `cleanup_sent` | `SnapshotDone`                              | idle           | Clear `procedure`; the elephant has released `k`.                                                                               |
| any            | illegal reply                               | unchanged      | Warn, do not transition, do not free anything.                                                                                  |
| serving        | old-side window fault or `WalFull`          | `frozen`       | Deny the front; the window keeps serving on the new side.                                                                       |
| frozen         | successful swap, no live fault              | `serving`      | Reopen the front.                                                                                                               |
| any            | new-side fault, or a fault outside a window | `stopped`      | Terminal for front work; the control plane still completes the procedure (§8 rung 10).                                          |

The transition checks are part of the API, not comments: an entry point that needs a job and does not find one logs the
same defensive warning as today, and an entry point that needs a phase can assert it under `std.debug.assert` in tests.
The existing `SnapshotPhase` enum already encodes the procedure half; the refactor gives it a single owner.

## 3. Proposed API

The sketch below is the contract the next iteration can refine. It is deliberately small: every function is an event
entry point or a resource callback, and no function exposes `Frame`.

```zig
//! Snapshot procedure: the index-side finite-state driver and the
//! elephant-side cold handlers. Resource ownership stays in lifetime.zig.

pub const Phase = enum { create_sent, dump_sent, close_sent, cleanup_sent };

pub const Job = struct {
    arena: std.heap.ArenaAllocator,
    clone: state.IndexState,
    host_idx: u8,
    index_idx: u16,
    ring_idx: u16,
    tag: u128,
    k: u32,
    phase: Phase,
    fd: posix.fd_t,
    old_fd: posix.fd_t,
    wal_path: [:0]u8,
    snapshot_path: [:0]u8,
};

pub const Serve = enum { serving, frozen, stopped };

pub const PendingPush = struct { slot_idx: u32, target_ring_idx: u16 };

/// Moved from lifetime.CompositeWriter; its completion rule is §5.
pub const CompositeWriter = struct { /* fields and write/noteFlush/quiet unchanged */ };

pub const State = struct {
    serve: Serve = .serving,
    procedure: ?*Job = null,
    pending_push: ?PendingPush = null,
    window: ?CompositeWriter = null,
    ticks: u32 = 0,

    pub fn armTicker(self: *State, host: anytype) void;
    pub fn onTick(self: *State, host: anytype) void;
    pub fn onReply(self: *State, host: anytype, task: cross_task.CrossTask) void;
    pub fn onFlush(self: *State, host: anytype, writer: *wal.WalWriteFile) void;
    pub fn onWriterFault(self: *State, host: anytype, writer: *wal.WalWriteFile) void;
    pub fn onWriteError(self: *State, host: anytype, err: wal.WalError) void;
    pub fn retryPending(self: *State, host: anytype) void;
};

pub fn mintJob(
    ctrl: *lifetime.Controller,
    host_idx: u8,
    index_idx: u16,
    tag: u128,
    k: u32,
    ring_idx: u16,
) !*Job;

pub fn releaseJob(ctrl: *lifetime.Controller, job: *Job) void;

/// §7.1; explicit resources, because it runs before the service-loop frame exists.
pub fn recoverPair(
    ctrl: *lifetime.Controller,
    ring: *lifetime.RingStuff,
    logger: *lifetime.LoggerStuff,
    index_idx: u16,
    host_idx: u8,
    st: *state.IndexState,
) !void;

pub const Elephant = struct {
    ctrl: *lifetime.Controller,
    log: *logging.Logger,
    ring_idx: u16,

    pub fn handle(self: *Elephant, task: cross_task.CrossTask) void;
    pub fn create(self: *Elephant, job: *Job) void;
    pub fn dump(self: *Elephant, job: *Job) void;
    pub fn cleanup(self: *Elephant, job: *Job) void;
    pub fn close(self: *Elephant, job: *Job) void;
};
```

The required host surface is a documented, compile-time duck type. It is intentionally six methods and one callback:

```zig
// Required host surface for snapshot.State:
//   controller() *lifetime.Controller
//   ring() *lifetime.RingStuff
//   logger() *lifetime.LoggerStuff
//   ringIdx() u16
//   indexIdx() u16
//   dataSet(host_idx: u8) *state.IndexState
//   step(cqe: zigring.CQE) void
```

The index adapter is private to `index.zig`:

```zig
const SnapshotHost = struct {
    frame: *Frame,

    fn controller(self: SnapshotHost) *lifetime.Controller { return self.frame.ctrl; }
    fn ring(self: SnapshotHost) *lifetime.RingStuff { return self.frame.ring; }
    fn logger(self: SnapshotHost) *lifetime.LoggerStuff { return self.frame.logger; }
    fn ringIdx(self: SnapshotHost) u16 { return self.frame.ring_idx; }
    fn indexIdx(self: SnapshotHost) u16 { return self.frame.index_idx; }
    fn dataSet(self: SnapshotHost, host_idx: u8) *state.IndexState {
        return &self.frame.data_sets[host_idx];
    }
    fn step(self: SnapshotHost, cqe: zigring.CQE) void { stepCQE(self.frame, cqe); }
};

fn snapshotHost(frame: *Frame) SnapshotHost { return .{ .frame = frame }; }
```

The index call sites stay recognizable: the cross-task arm ends in `frame.snap.onReply(snapshotHost(&frame), task)`, the
tick arm in `frame.snap.onTick(snapshotHost(&frame))`, and the flush arm in
`frame.snap.onFlush(snapshotHost(&frame), flush.writer)` followed by
`frame.snap.onWriterFault(snapshotHost(&frame), flush.writer)`. The loop pass calls
`frame.snap.retryPending(snapshotHost(&frame))` before waiting. Recovery and the ticker arm call the explicit-resource
functions, because neither has a frame.

The host choice is U3. The alternative is an explicit struct of function pointers (a vtable). I propose `anytype`
because the request explicitly says virtualization is not required and because the fake host in `snapshot.zig`'s tests
becomes a plain struct with the same methods. There is no runtime dispatch, no context pointer cast, and a missing
method is a compile error at the instantiation site.

## 4. What stays where

Subject to U1, the split is:

| File             | Keeps                                                                                                                                                                                                                                  | Loses                                                                                                                                                  |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `lifetime.zig`   | Controller ownership: `snapshot_slots`, `walAdoptWrite`, adoption marks, `copyTempIntoPair`, `runAdoptionRule`, `bringTail`/`TailSink`, registry, `indexDirPath`, `ensureIndexDir`, `nextElephantRing`, the state dump/load/clone SDK. | `SnapshotPhase`, `SnapshotJob`, `CompositeWriter`, `mintSnapshotJob`, `releaseSnapshotJob`; those become `snapshot.zig` types and functions.           |
| `index.zig`      | The CQE switch, front admission, `recordFits`, WAL flush mechanics, non-snapshot arms, the startup call into `snapshot.recoverPair`, the tick CQE arm.                                                                                 | The snapshot state fields, ticker arm, tick pass, dispatch, pending retry, reply routing, handler pass, swap, drain, unwinds, freeze/revive, recovery. |
| `elephant.zig`   | The thread loop, the non-snapshot task arms, the shutdown path.                                                                                                                                                                        | Every `Snapshot*` handler, `jobOf`, `replyTo`, the stop request, the file write/unlink helpers.                                                        |
| `snapshot.zig`   | The procedure FSM, both actors' handlers, recovery, the job and composite types.                                                                                                                                                       | Nothing.                                                                                                                                               |
| `cross_task.zig` | The wire vocabulary and the 16-byte bound.                                                                                                                                                                                             | Nothing.                                                                                                                                               |

The wire vocabulary stays in `cross_task.zig` because it is the transport's own type: `cross_task_slots`, `messages`,
and the comptime plain-data assert all consume it, and moving it would force
`cross_task -> snapshot -> lifetime -> cross_task`. The slot pool itself stays a Controller field for the same reason:
it is process-wide resource management, initialized next to `cross_slots` (`src/lifetime.zig:305-306`).

## 5. Migration plan

The plan is a strangler sequence. Each stage ends with `zig build test` and `zig build check`; a stage that cannot keep
the suite green is split rather than forced. The existing tests are the behaviour oracle, so the first stage records a
baseline and the last compares against it.

**Stage 0 — baseline.** Record the current test result on the uncommitted tree, and record the exact count of tests per
file. This matters because the tree already carries unrelated work; a failure after a stage must be attributable to the
stage, not to the starting point. The baseline taken for this letter is `zig build test --summary all`: **207/207 tests
pass**, with the expected failure-path stack traces on stderr (the registry-rename and dump-failure tests deliberately
provoke `unexpectedErrno` and recover through the ladder).

**Stage 1 — a compiling `snapshot.zig` with aliases.** Create `src/snapshot.zig` with `Phase`, `Job` and
`CompositeWriter` as aliases of the lifetime types, plus `Serve`, `PendingPush`, `State` and the `Elephant` shell. No
logic moves yet. This gives every later stage a stable import and lets the build's per-file walker compile the new file
from day one (`build.zig:198-240`).

**Stage 2 — the trigger and dispatcher.** Move the ticker arm, `tickPass`, `dispatchSnapshot`, `retryPendingPush` and
`resyncStream` behind `State`. Add `snap: State` to `Frame`; move `procedure`, `pending_push`, `snapshot_ticks` and
`wal_serve` into it (U2). Add the `SnapshotHost` adapter and update the `stepCQE` arms. Update tests from
`frame.procedure` to `frame.snap.procedure`, and the same for the other moved fields. This is the largest mechanical
diff; it is also where the adapter is proven.

**Stage 3 — the reply FSM and the handler pass.** Move `dispatchSnapshotReply` and `snapshotFdPass`, and move `window`
into `State`. The handler pass is a pure sequence of controller calls, so its body moves verbatim. Tests keep their
names and call `snapshot` entry points through the adapter.

**Stage 4 — completion, drain, unwinds and serve transitions.** Move `snapshotDumpedPass`, `drainUntilQuiet`, `unwindA`,
`unwindB`, `reviveIfHealthy`, `onCompositeWriteError` and the fault-classification half of `onWriterFault`. The flush
arm in `stepCQE` becomes `onFlush` plus `onWriterFault`; the WAL's own `flushResult` stays in `index.zig`. This is the
stage where the `snapshot -> index -> snapshot` recursion becomes real, because `drainUntilQuiet` calls `host.step`,
which can re-enter `onReply`.

**Stage 5 — startup recovery.** Move `StartupReplay`, `readWholeFile` and `recoverPair` into `snapshot.zig` (U4). The
signature takes explicit `ctrl`, `ring`, `logger`, `index_idx`, `host_idx` and `st`, because recovery runs before the
frame is built. `index.run` keeps the loop that calls it per hosted pair and the fatal-error policy. The recovery tests
already in `index.zig` keep driving the same function and stay in place until Stage 7.

**Stage 6 — the elephant object.** Move `createSnapshot`, `dumpSnapshot`, `writeSnapshotFile`, `closeSnapshot`,
`cleanupSnapshot`, `unlinkBestEffort`, `requestProcessStop` and `replyTo` behind `snapshot.Elephant`. `elephant.zig`'s
`handleTask` collapses all snapshot request and reply variants into one delegation; the "elephant read a snapshot reply
it does not handle" warning moves with them. Move the elephant fixture tests that exercise only snapshot handlers into
`snapshot.zig`; keep any test that also asserts the elephant loop in `elephant.zig`.

**Stage 7 — the type move and the test move.** Replace the Stage 1 aliases with real definitions of `Job`, `Phase` and
`CompositeWriter` in `snapshot.zig`; move `mintSnapshotJob`/`releaseSnapshotJob` to `mintJob`/`releaseJob`. The
composite test in `lifetime.zig` (the `WalFixture` sink and the both-frontiers test around `src/lifetime.zig:3501`) and
the job-mint test around `:3395` move to `snapshot.zig`, because they are now snapshot tests. This is the stage that
makes the dependency direction strict: `lifetime.zig` must have no reference to any snapshot type.

**Stage 8 — cleanup and promotion.** Remove dead imports, aliases and helper copies; run the invariant greps below;
amend `designs/SNAPSHOTS.md` per U6; compile this thread into `designs/snapshot-refactor.md` when the pad closes. No
behavioural test is deleted: the e2e tests (startup recovery, the plain-mode end-to-end procedure, the freeze ladder,
the stop mid-window, the PMEM adoption cases) stay in `index.zig` and must pass unchanged.

The test-migration policy is U5 because it changes the size and shape of the review. My proposal is: move unit tests
with the code they test, keep integration and wiring tests where they already are, and never rewrite an assertion while
moving it. A moved test that changes meaning is a red flag, not a convenience.

## 6. Verification

The commands are the repository's own:

```sh
zig build test
zig build check
```

`zig build test` already walks every file under `src/` and runs its `test` blocks (`build.zig:198-240`), so
`snapshot.zig` is covered even before anything imports it. Beyond the suite, the refactor is verified by invariants:

- `rg -n "@import\(\"index.zig\"\)|@import\(\"elephant.zig\"\)" src/snapshot.zig` is empty.
- `rg -n "SnapshotJob|SnapshotPhase|CompositeWriter" src/lifetime.zig` is empty after Stage 7.
- `rg -n "fn (tickPass|snapshotFdPass|snapshotDumpedPass|unwindA|unwindB|recoverPair|createSnapshot|dumpSnapshot|closeSnapshot|cleanupSnapshot)" src/index.zig src/elephant.zig`
  is empty after Stage 8.
- The `Frame` surface left in `index.zig` is `snap`, plus the host adapter; no procedure field is duplicated.
- `git diff --stat` shows `index.zig` and `elephant.zig` shrinking, `snapshot.zig` growing, and `lifetime.zig` shrinking
  by the moved types. A move that grows the two adapters is a sign the seam is wrong.
- The e2e procedure still writes the same files, in the same order, and the registry line is unchanged. The tests
  already assert the snapshot path, the WAL path, the tag, the final state and the slot release; they remain the
  contract.

No allocator or ownership change is part of the plan. `Job` is still heap on the controller's allocator, still released
only by the terminal elephant; `CompositeWriter.pending` is still owned by the controller's allocator; the temp ring is
still the slot index. The refactor is a move of code and an ownership seam, not a lifetime redesign.

## 7. Risks and mitigations

| Risk                                                                                                       | Mitigation                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The drain re-enters the FSM: `drainUntilQuiet` -> `host.step` -> `onReply`/`onFlush` -> `drainUntilQuiet`. | Preserve the current single-procedure invariant and add a test that delivers a flush completion and a terminal reply during the drain. The state checks make a second procedure impossible. |
| `anytype` host surface drifts.                                                                             | A fake host in `snapshot.zig`'s tests implements the same seven methods; a missing or renamed method fails compilation. Document the surface next to `State`.                               |
| `Frame` tests are numerous and touch every moved field.                                                    | Stages 2-4 are mechanical renames; the compiler enumerates all of them. No test assertion is rewritten, only the path to the field.                                                         |
| The resource boundary leaks: `snapshot.zig` starts reaching into `lifetime` internals.                     | U1 keeps the resource API in `lifetime`; any new `pub` there is a review flag. The snapshot file calls controller methods, never its private fields.                                        |
| Startup recovery is left half-moved.                                                                       | U4 makes it one stage; if it stays in `index.zig`, the doc must say so, and the file remains partly a snapshot owner.                                                                       |
| The design document contradicts the new layout.                                                            | U6 records the supersession and amends the file-split paragraph; the behavioural sections of `designs/SNAPSHOTS.md` are untouched.                                                          |
| A "pure move" accidentally changes behavior.                                                               | Stage gates, unchanged assertions, and the invariant that no test is edited for meaning. Any real bug found on the way is a separate note, not a silent fix in this refactor.               |

## Open questions

- **U1 (blocking).** Does the refactor's "logic" boundary include the `Controller`'s snapshot-specific resource
  operations (`walAdoptWrite`, the adoption marks, `copyTempIntoPair`, `runAdoptionRule`, `bringTail`, the registry,
  `mintSnapshotJob`/`releaseSnapshotJob`, the snapshot slot pool, the elephant cursor), or only the index/elephant
  procedure logic? Proposed: only the procedure policy, recovery, handlers and the procedure types move to
  `snapshot.zig`; the resource operations stay in `lifetime.zig`, because they are process-wide ownership, they are
  already assigned there by `designs/SNAPSHOTS.md:11-15`, and moving them would force private `lifetime` internals
  public and invite a `lifetime <-> snapshot` cycle. Confirm or override; if the answer is "move them too", the file and
  stage plan changes materially.
- **U2 (blocking).** Should the serve gate (`serving`, `frozen`, `stopped`) live in `snapshot.State` or remain in
  `index.Frame`? Proposed: move it into `snapshot.State`, because the freeze and revival rule is `designs/SNAPSHOTS.md`
  §5 and the tick's skip condition is §1.2, while the front-intake guard can read the same field. The alternative keeps
  the gate in `Frame` and gives the host getter/setter methods; the FSM then has two owners. Confirm or override.
- **U3 (non-blocking).** Is the structural `anytype` host the right seam, or should `snapshot.zig` define an explicit
  vtable of function pointers? Proposed: `anytype`, with the seven-method surface documented beside `State` and a fake
  host in tests, because the request says virtualization is not required and this keeps the call graph
  compile-time-only. The same answer covers the proposed names (`State`, `Job`, `Phase`, `CompositeWriter`, `Serve`,
  `Elephant`); they are easy to change before Stage 7.
- **U4 (non-blocking).** Does startup recovery (`recoverPair`: adoption rule, registry, snapshot load, writer,
  bring-tail, replay) move to `snapshot.zig` as well? Proposed: yes, as Stage 5, with explicit `ctrl`/`ring`/`logger`
  arguments because it runs before the frame exists. If no, it stays an index-startup function and the final `index.zig`
  still owns one snapshot procedure stage.
- **U5 (non-blocking).** Where should the moved tests live? Proposed: unit tests travel with the code they test (index
  snapshot-driver tests and elephant handler tests into `snapshot.zig`; composite and job-mint tests out of
  `lifetime.zig`), while the e2e and wiring tests stay in `index.zig`. The alternative keeps every test in its original
  file and calls `snapshot` entry points from there, which is a smaller diff but leaves snapshot tests scattered.
- **U6 (non-blocking).** How should `designs/SNAPSHOTS.md` record the new file split? Proposed: amend its file-split
  paragraph to name `src/snapshot.zig` as the procedure's home and keep everything else unchanged; the behaviour
  sections remain normative. The alternative leaves the design as history and records the supersession only in the
  promoted `designs/snapshot-refactor.md`. Confirm which document carries the new split.
