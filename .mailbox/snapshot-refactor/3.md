## 3. The pump

### 3.1 Stage 1's index-local shape

Before the shell exists, Stage 1 fixes the defect with index-local code. This is the intermediate that Stages 2-5 then
move; it must not differ semantically from the final form.

```zig
const Drain = enum { swap, revert };

// Frame gains:
pending_drain: ?Drain = null,

/// The two writers are quiet, or there is no window: the pump may continue.
fn drainQuiet(frame: *Frame) bool {
    const window = if (frame.window) |*w| w else return true;
    retryParkedFlush(window.new);
    retryParkedFlush(window.old);
    return window.quiet();
}

/// Runs outside every `inbox.batch` window: commit first, then pump.
fn drainPump(frame: *Frame) void {
    while (frame.pending_drain != null) {
        if (drainQuiet(frame)) {
            onDrained(frame);
            continue;
        }
        if (frame.ring.ring.popCQE()) |cqe| {
            stepCQE(frame, cqe);
            continue;
        }
        frame.ring.ring.park();
    }
}

fn onDrained(frame: *Frame) void {
    const mode = frame.pending_drain orelse return;
    frame.pending_drain = null;
    switch (mode) {
        .swap => finishSwap(frame),
        .revert => finishRevert(frame),
    }
}

fn beginSwap(frame: *Frame) void {
    if (frame.procedure == null) {
        frame.logger.logger.warn("snapshot completion without a procedure", .{ .ring_idx = frame.ring_idx });
        return;
    }
    frame.pending_drain = .swap;
}

fn beginRevert(frame: *Frame) void {
    if (frame.procedure == null) {
        frame.logger.logger.warn("snapshot failure reply without a procedure", .{ .ring_idx = frame.ring_idx });
        return;
    }
    frame.pending_drain = .revert;
}
```

`finishSwap` is today's `snapshotDumpedPass` (`index.zig:649-727`) with the `drainUntilQuiet` call deleted: the job
fetch, the no-window terminal branch, the copy, the rewire, the mark clear, the revival, the retirement and the close
dispatch. `finishRevert` is today's `unwindB` (`index.zig:786-836`) with the same deletion: the close of the new
writer, the mark clear, the rollback and the cleanup dispatch. `drainUntilQuiet` (`index.zig:729-744`) is deleted; no
production caller survives it.

`dispatchSnapshotReply` (`index.zig:515-547`) keeps its structure but its two completion arms become `beginSwap` and
`beginRevert`, and it gains the D1 guard:

```zig
fn dispatchSnapshotReply(frame: *Frame, task: cross_task.CrossTask) void {
    const log = &frame.logger.logger;
    if (frame.pending_drain != null) {
        log.warn("snapshot reply arrived while the window was draining; ignored", .{
            .ring_idx = frame.ring_idx,
        });
        return;
    }
    switch (task) { ... }
}
```

The guard is part of D1, not a new decision: while a drain continuation is set, the procedure has no legal reply until
the terminal dispatch, and a second completion of the same event must not re-enter a half-finished transition. The
regression test asserts it.

The loop (`index.zig:352-360`) gains exactly this, and the `continue` is deliberate:

```zig
while (batch.ring.popCQE()) |cqe| stepCQE(&frame, cqe);
batch.ring.commit() catch |err| { ... };

if (frame.pending_drain != null) {
    drainPump(&frame);
    continue;
}

while (batch.front.next()) |task| switch (task) { ... };
```

The `continue` is safe: `IndexInbox.batch` stores both windows on the inbox, and an unconsumed front task stays queued
because `front.next()` was never called (`src/index_inbox.zig:324-345`, `:372-379`). The CQ cursor is committed before
the pump opens the raw ring, which is the whole fix.

Test helpers: `drainUntilQuiet(&frame)` becomes `pumpWindow(&frame)`, a test-local copy of the pump without
`onDrained`:

```zig
fn pumpWindow(frame: *Frame) void {
    while (!drainQuiet(frame)) {
        if (frame.ring.ring.popCQE()) |cqe| {
            stepCQE(frame, cqe);
            continue;
        }
        frame.ring.ring.park();
    }
}
```

`drainWriterQuiet` (`index.zig:3041-3050`) stays an independent helper and inlines the one-line retry, so it does not
depend on the snapshot file: `if (writer.flush_pending and !writer.flush_in_flight) writer.driveFlush();`.

`drainPump` is the only snapshot code that still touches the raw ring, and it runs with no batch open:

```zig
fn drainPump(frame: *Frame) void {
    while (frame.snap.drainPending()) {
        if (frame.snap.drainQuiet()) {
            frame.snap.onDrained(frame.host());
            continue;
        }
        if (frame.ring.ring.popCQE()) |cqe| {
            stepCQE(frame, cqe);
            continue;
        }
        frame.ring.ring.park();
    }
}
```

### 3.3 Transition table additions

The transition table of iteration 2 §2.4 stands. Three rows are added or made explicit:

| Current state | Event | Next state | Action |
| --- | --- | --- | --- |
| `dump_sent` + `drain=swap` | duplicate dump/failure/terminal reply | unchanged | Warn and ignore; no state change, no free. |
| any + `drain != null` | any snapshot reply | unchanged | The Stage 1 guard; the drain is already committed to a continuation. |
| `dump_sent` | `SnapshotDone` | unchanged | Illegal before a terminal dispatch; warn, keep the procedure. |

`drain` is still not a fifth phase: `Job.phase` reads `dump_sent` while the pump runs, and the continuation is cleared
before the terminal dispatch.

## 6. Residual risks

| Risk | Mitigation |
| --- | --- |
| `snapshot -> lifetime -> index -> snapshot` is a lazy import cycle. | The tree already has `lifetime <-> index` (`lifetime.zig:27` and `:419`), so the pattern compiles; Stage 2 proves the added edge with `zig build check` before any logic moves. |
| The e2e retargets are broad (about forty field spellings). | Every retarget is a compile-time rename; a missed site fails the stage gate, not the behaviour. |
| The pump spins when the window is not quiet and no completion arrives. | It parks on the ring exactly as the old drain did; a flush in flight is the event that wakes it, and at most one flush per writer is in flight. |
| Stage 1's reply guard hides a real protocol bug. | It warns with the ring and leaves all state untouched; the terminal replies still arrive after the pump commits, and the regression test asserts the legal path. |
| Test fixtures duplicate across the two files. | Bounded to setup helpers; assertions never duplicate. A helper that grows past its call sites moves into the file owning the majority of its callers. |
