## 1. Resolutions in force

- **U1, accepted.** The boundary is control plane / data plane. `src/snapshot.zig` owns the procedure's policy: the FSM,
  the tick pass, the dispatch, the reply passes, the drain and swap, the failure ladder, recovery, and the cold
  handlers. `lifetime.Controller` keeps every resource it owns today: the snapshot slot pool, `walAdoptWrite`, the
  adoption marks, `copyTempIntoPair`, `runAdoptionRule`, `bringTail`, the registry, and `nextElephantRing`. No resource
  operation leaves the Controller, and the resource API is not dismantled. The only thing that may leave `lifetime.zig`
  is the `CompositeWriter` type (U7), which is not a Controller member and which the Controller never references. The
  one-way import rule is now a hard invariant: `snapshot.zig` may import `lifetime.zig`; `lifetime.zig` must never
  import `snapshot.zig`. The type-placement consequence of this rule is U7.
- **U2, confirmed.** `serve` (`serving`, `frozen`, `stopped`) moves out of `Frame` into `snapshot.State`. The tick's
  skip condition and the freeze/revival rule are §5 and §1.2, and the front-intake guard reads the same field. The
  file-read arm's terminal stop is a transition too, so it gets an entry point (`onReadFault`) rather than a field write
  from `index.zig`.
- **U3, accepted with direction.** No vtable, no callback, no indirect call is introduced for the seam. Production code
  uses concrete types; `anytype` is a test seam, used only where a test must substitute a fake, and even then it is
  monomorphized into a direct call. That removes two things from iteration 1: the `index.SnapshotHost` adapter and the
  `step` method on the host surface. The one place that needed `step` - the bounded drain - becomes a state of the FSM
  that the index's loop pumps. Section 2.3 is the consequence.
- **U4, confirmed.** Startup recovery (`StartupReplay`, `readWholeFile`, `recoverPair`) moves to `snapshot.zig` as one
  stage, with explicit `ctrl`, `ring`, `log`, `index_idx`, `host_idx`, `st` arguments, because it runs before the
  service-loop frame exists. `index.run` keeps the per-host loop and the fatal-error policy.
- **U5, confirmed.** Unit tests travel with the code they test; e2e and pump/wiring tests stay in `index.zig`; no
  assertion is rewritten while moving. Section 4.2 is the concrete list this produces.
- **U6, accepted.** `designs/SNAPSHOTS.md` is not amended and does not become the current document. It stays on disk as
  the implementation prelude that produced the code. The current design document is generated **after** the
  implementation, from the landed code, so this thread closes as a plan and promotion is deferred until the code exists.
  There is no documentation-editing stage in this refactor.

## 2. The seam, corrected

### 2.1 The host is a plain value, not an interface

`snapshot.zig` defines the resource bundle it is allowed to touch. It is a struct of pointers, a slice and two indices;
it carries no behaviour, no context pointer and no function pointer.

```zig
// src/snapshot.zig
const std = @import("std");
const posix = std.posix;
const lifetime = @import("lifetime.zig");
const logging = @import("logging.zig");
const messages = @import("messages.zig");
const state = @import("state.zig");
const wal = @import("wal.zig");
const cross_task = @import("cross_task.zig");

/// Everything a driver entry point may touch. Six fields of resources; no
/// callback, no vtable, no lifetime. The index builds it from `Frame`; tests
/// build it from their own fixture.
pub const Host = struct {
    ctrl: *lifetime.Controller,
    ring: *lifetime.RingStuff,
    log: *logging.Logger,
    ring_idx: u16,
    index_idx: u16,
    data_sets: []state.IndexState,
};
```

`index.zig` gets one private constructor and keeps no adapter type:

```zig
fn host(self: *Frame) snapshot.Host {
    return .{
        .ctrl = self.ctrl,
        .ring = self.ring,
        .log = &self.logger.logger,
        .ring_idx = self.ring_idx,
        .index_idx = self.index_idx,
        .data_sets = self.data_sets,
    };
}
```

`Host` is passed by value. It holds only pointers and slices, so a copy is cheaper than an address-of temporary and
cannot go stale. The index's call sites read `frame.snap.onTick(frame.host())`, `frame.snap.onReply(frame.host(), task)`
and so on.

### 2.2 The driver API

`lifetime.SnapshotJob` and `lifetime.SnapshotPhase` stay where they are under U7's proposed answer; `CompositeWriter`
moves into `snapshot.zig`. The sketch uses the proposed placement.

```zig
pub const Serve = enum { serving, frozen, stopped };

pub const PendingPush = struct { slot_idx: u32, target_ring_idx: u16 };

/// What the quiescent drain continues with. The procedure's `Phase` stays
/// `dump_sent` while this is set; the phase names the wire step, not the pump.
pub const Drain = enum { swap, revert };

pub const State = struct {
    serve: Serve = .serving,
    procedure: ?*lifetime.SnapshotJob = null,
    pending_push: ?PendingPush = null,
    window: ?CompositeWriter = null,
    ticks: u32 = 0,
    drain: ?Drain = null,

    pub fn armTicker(self: *State, host: Host) void;
    pub fn onTick(self: *State, host: Host) void;
    pub fn onReply(self: *State, host: Host, task: cross_task.CrossTask) void;
    pub fn onFlush(self: *State, host: Host, writer: *wal.WalWriteFile) void;
    pub fn onWriterFault(self: *State, host: Host, writer: *wal.WalWriteFile) void;
    pub fn onWriteError(self: *State, host: Host, err: wal.WalError) void;
    pub fn onReadFault(self: *State) void;
    pub fn retryPending(self: *State, host: Host) void;

    pub fn drainPending(self: *const State) bool;
    pub fn drainQuiet(self: *State) bool;
    pub fn onDrained(self: *State, host: Host) void;
};
```

`drainQuiet` retries a parked flush on each side, then asks the window; it is the old `drainUntilQuiet` minus the CQ
pop. `onDrained` consumes `drain`, clears it, and runs either the swap half or the revert half. The two halves are
private methods; the index never calls them directly.

The elephant is the second concrete object:

```zig
pub const Elephant = struct {
    ctrl: *lifetime.Controller,
    log: *logging.Logger,
    ring_idx: u16,

    /// True iff `task` is a snapshot variant, handled or deliberately warned
    /// about by this actor. False leaves the variant to the elephant loop's
    /// ordinary arms.
    pub fn handle(self: *Elephant, task: cross_task.CrossTask) bool;
};
```

Recovery is a free function, because it runs before `Frame` exists:

```zig
pub fn recoverPair(
    ctrl: *lifetime.Controller,
    ring: *lifetime.RingStuff,
    log: *logging.Logger,
    index_idx: u16,
    host_idx: u8,
    st: *state.IndexState,

```

The old `logger: *lifetime.LoggerStuff` parameter narrows to `*logging.Logger`; recovery only logs.

### 2.3 The drain is a state, not a re-entrant call

Iteration 1 made `drainUntilQuiet` call `host.step`, which is the `snapshot -> index -> snapshot` edge expressed as a
callback. U3 rejects the callback, and tracing the edge also found a defect (Section 3) that the callback shape causes.
The corrected shape splits the two halves:

1. `onReply(.SnapshotDumped)` checks the job and the window, sets `drain = .swap`, and returns. It does no I/O.
2. The index's loop, after it has committed its CQ batch, sees `drainPending()` and runs a pump: retry parked flushes;
   if quiet, call `onDrained` (copy, clear, revive, retire, dispatch `SnapshotClose`); otherwise pop one CQE with the
   ordinary raw `popCQE`, feed it through `stepCQE` (which routes a flush through `onFlush`), or park.
3. The failure reply does the same with `drain = .revert`; `onDrained` runs the revert half and dispatches
   `SnapshotCleanup`.

```zig
// index.zig: the only snapshot-related loop code left.
fn drainPump(frame: *Frame) void {
    while (frame.snap.drainPending()) {
        if (frame.snap.drainQuiet()) {
            frame.snap.onDrained(frame.host());
            continue;
        }
        if (frame.ring.ring.popCQE()) |cqe| {
            stepCQE(frame, cqe);
            continue;
        }
        frame.ring.ring.park();
    }
}
```

The call graph is acyclic: `stepCQE -> State.onReply/onFlush`; `drainPump -> stepCQE -> State...`;
`drainPump -> State.onDrained`. `snapshot.zig` never calls `index.zig`. The finite state machine is still expressed in
the API - a transition that needs the ring returns a continuation, and the ring's owner continues it - but no function
pointer and no module cycle exists. This is the reading of the request's "graph may walk snapshot -> index -> snapshot"
that costs nothing at runtime and stays testable.

### 2.4 The transition table, with the pump

| Current state                | Event                                     | Next state                   | Action                                                                                             |
| ---------------------------- | ----------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------- |
| idle                         | tick                                      | `create_sent`                | Check serve/procedure/pending, pick the pair over the barrier, acquire `k`, mint, dispatch create. |
| `create_sent`                | `SnapshotFd`                              | `dump_sent`                  | Mark, clone, adopt, install the composite, dispatch dump.                                          |
| `create_sent`                | `SnapshotCreateFailed`                    | `cleanup_sent`               | `unwindA` with no mark and no writer.                                                              |
| `dump_sent`                  | `SnapshotDumped`                          | `dump_sent` + `drain=swap`   | `beginSwap`: validate the window; no I/O.                                                          |
| `dump_sent` + `drain=swap`   | drain quiescent                           | `close_sent`                 | `finishSwap`: copy, rewire, clear mark, revive, retire old writer, dispatch close.                 |
| `dump_sent`                  | `SnapshotDumpFailed`, `SnapshotAbandon`   | `dump_sent` + `drain=revert` | `beginRevert`: validate the window; no I/O.                                                        |
| `dump_sent` + `drain=revert` | drain quiescent                           | `cleanup_sent`               | `finishRevert`: close and destroy the new writer, clear the mark, dispatch cleanup.                |
| `close_sent`                 | `SnapshotDone`                            | idle                         | Clear `procedure`; the elephant released `k`.                                                      |
| `cleanup_sent`               | `SnapshotDone`                            | idle                         | Clear `procedure`; the elephant released `k`.                                                      |
| any                          | illegal reply                             | unchanged                    | Warn, no transition, no free.                                                                      |
| `serving`                    | old-side fault or `WalFull`               | `frozen`                     | Deny the front; the window keeps serving new-first.                                                |
| `frozen`                     | successful swap, no live fault            | `serving`                    | Reopen the front.                                                                                  |
| any                          | new-side fault, or fault outside a window | `stopped`                    | Terminal for front work; the control plane completes the procedure.                                |
| any                          | read walk's terminal `IO` fault           | `stopped`                    | `onReadFault`; the control plane continues.                                                        |

The `Phase` enum keeps its four values. `drain` is the continuation, not a fifth phase: it says what the pump should do
when the window goes quiet, and it is cleared before the terminal dispatch. `Job.phase` therefore still reads
`dump_sent` while a drain is pending, which is also the truthful wire state.

### 2.5 Index wiring

`Frame` shrinks to the transport and front state:

`run` builds the frame before arming the ticker, because `armTicker` is now a `State` method:

```zig
var frame = Frame{ ... };
frame.snap.armTicker(frame.host());
```

The loop keeps its shape and gains one post-commit check:

```zig
while (true) {
    frame.snap.retryPending(frame.host());

    const batch = inbox.batch(cfg.batch_k, cfg.batch_k) orelse { ... };

    while (batch.ring.popCQE()) |cqe| stepCQE(&frame, cqe);
    batch.ring.commit() catch { ... };

    if (frame.snap.drainPending()) {
        drainPump(&frame);
        continue;
    }

    while (batch.front.next()) |task| switch (task) { ... };
}
```

The pump runs only when no batch view is open, and the `continue` abandons the front view for this pass. That ordering
is the fix for the defect in Section 3, not an incidental detail.

`stepCQE` keeps the CQ dispatch and loses the procedure bodies:

The front-intake guard reads `frame.snap.serve != .serving`. The front's write path, when it exists, calls

## 3. A defect found while tracing the seam

The current drain is not safe inside the loop's batch window. This is D1.

- `inbox.batch` opens a `BatchCQ` whose `popCQE` advances only the batch cursor; the ring's `cq_head` is not published
  until `commit` (`src/index_inbox.zig:324-345`, `zig-pkg/zigring-0.0.15-*/src/iouring.zig:2189-2220`).
- `stepCQE` is called inside that window (`src/index.zig:352`). A `SnapshotDumped` reply reaches `snapshotDumpedPass`
  (`src/index.zig:649`), which calls `drainUntilQuiet` (`src/index.zig:730`). The drain uses the **raw** ring
  (`src/index.zig:736`), and raw `popCQE` reads from `ring.cq_head` and advances it immediately
  (`iouring.zig:1504-1521`).
- If the window is not quiet when the reply is handled, the drain's first pop re-reads the very CQE the batch already
  consumed, because `cq_head` still points at it. The reply is dispatched a second time, re-entrantly, before the first
  pass has finished.
- If the drain pops past the batch cursor (a flush completion behind the reply), the later `batch.ring.commit()` stores
  the batch cursor and rewinds `cq_head` behind completions the drain already consumed and whose slots were already
  released. Those completions can then be delivered again.
- Why the suite misses it: the procedure tests call `stepCQE` on raw CQEs (`src/index.zig:3145` and the e2e drivers),
  never through `inbox.batch`; and the skeleton's front write path does not yet keep the window busy under load. The
  only production caller of the batch loop is `run`, and it is not exercised by the tests.

The pump in 2.3 removes the whole class: a reply only records a continuation, the batch commits with its cursor
untouched, and the pump runs with no batch open. The regression test is Stage 1's proof, not a theoretical check. The
recipe:

1. Build a live window and a procedure, as the completion test does.
2. Push a `SnapshotDumped` reply into the index ring, then write one event through the window, so the CQ holds
   `[reply, flush-completion]` in that order and the window is not quiet when the reply is handled.
3. Open `inbox.batch`, pop and step the reply, then `commit`.
4. Assert `cq_head` did not go backwards, `drain == .swap`, the reply was handled once, and no terminal message was
   dispatched yet.
5. Run `drainPump`; assert the flush was consumed once, `job.phase == .close_sent`, and exactly one `SnapshotClose` was
   sent.

With the current code, step 3 re-dispatches the reply and step 4 fails (or the nested pass completes the swap and the
outer pass dispatches cleanup). With the pump, all five hold.

The fix is behaviour-changing only on a path that is currently broken. U8 asks where it lands in the sequence.

## 5. Verification and invariants

The commands remain the repository's own:

```sh
zig build test
zig build check
```

`zig build test` walks every file under `src/` (`build.zig:198-240`), so `snapshot.zig` is compiled and its test blocks
run from the day it exists. Beyond the suite:

- `rg -n '@import\("snapshot.zig"\)' src/lifetime.zig` is empty. The one-way rule, checked in the direction that
  matters.
- `rg -n '@import\("index.zig"\)|@import\("elephant.zig"\)' src/snapshot.zig` is empty.
- `rg -n 'fn (tickPass|snapshotFdPass|snapshotDumpedPass|drainUntilQuiet|unwindA|unwindB|recoverPair|createSnapshot|dumpSnapshot|closeSnapshot|cleanupSnapshot|dispatchSnapshotReply|dispatchSnapshot|retryPendingPush)' src/index.zig src/elephant.zig`
  is empty after Stage 9.
- `rg -n 'wal_serve|frame\.procedure|frame\.window|frame\.pending_push|frame\.snapshot_ticks' src/index.zig` is empty:
  the state has one owner.
- `rg -n 'drainUntilQuiet' src/` is empty: the pump replaced it.
- `rg -n 'anytype' src/snapshot.zig` lists only test-driven seams, each one documented at its entry point; zero is the
  expected steady state.
- The `Frame` surface left in `index.zig` is `snap`, `host()`, the front/transport fields and `stepCQE`; no procedure
  field is duplicated.
- `git diff --stat` shows `index.zig` and `elephant.zig` shrinking, `snapshot.zig` growing, and `lifetime.zig` shrinking
  by the composite (and, under the alternative U7, by the job types). A stage that grows the two adapters is a sign the
  seam is wrong.
- The e2e procedure still writes the same files in the same order, the registry line is unchanged, and the existing
  assertions about the path, tag, final state and slot release are untouched.
- The D1 regression test asserts `cq_head` is monotonic across a reply-triggered drain and that the reply is handled
  once.

No allocator or ownership change is part of the plan. The job remains heap on the controller's allocator and is released
only by the terminal elephant; `CompositeWriter.pending` remains on the controller's allocator; the temp ring remains
the slot index. The refactor is a move of code plus the ownership seam, with D1 as the one deliberate behaviour fix.

## 6. Risks and mitigations

| Risk                                                                              | Mitigation                                                                                                                                                                                               |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The drain continuation changes when the swap happens (one committed batch later). | The pump runs immediately after the commit, before any front task, so the only difference is that the reply pass no longer re-enters the CQ. The ordering is deterministic; the regression test pins it. |
| D1's fix is mistaken for a move.                                                  | U8 keeps it a separate commit and a separate regression test. The move stages then change no behaviour.                                                                                                  |
| `lifetime.zig` ends up importing `snapshot.zig` through a type move.              | U7; the `rg '@import("snapshot.zig")' src/lifetime.zig` invariant fails the build review immediately.                                                                                                    |
| `anytype` creeps into production signatures.                                      | Concrete-first: production uses `Host` and `Elephant` values; an `anytype` is added only with the test that needs it, and the grep above lists them.                                                     |
| The pump starves the inbound queue while a flush is slow.                         | It parks on the ring exactly as the old drain did, and it only runs while a procedure is mid-swap. A flush in flight is the event it is waiting for, so no front work is runnable behind it.             |
| The type placement chosen in U7 makes Stage 8 a large diff.                       | Stage 8 is isolated; Stages 2-7 use `lifetime.SnapshotJob` directly, so the FSM is already moved and tested before the type moves.                                                                       |
| Test fixtures duplicate.                                                          | Accepted, bounded: setup helpers only; no assertion is copied. If a helper grows, it moves into the file that owns the majority of its callers.                                                          |
