## 1. Resolutions in force

- **U9, confirmed.** `src/config.zig` exposes three aliases and three constructors: `Bytes`/`bytes` for `.b`, `Kib`/`kib` for `.kib`, `Mib`/`mib` for `.mib`. `Bytes` keeps its name so the logging fields and their `config.bytes(...)` fixtures keep their spelling.
- **U10, confirmed.** `snapshots.size_barrier` has a 1 MiB validation floor and all eight index fixtures move to `mib(1)`. Tests that need a dispatch write more than 1 MiB of WAL extent; the skip-guard test needs no extra data because every guard returns before the barrier check. The raw-value escape (strategy b) is not used.
- **U11, confirmed.** The change is a clean WIP break with no compatibility remnants: no deprecated keys, no dual-source fallbacks. The sample `mpy6a.cfg` is updated to the new spellings.
- **U12, confirmed.** `logging.pool_capacity` remains the source of truth: it is the number of frames, a plain `u32` count. `logging.pool_frame_size` becomes a `Bytes` volume whose default drops from 2048 to 512 bytes, because most events are far below one frame. The pool is therefore 1024 frames of 512 bytes, 512 KiB by default, down from 2 MiB.

## 2. Supersession of U5

Iteration 1's pad accepted replacing `pool_capacity` with a `pool_bytes` budget and deriving the frame count. Iteration 2's pad answers U12 with "let's keep a number of frames and reduce a single frame to 512 bytes". Those two statements cannot both hold, so the later one wins:

- `logging.pool_capacity` stays a required `u32` count.
- `logging.pool_bytes` is not added.
- There is no `poolCapacity()` derivation; the consumer passes `pool_capacity` directly.
- `frameSize()` narrows the new volume leaf for `blog.BufferPool.init`.

The U5/C4/C5 rows of the iteration 2 matrix are replaced accordingly. This is restated as fact because the decision comes from the human, not from the planner.

## 4. Implementation notes fixed by this letter

- `Wal.lba()` keeps the existing narrowing pattern: `value64()`, then `std.math.cast(u32, ...)`, zero on overflow, so validation rejects it.
- `Logging.frameSize()` follows the same pattern. A zero frame size is left to `BufferPool.init`, which already answers `error.InvalidConfig`.
- The WAL floor rises from 512 to 1024. The validation tests can no longer write bare `256`, `3072` or `2097152`; a bare byte count that is not a whole KiB now fails in the parser. They use `0KiB`, `3KiB` and `2048KiB` instead, and a `lba = 512` document is asserted to be a parse error.
- The index fixtures that must cross the barrier get enough WAL extent to reach `mib(1)`. The two end-to-end procedure tests carry large record payloads so their state and session counts are unchanged.
- The `wal.zig` fixtures that construct a `config.Wal` with a 512-byte LBA move their `areaStride`, `Area.init`, `walkVerdict` and `openBattery` geometry to 1024 with the config. Pure area-math tests that never construct a `config.Wal` keep 512 and still cover the smallest internal geometry.
- `mpy6a.cfg` is updated: `pool_frame_size = 512`, `lba = 4KiB`, `size_barrier = 256MiB`.
